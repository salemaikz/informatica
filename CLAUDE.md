# Правила проекта Informatica

Платформа подготовки школьников Казахстана к ЕНТ (ҰБТ) по информатике. Цель — **максимально качественно и максимально дёшево**: короткие уроки как в Duolingo, геймификация, статистика, персонализация, ИИ-помощник. Языки: **русский и казахский**.

Этот файл — живые правила. Когда по ходу работы мы понимаем что-то важное — дописываем сюда.

## Документация — обязательно

После каждой задачи обновлять:

- `docs/CHANGELOG.md` — что сделано/изменено (дата, кратко, по пунктам). **Любое изменение промптов ИИ — отдельной строкой.**
- `docs/ROADMAP.md` — отметить сделанное, добавить появившиеся планы.
- `docs/DECISIONS.md` — если принято архитектурное/продуктовое решение (что выбрали, почему, какие альтернативы).
- `docs/ARCHITECTURE.md` — если поменялось «как работает».
- Этот файл — если появилось новое правило.

Документация пишется по-русски. Идентификаторы в коде — по-английски, комментарии — коротко по-русски.

## Распределение задач между моделями — экономим токены

Главная (самая мощная) модель — «прораб»: планирует, режет работу на куски и раздаёт их моделям по сложности. Сама делает только то, где нужна сильная модель.

**При разработке (Claude Code — субагенты `Agent` / `Workflow` с параметром `model` и `effort`):**

| Сложность | Модель | Примеры задач |
|---|---|---|
| Механика, «найди и перескажи» | `haiku`, effort low | поиск по коду, сбор строк/файлов, прогон тестов и скриптов с кратким итогом, скриншоты, массовые однотипные правки |
| Работа по чёткой спецификации | `sonnet`, effort medium | компонент/мини-игра по готовому ТЗ, тесты, переводы, документация, ревью одного файла |
| Думать и решать | главная модель (`opus`), effort high | архитектура, ТЗ для других, сложные баги, промпты ИИ, интеграция, финальная проверка |

- Сначала ТЗ, потом исполнитель: дешёвой модели даём конкретную спецификацию (файлы, интерфейсы, критерии готовности), а не «сделай красиво».
- Результаты субагентов — короткие выжимки; большие файлы и логи главная модель целиком не читает.
- Проверку (тесты, скриншоты) делает дешёвая модель; решение «принять/исправить» — главная.
- Независимые куски — параллельно (у каждого исполнителя свои файлы, общие файлы правит только главная модель).

**В приложении (OpenAI):** та же лестница — самая дешёвая модель, которая справляется.

| Уровень | Модель | Где |
|---|---|---|
| Без ИИ | код | проверка ответов, генерация заданий, мини-игры, статистика |
| Дешёвый | `gpt-5.4-nano` | отзыв после урока, память наставника, короткие структурированные ответы |
| Средний | `gpt-5.4-mini` | чат-наставник, подсказки, разбор ошибок, проверка фото |
| Сильный | `gpt-5.5` | **только офлайн-задачи разработчика** (вычитка казахского, генерация черновиков контента), никогда — на каждый запрос ученика |

## Язык и контент

- Любая строка для ученика — **на двух языках**. Интерфейс: `src/i18n/dict.ts` (каждый ключ — `{ ru, kk }`, TypeScript не даст пропустить). Контент уроков: тип `L = { ru, kk }`.
- Никаких захардкоженных русских строк в компонентах — только `t("ключ")` или `l(контент)` из `useT()`.
- Исключение — мини-игры: их тексты живут рядом с игрой в `src/games/<id>/strings.ts` (тот же формат `{ ru, kk }`), чтобы игры разрабатывались независимо.
- Казахские тексты — литературный язык, термины как в казахстанских учебниках: санау жүйесі, екілік/ондық жүйе (не «бинарлы»), негіз, разряд, қалдық, бөлінді. ЕНТ по-казахски — **ҰБТ**.
- Носителя-редактора пока нет → каждый новый казахский текст прогоняем через `npm run review:kk` (сильная модель в роли редактора) и применяем обоснованные правки. В CHANGELOG помечаем «вычитано моделью, носителем — нет».
- Программирование в курсе — **Python** (как в ЕНТ у наших учеников).
- Формулы — Unicode, не LaTeX: `1011₂`, `2³`, `25₁₀`.
- Озвучку TTS всегда проверять обратной расшифровкой — модель иногда пропускает фразы.
- Пол ученика неизвестен — в текстах и промптах избегаем глаголов с родом («у тебя получилось», а не «ты сделал/сделала»).
- Контент проверяется тестами (`tests/content.test.ts`): двуязычность, корректность ответов, уникальность id. Новый урок → `npm test` должен быть зелёным.

## Дизайн

- Минимализм, удобство, крупные кнопки, мобильная вёрстка в первую очередь (ширина 360–430px), затем десктоп.
- **Семантика цветов (не нарушать):**
  - зелёный `success` — верно / освоено;
  - красный `danger` — неверно / слабая тема;
  - янтарный `warning` — частично / в процессе;
  - золотой `gold` — XP, награды, достижения;
  - оранжевый `streak` — серия дней, комбо;
  - голубой `primary` — основные действия и навигация;
  - фиолетовый `ai` — **всё, что делает ИИ** (подсказки, чат, отзывы).
- Цвета — только через токены (`bg-success-soft`, `text-danger` …) из `src/app/globals.css`. Есть светлая и тёмная тема — новые цвета добавлять в обе.
- Склейка классов — через `cn()` (`src/lib/cn.ts`, tailwind-merge), чтобы переопределения `className` работали.
- Иллюстрации — React/SVG-компоненты (маскот «Бит», `components/visuals`), а не тяжёлые картинки.
- **Никаких эмодзи в интерфейсе** — только рисованные иконки `lucide-react` (как в боковом меню). Эмодзи выглядят по-разному на разных телефонах и «дешевят» дизайн. Иконку для данных из `src/lib` храним строкой-именем, компонент выбираем в `components` (пример — `AchievementBadge`).
- Ссылка-кнопка — `ButtonLink`, не `<Link><Button/></Link>` (нельзя вкладывать `<button>` в `<a>`).

## ИИ (OpenAI) — экономия и безопасность

- Ключ `OPENAI_API_KEY` — **только на сервере** (`.env.local`, переменные окружения хостинга). Никогда не коммитить, не передавать в клиент, не писать в документацию.
- Сначала бесплатное, потом ИИ: статическое объяснение есть у каждого задания; ИИ — по кнопке («Подсказка», «Объясни», проверка фото).
- Модели задаются env-переменными (`OPENAI_MODEL_TUTOR`, `OPENAI_MODEL_VISION`, `OPENAI_MODEL_FAST`), по умолчанию самые дешёвые подходящие (`gpt-5.4-mini` / `gpt-5.4-nano`). Чат — `reasoning_effort: "none"`.
- Каждый маршрут ИИ: лимит по IP (`server/rate-limit.ts`), обрезка входных данных (`server/context.ts`), лог расхода токенов `[ai] route=… in=… out=…`.
- Данные с клиента — недоверенные. Ответ ИИ рендерим через `Markdown` (react-markdown, без сырого HTML).
- Режим «подсказка» никогда не выдаёт ответ.
- Промпты — `src/server/prompts.ts`. Меняешь промпт → проверь на ru и kk живыми запросами и запиши в CHANGELOG.

## Код

- Next.js 16 (App Router, Turbopack), React 19, TypeScript strict, Tailwind v4, Zustand, Remotion Player. Перед работой с API Next читать доки в `node_modules/next/dist/docs/` (см. AGENTS.md) — версия новее обучающих данных.
- Прогресс ученика — в `useApp` (`src/lib/store.ts`, localStorage). Действия стора — единственный способ менять прогресс (потом заменим хранилище на бэкенд, не меняя интерфейс).
- Чистая логика (проверка ответов, генераторы, геймификация, освоение) — в `src/lib/*` без React, покрыта тестами в `tests/`.
- Запросы к ИИ из компонентов — только через `src/lib/ai.ts` / хук `useTutor`.
- `setState` синхронно в эффектах — нельзя (правило линтера React 19). Запросы, запускаемые действием пользователя, — из обработчиков.
- Мини-игра — по контракту `src/games/types.ts`; логика игры — в чистом `logic.ts` с тестами; правильные ответы всегда вычисляет код.

- Chromium для скриншотов/e2e: `/opt/pw-browsers/chromium-1194/chrome-linux/chrome` (в облачной среде).
