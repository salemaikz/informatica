# Правила для исполнителя

Единый свод правил для всех, кто делает функции или контент для Informatica: наших ИИ-субагентов, внешнего разработчика, внешней ИИ. Цель — чтобы результат выглядел и работал как остальное приложение, а не «что-то совсем другое».

Здесь только правила. Подробности — в файлах из раздела 6.

---

## 0. Как пользоваться

**Перед работой прочитай:**

1. Весь этот файл.
2. По типу задачи:
   - интерфейс → раздел 2 + открой `src/components/ui/*` и соседние экраны;
   - код и логика → раздел 3 + `docs/ARCHITECTURE.md`;
   - урок, банк, задания ЕНТ → раздел 4 + `docs/specs/course-v2.md`, `docs/specs/content.md`, `docs/ENT.md`;
   - ИИ и экономика → разделы 1, 3.6 + `docs/specs/economy.md`.
3. Два-три существующих примера того же рода (урок той же темы, похожий экран, похожая игра). Делай «как у соседа», а не по-своему.
4. Код с API Next.js — сначала `node_modules/next/dist/docs/`: версия новее, чем ты знаешь.

**Что приложить к результату** (отчёт до 15 строк):

- список созданных и изменённых файлов;
- что и чем проверено (команды, скриншоты, python3 для ответов);
- оставшиеся предупреждения и причина;
- что пришлось бы поменять в общих файлах (типы, словарь, реестры) — **не меняй сам**, опиши;
- новые казахские тексты — отметка, прогнаны ли через `npm run review:kk`.

**Не трогай без поручения:** общие типы (`src/lib/types.ts`), реестры `generated.ts`, `course.ts`, `skills.ts`, `lib/bank/index.ts`, `tests/*`, чужие уроки, `CLAUDE.md`, блок в `AGENTS.md`. Общие файлы правит только главная модель.

## 1. Продукт: всегда / никогда

Цель: **максимально качественно и максимально дёшево**. Короткие уроки как в Duolingo, геймификация, статистика, персонализация, ИИ-помощник. Языки — русский и казахский, на равных.

**Всегда**

- Двуязычие: каждая строка для ученика — `{ ru, kk }`.
- Сначала мобильная вёрстка (360–430 px), потом десктоп.
- Всё, что может сделать код, делает код: генерация заданий, проверка ответов, игры, калькулятор, запуск кода. Правильный ответ вычисляет код.
- У каждого задания есть бесплатные статические `hint` и `explanation`, у вариантов — `whyWrong`. ИИ — только по кнопке с ценой.
- Порядок урока (`docs/CONTENT_GUIDE.md`): ситуация из жизни → объяснение с картинкой → разбор 2–3 примеров по шагам → решаем вместе → сам → задание ЕНТ → конспект.
- От простого к сложному: уровни A/B/C, доли 50/30/20, как в ЕНТ.
- Один урок — один навык, 8–10 минут (длиннее — бросают).
- Ученик сам выбирает путь: учить, тестироваться, играть, читать; темы в любом порядке.
- Живо без спешки: анимации, звук, реакции маскота. В обучении и играх таймер — только если ученик сам выбрал темп (пробный ЕНТ — с таймером, как экзамен).
- Прогресс меняется только действиями стора.

**Никогда**

- Эмодзи в интерфейсе.
- Захардкоженные русские строки в компонентах.
- Цвета мимо токенов; цвет не по смыслу.
- Глаголы с родом в обращении к ученику («ты сделал/сделала»).
- ИИ сам по себе, без нажатия (исключения: бесплатный короткий отзыв после урока; `AiPanel.autoAsk` — вопрос уходит сам только после нажатия кнопки с ценой «Спросить Бита» на плашке «Нужна помощь?», решение #115); ИИ, который выдаёт ответ в режиме подсказки.
- ИИ, маскот, XP, подсказки и звуки в пробном ЕНТ и тесте раздела (оболочка `ExamRun`): там только калькулятор и черновик, как на экзамене.
- Генерация уроков и заданий ИИ «на лету».
- Блокировка уроков по порядку.
- Имитация оплаты и сбор контактов. Любая покупка за ₸ → `ComingSoonSheet` («Оплата скоро»).
- Продажа заморозок серии, продажа сердечек сверх недостающих, трата XP как валюты.
- Списание входа не при начале занятия и в обход общего ключа входа (`payEntryOnce` / `useEntryAccess`, решение #120): одно занятие — одно сердечко, двойной вызов не списывает дважды. Прямой `payEntry` из эффекта — нельзя.
- Голая ошибка «не хватает»: нехватка сердечек или чипов — только окно «Не хватает» (`ShortfallSheet` через `OutOfHearts` / `NoChipsNotice`, решение #121).
- Звук и музыка в пробном ЕНТ и тестах (`ExamRun`): там тишина, как на экзамене.
- Запуск кода ученика на сервере (только в браузере).
- Ключ ИИ в клиенте, в коде, в документации, в коммите.
- Названия подрядчиков и технологий (сервис ИИ, хостинг, хранилище, CDN, модели, имена cookie) в текстах для ученика и в документах — пишем обобщённо: «сервис ИИ», «облачный хостинг» (решение #62). Бот тоже их не называет.
- Резервная копия, выгрузка и загрузка данных ученика файлом (решение #60): прогресс будет храниться в нашей базе (этап 17).

## 2. Дизайн

### 2.1 Цвета — только токены, только по смыслу

Токены — в `src/app/globals.css`. В классах: `bg-success-soft`, `text-danger`, `border-ai/40` и т. п.

| Токен | Смысл | Где |
|---|---|---|
| `primary` (`-strong`, `-soft`) | основные действия, навигация | кнопка «Дальше», активный пункт меню |
| `success` | верно, освоено | правильный ответ, освоенная тема |
| `danger` | неверно, слабая тема | ошибка, слабый навык |
| `warning` | частично, в процессе | неполный ответ, тема в работе |
| `gold` | XP, награды, достижения, **чипы (валюта)**, тарифы | `+10 XP`, иконка `Cpu` у чипов |
| `streak` | серия дней, комбо | огонёк серии |
| `ai` | **всё, что делает ИИ** | подсказка Бита, чат, отзыв, разбор |
| `heart` | **только сердечки** (жизни в уроке) | иконка `Heart` |
| `rarity-common/rare/epic/legendary` (`-soft`) | **только редкость**: украшения профиля, достижения, ступени уровня (решения #107, #108) | классы — `components/ui/rarity.ts`, для SVG — `RARITY_VAR` |

Нейтральные: `bg` (фон страницы), `surface` (карточки), `surface-2` (дорожки, вложенные блоки), `border`, `text`, `muted` (вторичный текст), `on-primary`.

Для иллюстраций есть производные токены: `--device-*`, `--paper`, `--paper-line`, `--skin`, `--skin-shade`, `--art-gloss`, `--art-shadow`. Это только CSS-переменные (в `@theme` их нет) — в SVG пишем `fill="var(--device-shell-1)"`, классов `bg-device-*` не существует.

Оттенки: у `primary`, `success`, `danger`, `warning`, `ai`, `heart` есть `-strong` и `-soft`; у `gold`, `streak` и `rarity-*` — только `-soft`.
Текст и тонкие линии цвета смысла **поверх его `-soft`-заливки** — токены `ink-*` (`ink-primary|success|danger|warning|ai|heart|gold|streak`; `text-ink-primary`, `var(--ink-success)` …): в светлой теме — тёмные оттенки с контрастом ≥ 4,5:1 к своей `-soft`, в тёмной — базовый цвет (тёмный `-strong` на тёмном `-soft` нечитаем, ≈ 3,4:1). `Pill` уже на них. Связку `bg-*-soft` + `text-*-strong` в новом коде не использовать.

Приёмы:

- мягкий фон + насыщенный текст: `bg-success-soft text-success-strong`;
- активный элемент: `border-primary/40 bg-primary-soft text-primary` (для ИИ — то же с `ai`);
- золото как фон с текстом: `bg-gold-soft text-warning-strong` (читаемость).

**Новый цвет** = добавить в три блока `globals.css`: `:root`, `:root[data-theme="dark"]` и `@media (prefers-color-scheme: dark)`. Два тёмных блока держать одинаковыми. Затем — в `@theme inline`.

**Текст на насыщенной цветной заливке** (кнопки, плитки, бейджи с белым текстом) — только `bg-action-primary|success|danger|ai` + `text-white`, рамка того же цвета — `border-action-*`, объёмная тень — `var(--action-*-edge)`: у них контраст белого ≥ 4,5:1 в обеих темах. `bg-primary/success/danger/ai` под `text-white` ниже 4,5:1 — нельзя. Заливки-сигналы без текста остаются на базовых токенах (решение #125).

Hex в компонентах запрещён. Исключения: маскот и аватары (фиксированные цвета, одинаковы в обеих темах), конфетти (`canvas-confetti` не понимает CSS-переменные), белый фон экспорта рисунка. `text-white` на цветных кнопках и белая ручка `Switch` (`bg-white`) — допустимы. В сценах оттенок «темнее/светлее» — через `color-mix` от токена, а не новым hex.

### 2.2 Типографика

- Шрифты: **Nunito** (основной, есть казахские буквы) и **JetBrains Mono** (код, числа). Подключены в `layout.tsx`, свои не добавлять.
- Начертания тяжёлые: кнопки, пилюли, меню, заголовки — `font-extrabold`; дальше `font-bold`, `font-semibold`.
- Частые сочетания:

| Роль | Классы |
|---|---|
| Заголовок страницы | `text-2xl font-extrabold` |
| Заголовок блока | `text-lg font-extrabold` (компонент `SectionTitle`) |
| Подзаголовок карточки | `text-xl font-extrabold` / `text-sm font-extrabold` |
| Основной текст | `text-sm font-semibold` / `font-bold` |
| Подписи, пилюли | `text-xs font-extrabold` |
| Подпись в нижнем меню | `text-[11px] font-extrabold` |

- Markdown (теория, конспект, ответы ИИ) — только через компонент `Markdown` с классом `.prose-app`; свои стили для текста не изобретать.
- В коде лигатуры выключены — не включать.

### 2.3 Скругления, рамки, тени, отступы

| Элемент | Скругление |
|---|---|
| Карточки, модалки | `rounded-3xl` |
| Кнопки md/lg, пункты меню | `rounded-2xl` |
| Кнопки sm, подпункты | `rounded-xl` |
| Пилюли, чипы, прогресс, вкладки | `rounded-full` |

- Рамки — **2px**: `border-2 border-border` (карточки, шапка `border-b-2`, нижнее меню `border-t-2`, сайдбар `border-r-2`).
- Тени: у кнопок — «3D-край» снизу (см. Button); у модалок — `shadow-2xl` и фон `bg-black/40`. Других теней не добавлять.
- Отступы: карточка `p-4 sm:p-5` (уже в `Card`). Поля страницы `px-4 sm:px-6` и низ `pb-28` (место под нижнее меню) даёт `AppShell` — внутри `(main)` не дублировать; полноэкранные режимы ставят свои.
- Склейка классов — только `cn()` из `src/lib/cn.ts`.

### 2.4 Кнопки и карточки — канонические примеры

Используй готовые примитивы из `src/components/ui/`. Не делай свои кнопки и карточки.

```tsx
import { Button, ButtonLink } from "@/components/ui/Button";
import { Card, SectionTitle } from "@/components/ui/Card";
import { Pill } from "@/components/ui/Pill";

<Button variant="ai" size="lg" block icon={<Sparkles size={20} />} onClick={onAsk}>
  {t("ai.askBit")} <AiCost kind="ask" variant="solid" />
</Button>

<ButtonLink href="/learn" variant="secondary">{t("common.back")}</ButtonLink>

<Card className="flex items-center gap-3">…</Card>

<Pill tone="gold" icon={<Star size={12} />}>+10 XP</Pill>
```

- **Button**: варианты `primary | success | danger | ai | secondary | ghost`; размеры `sm` (h-9), `md` (h-11, по умолчанию), `lg` (h-13); `block` = во всю ширину. Вариант выбирай по смыслу цвета (ИИ-действие → `ai`).
- Нужен вид кнопки на своём элементе → `buttonClass({ variant, size, block, disabled })`.
- Цена ИИ на кнопке — `AiCost` (`components/economy`): `kind` = `hint | explain | ask | chat | photo | review | voice`; на насыщенной кнопке (`ai`) — `variant="solid"`, на светлом фоне — по умолчанию `soft`; узкая кнопка — `short`.
- **Ссылка-кнопка — только `ButtonLink`.** Никогда `<Link><Button/></Link>`.
- **Card**: `interactive` — для нажимаемых, `appear` — появление с анимацией.
- **Pill**: тона `primary | success | danger | warning | gold | streak | ai | muted` (тона `heart` нет; у Button нет `gold`/`warning`/`heart` — не добавлять самому).
- **Modal**: на телефоне — шторка снизу, от 640px — окно по центру. Все диалоги — через него.
- **ProgressBar / Ring** (`ui/ProgressBar.tsx`): прогресс и дневная цель.
- Переключатели и сегменты — `Switch`, `Segmented`, `Row` из `src/components/goals/controls.tsx`.
- Поля ввода — по образцу `chat/Composer.tsx`, `notes/NotesHome.tsx`.

### 2.5 Иконки

- Только `lucide-react`. Эмодзи — никогда, ни в UI, ни в контенте.
- Размеры: меню 22, подпункты 18, кнопки 18–20, пилюли 12–14.
- В данных из `src/lib` иконка хранится **строкой-именем**; компонент выбирается в `components` (образец — `AchievementBadge`). В `nav.ts` и сценах — ссылка на компонент (`icon: Cpu`).
- Декоративная иконка — `aria-hidden`.
- Фиксированные: чипы — `Cpu` (gold), сердечки — `Heart` залитое (heart).

### 2.6 Иллюстрации

- Только SVG внутри React-компонента: маскот «Бит» (`components/mascot/Mascot.tsx`), `components/visuals`, сцены (`components/scenes`). Без растровых картинок, внешних изображений и шрифтов. `<img>` — только для контента пользователя (аватар, фото).
- Маскот: настроения `happy | neutral | thinking | sad | celebrate`; рядом с текстом — `MascotSays`.
- Сцена: адаптивный `viewBox` (читаемо на 360px, на десктопе не шире ~560px); цвета только из токенов; подписи через `useT()/l()`; `role="img"` + `aria-label`.
- Стиль: плоская «учебниковая» иллюстрация, узнаваемые формы, 2–3 оттенка на объект, мягкие тени. Без градиентов (в сценах их нет).
- Чистая логика раскладки — в соседнем `.ts` с тестом. Подробно — `docs/specs/basics.md` §3.

### 2.7 Анимации

- Библиотека `motion/react` через `LazyMotion`: в компонентах `m.div`, а не `motion.div`.
- Только пресеты из `src/components/motion/presets.ts`:
  - `springSnappy` — нажатия, переключения;
  - `springSoft` — появление панелей и карточек;
  - `springBouncy` — награды, «поп»;
  - `easeOut` — переходы шагов и страниц.
- Отклик ≤ 400 мс. Не делать долгих анимаций.
- Готовое (`src/components/motion/`): `Reveal`, `Shake` (ошибка), `XpBurst`, `CountUp`, `ComboFlame`, `XpChipAnimated` / `StreakChipAnimated`; CSS-классы `animate-pop`, `animate-shake`, `animate-slide-up`, `animate-fade-in`, `animate-rise-in`, `animate-ring-out`, `animate-pulse-ring`.
- Уважать «Меньше анимаций»: в JS — `useReduceMotion()` (motion-анимации гасит `MotionProvider`); CSS-анимации уже гасятся глобально.

### 2.8 Тёмная тема

- Всё должно работать в обеих темах. Новый токен — в обе (см. 2.1).
- Проверка глазами: телефонная ширина + тёмная тема, обязательно для каждого нового экрана.

### 2.9 Вёрстка

- Каркас — `AppShell`: на телефоне шапка + нижнее меню из 4 пунктов, от 1024px — сайдбар. Свою навигацию не делать.
- Навигация — единый источник `src/components/app/nav.ts` (4 группы: Учиться, Практика, Материалы, Прогресс; решение #110). ИИ-чат — плавающая кнопка Бита (`components/guide/BitDock.tsx`), не пункт меню. Новый раздел добавляется в `nav.ts`, а не отдельным меню.
- Подсказки «что здесь» — только через проводника Бита (`lib/guide.ts`: сцена из 1–4 реплик, метки `data-tour` на элементах; решение #109). Карточки-подсказки вверху страницы не делать. Новая страница с проводником → сцена в `GUIDE_SCENES`, id в `TIP_IDS`, метки `data-tour`.
- Шапка телефона: только логотип, серия, сердечки, чипы, XP (от 520px), инструменты. Поиск и аватар туда не ставить.
- Подразделы на телефоне — `SectionTabs`.
- Ширина контента задаёт `AppShell`: `max-w-2xl`, на `/tutor` и `/code` — `max-w-5xl` (список путей — `wide` в `AppShell.tsx`).
- Безопасные зоны — `env(safe-area-inset-*)` у прижатых к краю элементов.
- Полноэкранные режимы (урок, тренировка, пробник, игра) — вне группы `(main)`.

### 2.10 Доступность

- Касание ≥ 44px (кнопки md/lg, пункты меню 48–64px). Мелкий контрол — расширить зону через `after:absolute after:-inset-1.5`.
- Фокус: `focus-visible:outline-3 focus-visible:outline-offset-2 focus-visible:outline-primary` (уже в примитивах).
- Роли и атрибуты: `role="dialog" aria-modal`, `role="progressbar"`, `role="switch" aria-checked`, `aria-current="page"` в меню, `aria-label` у навигации, иконок-кнопок и SVG.
- Цвет не единственный носитель смысла: рядом иконка или текст.

## 3. Разработка

### 3.1 Стек

Next.js 16 (App Router, Turbopack), React 19, TypeScript strict, Tailwind v4, Zustand 5, motion, lucide-react, react-markdown + remark-gfm, Remotion Player, CodeMirror 6, sql.js, idb-keyval. Тесты — vitest (+ happy-dom), e2e — Playwright.

Новые зависимости — только с обоснованием в отчёте. Next 16 отличается от того, что ты знаешь: читай `node_modules/next/dist/docs/`, учитывай пометки об устаревании.

### 3.2 Где что лежит

| Что | Где |
|---|---|
| Страницы | `src/app/(main)/<раздел>/page.tsx` — тонкая обёртка |

| API ИИ | `src/app/api/ai/<маршрут>/route.ts` |
| Компоненты | `src/components/<область>/` (ui, lesson, ai, economy, chat, exam, scenes, mascot, ide, games…) |
| Чистая логика без React | `src/lib/*` (+ тест в `tests/`) |

| Серверный код | `src/server/*` (первая строка `import "server-only"`) |
| Промпты ИИ | `src/server/prompts.ts` — только там |
| Словарь интерфейса | `src/i18n/dict.ts` + `src/i18n/parts/<область>.ts` |
| Уроки | `src/content/lessons/<id>.ts` |
| Задания ЕНТ | `src/content/ent/<id>.ts` |

| Практикум кода | `src/lib/ide/*`, `components/ide/*`, воркеры `public/ide/*.js` |

`generated.ts` (уроки, банк, ЕНТ) руками не правят — их пишет `scripts/register-content.mjs`, и запускает его только главная модель (регистрация урока — её работа).

### 3.3 Правила React 19 / Next 16

- `params` — промис:

```tsx
export default async function Page(props: { params: Promise<{ id: string }> }) {
  const { id } = await props.params;
  return <HistoryDetail id={id} />;
}
```

- Новая страница — серверная обёртка (как `history/[id]`), логика — в клиентском компоненте (`"use client"`).
- Синхронный `setState` в эффекте — нельзя (линтер). Запросы по действию пользователя — из обработчиков.
- `Date.now()` в рендере — нельзя. Используй `useNow()` / `useNowSeconds()` из `components/economy/useEconomy.ts`. В обработчиках и действиях стора — можно.
- Тяжёлое (редактор кода, IDE, видео, игры) — через `next/dynamic`.

### 3.4 Состояние

- Один стор `useApp` (Zustand + persist, localStorage). Прогресс меняется **только действиями стора** (`recordAnswer`, `finishSession`, `spendAi`, `loseHeart`, `buy`…). Интерфейс стора сохранится при переходе на бэкенд.
- Вычисления — чистые функции в `lib/*`; стор их только вызывает.
- Новое поле стора: значение по умолчанию + санитайзер в `mergeState`. Всё из хранилища — недоверенное.
- Чипы начисляет только `settleChips(...)` в конце действий-наград.
- Большие данные — в IndexedDB, не в сторе: картинки заметок, попытки пробника, сообщения чатов.
- Логика экономики — в `src/lib/economy.ts`; в UI — через хуки `useHearts`, `useChips`, `usePlan`, `useAiQuote`.

### 3.5 Строки и языки (i18n)

- Каждая строка для ученика — `{ ru, kk }` (тип `L` из `@/lib/types`).
- Новая область словаря — файл `src/i18n/parts/<область>.ts`, затем развернуть в `dict.ts` (общий файл: без поручения — опиши в отчёте):

```ts
export const heartsDict = {
  "hearts.lost": { ru: "−1 сердечко", kk: "−1 жүрек" },
} satisfies Record<string, L>;
```

- Ключи — с точками по областям. Параметры — `{n}`.
- В компоненте: `const { t, l, lang } = useT();` → `t("ключ", { n })` для интерфейса, `l(текст)` для контента. Вне React — `translate(lang, key, params)`.
- Мини-игры держат строки в `src/games/<id>/strings.ts` в том же формате.
- Тест требует непустые ru и kk у каждого ключа; TypeScript не даст сослаться на несуществующий.

### 3.6 ИИ и экономика

**Клиент**

- К ИИ — только через `src/lib/ai.ts` (`streamTutor`, `checkSolution`, `lessonFeedback`), `src/lib/voice.ts` (расшифровка) или хук `useTutor` (`components/ai/useTutor.ts` — сам делает `spendAi`/`refundAi` и кэш). Прямой `fetch` из компонентов — нельзя.
- Ответ ИИ — только через компонент `Markdown` (без сырого HTML).
- Сначала бесплатное: статическая подсказка/объяснение (`lib/ai-static.ts`), ИИ — по кнопке. Нет статической подсказки → «готовой подсказки нет» + платная кнопка «Спросить Бита». Шторка ИИ сама модель не вызывает; единственное исключение — `AiPanel.autoAsk`, и только после нажатия кнопки с ценой на плашке «Нужна помощь?».
- Цена — на кнопке: `<AiCost kind="…" />`.
- Порядок оплаты:

```ts
const receipt = app.spendAi("hint");
if (!receipt.ok) {
  // reason "chips" → <NoChipsNotice kind="hint" />, "cap" → дневной лимит
  return;
}
try {
  // вызов через lib/ai.ts; onMeta получает заголовки ответа до текста
  await streamTutor(req, onText, signal, (meta) => {
    // Каждый полученный ответ — одно обращение (#118), в том числе из кэша и безопасный «ответ не назову».
    // Возврат только за кризисный ответ (бесплатный), если клиент его не распознал.
    if (meta.crisis) useApp.getState().refundAi(receipt);
  });
} catch {
  // Ответа не было: ошибка HTTP, обрыв без маркера OK, пустой ответ, закрыли до первого текста.
  useApp.getState().refundAi(receipt);
}
```

Образцы: `components/ai/useTutor.ts`, `components/lesson/Results.tsx`, `chat/voice/VoiceButton.tsx`.

- Виды: `hint`, `explain`, `ask`, `chat`, `photo`, `feedback` (бесплатно), `voice` (расшифровка: только дневной потолок, ни бесплатных, ни чипов — платится ответ в чате).
- Нет чипов → `NoChipsNotice` (в шторке и чате, без ухода со страницы), не голая ошибка.
- Шторка ИИ, ответ которой может прийти после закрытия, пишет вопрос в свою ветку (`components/ai/ai-threads.ts`) до запроса и не затирает более новые данные (`rev`).
- Две вкладки одного ученика синхронизируются (`lib/storage-sync.ts`).

- ИИ-элементы — цвет `ai`.

**Сервер** (образец — `src/app/api/ai/lesson-feedback/route.ts`), по порядку:

1. ``const g = await guardAi(req, { route: "<маршрут>", units: AI_UNITS["<вид>"] })`` (`src/server/ai-guard.ts`) → `if (!g.ok) return g.response;` — внутри: строгий `sameOrigin` (403), всплеск по устройству и IP (429 `rate_limited`), суточные лимиты устройства, IP и сайта (429 `daily_limit`, 503 `ai_busy`). Свой `rateLimit` по IP вместо стража — нельзя. Новый маршрут — новая строка в `BURST_LIMITS`;
2. `getOpenAI()` вернул null → `g.release()` + 503;
3. разбор JSON → 400 (+ `release()`); тело большое — сначала дешёвый `preCheckAi` до разбора;
4. обрезка всех входных полей (`sanitizeContext`, `sanitizeTask`, `sanitizeImage`, `str(v, max)`, `.slice`);
5. строгая JSON-схема ответа, если ответ структурный; потолок `MAX_TOKENS` и таймаут `callTimeoutMs(maxDuration)` из `src/server/openai.ts`;
6. `logUsage(...)` → лог расхода токенов;
7. ошибка → `console.error` + 502; `g.release()` — **только** если `openAiRejected(e, req.signal)` (модель запрос не получила); обрыв клиентом и таймаут обращение не возвращают;
8. ответ — через `withGuardHeaders(response, g)` (cookie нового устройства); потоковый текст — с маркером конца из `lib/ai-stream.ts` (`\u0000OK` / `CUT` / `ERR`);
9. `export const maxDuration`.

- Модели — только через env-переменные и `MODELS` из `src/server/openai.ts`. Названия моделей в код не вписывать. Берётся самая дешёвая, которая справляется; сильная модель — только офлайн, никогда на запрос ученика.
- Подсказка никогда не выдаёт ответ: модель получает ответ «только для себя», код проверяет утечку.
- Неперсональные ответы кэшируются (сервер + устройство): кэш экономит деньги, а не обращения ученика — ответ из кэша тоже одно обращение (#118). Сервер при попадании в кэш свой потолок освобождает — расхождение намеренное.
- Промпты — только `src/server/prompts.ts`. Изменил промпт → проверь живыми запросами на ru и kk → отдельная строка в CHANGELOG.

**Деньги:** не подключены. Любая покупка за ₸ → `ComingSoonSheet`. Числа экономики (цены, лимиты, бонусы) — только из `src/lib/economy.ts`, не дублировать в компонентах.

**Вход в занятие** (решение #120): новый режим с заданиями получает свой ключ входа и платит через `payEntryOnce(key, cost)` — из обработчика или хуком `useEntryAccess` (списание в `requestAnimationFrame`, не синхронно в эффекте). Ключ передаётся в `SessionResult.drillKey`, чтобы `finishSession` его снял. Уход с итогов платного занятия — `replace` (`router.replace`, `ButtonLink replace`), иначе «Назад» откроет занятие заново за новое сердечко. Платный вход внутри открытого экрана (задача практикума, «Дай задачи») запоминается в `ref`, пока экран смонтирован.

**Опыт и бустер** (решение #122): бустер умножает только опыт (`xpMultiplier`) внутри стора; опыт, показанный в плеере, — зачисленный стором, а не базовый. Чипы — только за дела (`CHIP_REWARD`), множитель — только тарифа.

**Соцчасть и дуэли** (решения #126–#129): данные другого игрока — только через сервер и только то, что разрешено (имя после фильтра, уровень, рамка, титул; код друга — только друзьям); адресат жалобы или блокировки в живом матче определяет сервер по подписанному месту (`x-duel-seat`), а не по коду из тела; GET никогда ничего не меняет (добавление в друзья по ссылке — POST по кнопке); бот всегда помечен «бот» и не попадает в топы; чата и свободного текста между игроками нет; новый маршрут соцчасти — `sameOrigin`, игрок по cookie, потолок тела, 503 при выключенной соцчасти, лог `[social] … cmds=N`; клиент не импортирует `lib/duel/deck.ts` и банк.

**Окна поверх окон:** модальное окно над другим окном и ссылки на тот же маршрут (`#якорь`) сами закрывают окно-родитель.

## 4. Контент и язык

### 4.1 Урок

Три файла на урок: `content/lessons/<id>.ts`, `lib/bank/<id>.ts`, `content/ent/<id>.ts`. Образцы — `ns-2-read.ts`, `ns-3-write.ts`; прочитай и соседние уроки той же темы.

- Один навык; 14–18 шагов; `durationMin` 6–9; конспект 500–1200 знаков на каждом языке.
- Порядок шагов:
  1. `story` (`speaker: "bit"`): ситуация и зачем это;
  2. `theory` со `scene`: одна карточка — одна мысль, плюс «Где это встречается»;
  3. `worked`: 2–3 примера A → B → C, у каждого подшага своя сцена;
  4. ловушка: типичная ошибка ЕНТ (разбор или задание с `reveal`);
  5. `cloze`: решаем вместе;
  6. сам: 6–8 заданий от A до C;
  7. ≥ 2 задания ЕНТ (`ent: true`) — «босс урока» в реальном формате;
  8. финал: короткий `story` или шпаргалка `theory`.
- Типы вопросов чередовать (`choice`, `input`, `match`, `order`, `multi`, `cloze`): не больше двух одного типа подряд.
- Сцена — минимум у 5 шагов.
- Предупреждения `check-content` «по методике 12–15 шагов» и «не больше 8 заданий» устарели — ориентир этого раздела (14–18 шагов) главнее.
- Python-уроки ссылаются на прошлые («в уроке «Циклы» ты уже видел…»).
- **Микроурок** (`micro: true`, этап 14, #82) — одна маленькая часть сложного навыка в цепочке перед «родительским» уроком: 9–12 шагов, 4–6 заданий (≥ 1 с `ent: true` в настоящем формате), `durationMin` 3–5, конспект 300–800 знаков; `skills` — навык родительского урока (своего банка и файла ЕНТ нет). Каждый следующий микроурок ссылается на предыдущий.
- «Босс урока» в формате ЕНТ (одно «соответствие» 2×4 и, если нет, «несколько верных» на 6) код вставляет сам (`lib/ent-boss.ts`) — в файле урока его не писать.

### 4.2 Задания

У каждого вопроса: `skill` (из `lesson.skills`), `level` (1=A, 2=B, 3=C), `hint`, `explanation` (полное решение). У `choice` и `multi` — `whyWrong`.

| Тип | Ключевые поля и правила |
|---|---|
| `choice` | `options` (≥2, без повторов), `correct` |
| `multi` | `options` (≥3), `correct: number[]` — набор точно верный |
| `input` | `answers` — все допустимые записи; `mode` `number`/`binary`/`text`; `suffix` |
| `match` | 3–6 пар, справа без повторов, соответствие взаимно-однозначное |
| `order` | `items` в **правильном** порядке (экран перемешает), ≥3 |
| `cloze` | ≥1 пропуск; `binary`-пропуск — только 0 и 1 |
| `entmatch` | «соответствие» как на ЕНТ: ровно 2 `items`, 4 `choices`, `answer` — 2 разных индекса 0..3; без «A. », «1) » в начале |
| `code` | задача практикума на Python в уроке: `task` — id задачи из `lib/ide/python/tasks.ts`, `skill` — навык урока, `prompt` (вводная), `explanation`, `hint`; только в Python-уроках, одна на урок, после «сам» и до заданий ЕНТ |

- `whyWrong`: длина = числу вариантов, у верных `null`, у остальных — одна фраза об ошибке без рода («Остатки прочитаны сверху вниз»).
- Код — только в `scene: { kind: "code" }`, не в тексте вопроса.
- `reveal` — только у вопросов.
- Десятичные ответы — в режиме `text`: `["12.5", "12,5"]` (режим `number` выкидывает точку).
- Id шагов: `<префикс>-<что>` (`oct-q-triads-1`), уникальны в уроке.

**Уровень — это тип рассуждения, не размер чисел:** A — применить правило по образцу; B — узнать образец в таблице или коде, сравнить; C — несколько шагов, сочетание тем, обратная задача, настоящий формат ЕНТ.

### 4.3 Сцены

Выбирай вид по тому, что показываешь:

| Вид | Для чего | Ограничения |
|---|---|---|
| `table` | таблицы истинности, БД, электронные таблицы, трассировка | ≤8 столбцов, ≤16 строк |
| `code` | Python, SQL, HTML/CSS | 1–24 строки, ≤60 символов, отступ 4 пробела |
| `circuit` | логические схемы | 1–4 входа, 1–6 вентилей |
| `flow` | блок-схемы, топологии | сетка x 0..4, y 0..9 |
| `cards` | темы на знание | 1–9 карточек, иконки из `IconName` |
| `pixels` | растр | до 16×16 |
| `venn` | 2–3 множества | значения ≤12 символов |
| `web` | HTML/CSS | без скриптов |
| `binary`, `ladder`, `lamps`, `coins`, `decimal` | системы счисления | — |
| `hardware`, `pc-inside`, `cpu-cycle`, `keyboard`, `sizes`, `files`, `layers`, `quest` | устройство ПК, файлы, сюжет | см. `docs/specs/content.md` |

Подписи — `{ ru, kk }` или строка без перевода (числа, код), не пустые.

### 4.4 Банк практики

- Один `SkillBank` на навык. `question(level, seed)` — обязательно, детерминированно по `seed` (`seeded(seed)` из `src/lib/text.ts`). Также `statement`, `pair`, `short`.
- Задачи на вычисление — генератор в коде: верный ответ считает код, неверные варианты — из типичных ошибок, а не просто n±1. Образцы: `src/lib/generators.ts`, `src/lib/bank/ns.ts`.
- Темы на знание — `poolBank({ skill, questions, statements, pairs, shorts })` из `src/lib/bank/pool.ts`.
- Минимум: ≥18 вопросов (≥6 на каждый уровень), ≥10 утверждений, ≥8 пар, `short` ≥8, где ответ однозначен. У вопросов, утверждений и `short` — `hint` (без ответа) и `explanation`; у `choice`/`multi` — `whyWrong`.

### 4.5 Задания ЕНТ

Реальный формат (`docs/ENT.md`): 40 заданий, 50 баллов — 25 single, 5 context (группа из 5 вопросов по программе на Python), 5 multi (6 вариантов, 2/1/0 балла), 5 match.

| Тип | Правила |
|---|---|
| `single` | ровно 4 разных варианта, `correct` 0..3, `whyWrong` из 4 |
| `multi` | ровно 6 вариантов, 2–3 верных |
| `match` | ровно 2 `items`, 4 `choices`, `answer` — 2 разных индекса; без «A. », «1) » в начале |
| `context` | текст + ровно 5 вопросов по 4 варианта, id уникальны |

- Минимум на урок: ≥12 single, ≥4 multi, ≥4 match; в Python-уроках с пометкой «контекст» — ≥2 context (образец — демо НЦТ «касса супермаркета»).
- Все три уровня, примерно 50/30/20. У каждого задания и вопроса контекста — `hint`.
- `id` = `<id урока>:<имя>` (`^[a-z0-9-]+:[a-z0-9-]+$`); `topic` — из `lesson.entTopics`.
- Стиль как в демоверсиях НЦТ: коротко, однозначно, без подвохов в формулировке; дистракторы — реальные типичные ошибки. Не копировать задания дословно из сборников.
- **Практика на ЕНТ — это «чтение кода» (#87).** В уроках по Python, алгоритмам, БД, SQL, таблицам и вебу задания ЕНТ — в основном «прочитать готовое», с полем `read`: `output` (что выведет), `bug` (где ошибка), `fix` (что поменять), `fill` (что вставить вместо `___`), `purpose` (зачем строка), `schema` (первичный и внешний ключ, связь). В банке каждого такого урока — **≥ 2 single** с `read` из `bug`, `fix`, `fill`, `purpose` (их берёт «босс» урока). У `bug`/`fix` строку с ошибкой не подсвечивать (`marks`). Для `fix`/`fill` прогнать **каждый** вариант: верный ровно один. Шаблоны и типовые ошибки — `docs/specs/stage15.md`, А1.
- Условие задания ЕНТ — на «вы», как на экзамене («Выберите…», «Установите соответствие…»; kk — «таңдаңыз»); подсказка и разбор — на «ты», как весь курс.

### 4.6 Подсказки и объяснения

- `hint` — 1–2 фразы, толкает к первому шагу, **никогда не даёт ответ**. Бесплатно, без ИИ, одинаково для всех.
- `explanation` и `whyWrong` показываются бесплатно при ошибке, до любого разбора ИИ.
- Теория понятна без ИИ.

### 4.7 Тон

- На «ты», коротко, дружелюбно, без канцелярита и эмодзи.
- Без рода: «у тебя получилось», «остатки прочитаны снизу вверх».
- Ученик — полный новичок: термин только после бытового примера.
- Формулы — Unicode, не LaTeX: `1011₂`, `2³`, `N = 2ⁱ`, `I = K · i`, `¬A`, `A ∧ B`, `A ∨ B`, `A → B`, `≤`, `≠`.
- Markdown в `body`/`explanation`: **жирный**, списки, `код`. Без HTML и markdown-таблиц — таблица идёт сценой `table`.
- Программирование — только Python 3.

### 4.8 Корректность — 100%

- Каждую программу на Python запусти (`python3`, временные файлы — в `scripts/out/`). Ответ на «что выведет» — реальный вывод.
- SQL — проверь через python3 + sqlite3 на той же таблице.
- Логику, таблицы истинности, формулы таблиц, перевод систем, единицы — считай python3, не в уме.
- В отчёте — что проверено и чем.

### 4.9 Казахский

- Литературный язык, термины — по глоссарию НЦТ (`docs/ENT.md` §4) и казахстанским учебникам.
- ЕНТ по-казахски — **ҰБТ** («ЕНТ» в kk — ошибка). «екілік», не «бинарлы».
- Окончание после числа — только `kkSuffix(n, падеж)` из `src/lib/kk.ts` (`acc | dat | loc | abl | gen | ins`: «25-ті», «6-дан»); частица после него тоже по сингармонизму. Проще — без окончания: «x = 25», «25 саны», «нәтижесі: 25».
- Без падежного окончания сразу после кода или `{параметра}`.
- Нет носителя-редактора → каждый новый kk-текст через `npm run review:kk`; в CHANGELOG: «вычитано моделью, носителем — нет».
