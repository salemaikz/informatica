> **Этот файл — для тебя, человека.** Codex читает свои правила в `AGENTS.md` и в `docs/`.
>
> Набор собран **2026-10-03** из проекта **Informatica** — это такое же приложение, только по информатике (дальше — «образец»). Факты о Codex, ценах и ЕНТ указаны на эту дату. Пометка **«проверить»** значит: факт не подтверждён, перед тем как полагаться — проверь. Пометка **«совет»** — наше мнение.

## 1. Что это за набор

Ты делаешь приложение для подготовки школьников Казахстана к ЕНТ (ҰБТ) **по математике**. Оно такое же, как Informatica:
- короткие уроки на 5–7 минут, как в Duolingo;
- мини-игры, XP, серия дней, уровни, достижения;
- статистика и «работа над ошибками»;
- ИИ-наставник **«Пи»** (маскот — робот с антенной в форме π);
- два языка — русский и казахский, равноправно.

Цель та же, что у образца: **максимально качественно и максимально дёшево**.

**Кто что делает:**
- код пишет **OpenAI Codex**;
- ты — **заказчик и приёмщик**: даёшь Codex готовые задания из `docs/PROMPTS.md`, смотришь результат на телефоне, говоришь «принято» или «вот замечания».

**Что внутри набора:**
- правила для Codex (`AGENTS.md`);
- подробные документы: что строим, как это выглядит, как устроен код, как писать уроки, как работает ИИ, какие игры, что на ЕНТ, план по этапам, готовые промпты;
- `reference/` — эталонные файлы кода Informatica. Codex берёт из них образец, чтобы сделать «так же», а не придумывать заново.

**Кода приложения в наборе нет.** Его по этапам напишет Codex (`docs/ROADMAP.md`).

## 3. Два пути

### Путь A — с нуля по правилам (основной)

Codex строит приложение с пустой папки по этапам `docs/ROADMAP.md`. Весь набор написан под этот путь.

- **Плюсы:** чистый проект под математику, без «хвостов» информатики; каждый шаг понятен и проверен тобой; на каждый этап есть готовый промпт.
- **Минусы:** дольше. Один фундамент (этап 1) — это 9 частей (1.1–1.9), для них 13 промптов (от П-1.1 до П-1.9б), каждый в своём чате и с короткой приёмкой.

Дальше в этом файле описан путь A.

### Путь B — взять движок Informatica (только если владелец Informatica даст доступ к коду)

Это вариант, а не обязанность. Без доступа набора полностью хватает для пути A.

| | |
|---|---|
| **Плюсы** | быстрее старт: у образца уже работают онбординг, плеер урока, стор с прогрессом, XP и серия, тренировка, «работа над ошибками», маршруты ИИ, панель инструментов, оболочка игр, тесты (467 юнит-тестов и 6 e2e на снимке 2026-10-03, v0.4.0) |
| **Минусы** | много «информатики», которую надо аккуратно убрать (двоичные лампочки, лесенка деления, калькулятор систем счисления, навыки `ns.*`, 4 игры про биты). Математического ядра там нет: точные дроби, разбор выражений, KaTeX, математическая клавиатура. Риск, что где-то останется старое |

**Как идти по пути B (коротко):**
1. Получи у владельца Informatica доступ к репозиторию **и разрешение** использовать код.
2. Создай **свой новый** репозиторий `matematika` (раздел 6, шаг 3). Попроси Codex: «Скопируй код Informatica в эту папку без её истории git и сделай первый коммит» (совет: так проще, чем форк).
3. Замени правила и документы на этот набор:
   - `AGENTS.md` — из набора;
   - `CLAUDE.md` удалить: это правила для Claude Code, их заменяет `AGENTS.md`;
   - документы Informatica из `docs/` перенести в `docs/informatica/` (как справку) или удалить, а на их место положить `docs/` набора;
   - `reference/` не нужен: живой код уже в проекте.
4. Обязательно поменяй:
   - ключ хранилища `informatica-v1` → `matematika-v1`;
   - название, иконку и PWA-манифест;
   - маскота «Бит» → «Пи» (`docs/DESIGN.md`, раздел 10);
   - названия уровней и достижений (`docs/CONCEPT.md`, раздел 7);
   - промпты ИИ: термины информатики → математика, правило «без LaTeX» → «простое Unicode, сложное KaTeX» (`docs/AI.md`).
5. **Новый проект в Vercel и новый ключ OpenAI.** Ключ Informatica не использовать никогда.
6. Первый промпт (план, без кода): «Это код Informatica. Сравни его с `docs/ARCHITECTURE.md` и этапом 1 в `docs/ROADMAP.md`: что уже есть, что убрать, что добавить. Составь план перевода на математику, не больше 10 пунктов. Код не меняй». Потом отметь в ROADMAP, какие части этапа 1 уже готовы, и иди по этапам как в пути A.

| Что | Зачем | Сколько стоит (на 2026-10-03) | Когда нужно |
|---|---|---|---|
| **GitHub** (github.com) | хранит код. Облако Codex и Vercel берут код отсюда | бесплатно, приватный репозиторий | этап 0 |
| **ChatGPT Plus** (chatgpt.com) | в нём Codex — им ты разрабатываешь | **$20 в месяц** | этап 0 |
| **Vercel** (vercel.com, вход через GitHub) | сайт: выкладывает новую версию после каждого изменения | бесплатный тариф Hobby. Можно ли на нём коммерческий проект — **проверить** до платного запуска | этап 1 (как только есть что показать) |
| **OpenAI API** (platform.openai.com) | ключ для ИИ **внутри приложения**: наставник «Пи», подсказки, проверка фото | плата за токены, отдельный счёт. Совет: жёсткий лимит **$10–20 в месяц** на старте | этап 2 |

Тарифы ChatGPT (источник — https://learn.chatgpt.com/docs/pricing, 2026-10-03):
- **Free и Go ($8)** — только GPT-6 Luna (самая экономичная модель) и только в приложении для компьютера. Для проекта мало.
- **Plus ($20)** — Codex в приложении для компьютера, в браузере, в терминале и на iPhone, облачные задачи, ревью кода, модели GPT-6.1 Sol и GPT-6 Luna. **Это стартовый вариант.**
- **Pro (от $100)** — то же плюс больше лимитов. Пока на Pro нет 5-часового лимита. Брать, только если на Plus постоянно упираешься в лимит.

Сколько работы влезает в Plus: OpenAI оценивает **15–160 сообщений на GPT-6.1 Sol** или **350–3000 на GPT-6 Luna** за 5 часов. Это не фиксированные числа: длинные чаты тратят больше. Могут действовать и недельные лимиты. Остаток видно на https://chatgpt.com/codex/settings/usage.

### Подписка ChatGPT и ключ API — это разные вещи

| | Подписка ChatGPT Plus | Ключ OpenAI API |
|---|---|---|
| Для кого | для **тебя**: ты работаешь с Codex | для **приложения**: «Пи» отвечает ученикам |
| Как платишь | фиксированно, $20 в месяц | за каждый запрос учеников, с баланса на platform.openai.com |
| Где живёт | ты входишь в Codex кнопкой **«Sign in with ChatGPT»** | секретная строка в файле `.env.local` на твоём компьютере и в настройках Vercel |

- Plus **не оплачивает** API, а API **не даёт** доступа к Codex по подписке.
- **В Codex входи только через «Sign in with ChatGPT».** Если войти API-ключом, работа Codex будет списываться по тарифам API, а облачные задачи и ревью в GitHub станут недоступны.
- Сколько стоит ИИ в приложении (замеры образца, **проверить** по логам): запрос к наставнику на модели `gpt-5.4-mini` — примерно $0,001–0,003 (подсказка ≈ $0,001, чат ≈ $0,002–0,003; цены: $0,75 за 1 млн входных токенов, $4,50 за 1 млн выходных, developers.openai.com/api/docs/pricing, 2026-10-03). То есть $1 — это примерно 350–1000 ответов. Подробно — `docs/AI.md`, раздел 11.
- В приложении есть лимит 60 обращений к ИИ в день на ученика, как в образце. Но это счётчик на телефоне ученика: его обходят очисткой данных браузера, **бюджет он не защищает**. Настоящая защита — жёсткий месячный лимит в кабинете OpenAI (ниже). Лимиты на аккаунт ученика появятся на этапе 8 (часть 8.3).

### Как завести ключ API с лимитом (этап 2)

1. platform.openai.com → создай отдельный **Project** «matematika» и ключ в нём (https://platform.openai.com/api-keys).
2. **Project settings → Limits → Spend → Monthly spend limit** → включи **Enforce a hard limit** → Save. Добавь оповещение (Spend alert) на 50 %.
3. Когда лимит кончится, API ответит ошибкой `429`, а приложение продолжит работать без ИИ: у каждого задания есть обычное объяснение.
4. Ключ показывается один раз. Положи его в `.env.local` (шаг 11) и в Vercel. **Больше никуда:** ни в чат с Codex, ни в скриншоты, ни в документы.

## 6. Пошагово: от нуля до первого сайта

### Шаг 1. Аккаунты
Заведи GitHub, ChatGPT Plus и Vercel (раздел 4). OpenAI API можно отложить до этапа 2.

### Шаг 2. Установка
Поставь приложение ChatGPT, Git и Node.js (раздел 5).

### Шаг 3. Репозиторий на GitHub
github.com → **New repository** → имя `matematika` → **Private**. Галочки «Add README» и «.gitignore» **не ставь**: пустой репозиторий проще подключить.

### Шаг 4. Папка проекта
1. Создай на компьютере папку `matematika`.
2. Владелец Informatica передаёт тебе папку `math-kit` (архивом или ссылкой). Распакуй её, зайди **внутрь** `math-kit` и скопируй всё, что там лежит, в свою папку `matematika`. Саму папку `math-kit` внутрь `matematika` класть не нужно. Должно получиться так:

```
matematika/
├── README.md        ← этот файл
├── AGENTS.md        ← правила для Codex (обязательно в корне!)
├── docs/            ← CONCEPT, DESIGN, ARCHITECTURE, …, HANDOFF
└── reference/       ← образцы кода Informatica
```

Копируй папки целиком, а не отдельные файлы. В `reference/` есть скрытый файл `.env.example` (имя начинается с точки), и его легко потерять.

**Проверка:** `AGENTS.md` лежит прямо в `matematika/`, а не в `matematika/math-kit/`. Иначе Codex не увидит правила.

### Шаг 5. Codex
1. Открой приложение ChatGPT → режим **Codex** → открой папку `matematika`.
2. Где работать — **Local** (на этом компьютере).
3. Права — **Ask for approval**: Codex правит файлы в папке проекта, а для всего за её пределами спрашивает разрешение. **«Full access» не включать.**
4. Модель — **GPT-6.1 Sol**, усилие **Medium**. Модель и усилие выбираются переключателем прямо под полем ввода сообщения (в приложении он может выглядеть как ползунок с готовыми вариантами, точный выбор — **Advanced**). Что значат эти слова — словарик, раздел 11.

### Шаг 6. Первый коммит (точка отката)
Новый чат, сообщение:

> Сделай из этой папки git-репозиторий. Создай `.gitignore` как в `docs/WORKFLOW.md`, раздел 1.4. Проверь командой `git check-ignore .env.local`, что ключ не попадёт в git. Сделай первый коммит «Набор правил Matematika, v0.0.0» в ветку `main`, пропиши адрес `https://github.com/<твой-логин>/matematika` и отправь коммит туда. Если для отправки нужен вход в GitHub — объясни мне по шагам, что нажать.

- Папку `reference/` коммитим вместе со всем. Из проверок и сборки её исключит промпт П-1.1.
- `.env.example` коммитим, `.env.local` (с ключом) — никогда.
- Если Codex попросит разрешение на `git push` (это выход в интернет) — разреши: это разовое разрешение, а не Full access.
- **Если push не проходит** (просит логин или пишет про авторизацию), самый простой путь для новичка:
  1. Поставь **GitHub Desktop** (desktop.github.com) и войди в нём в свой GitHub.
  2. **File → Add local repository** → выбери папку `matematika`.
  3. Нажми **Push origin** (адрес репозитория Codex уже прописал).
  
  Если и после этого Codex не может отправить сам — отправляй кнопкой **Push origin** в GitHub Desktop после каждого коммита. Другой путь — попросить Codex провести тебя через вход командой `gh auth login` (программа GitHub CLI, вход через браузер).

Открой репозиторий на GitHub: файлы должны быть там.

### Шаг 7. Этап 0 — Codex знакомится с набором
**Новый чат** → промпт **П-0** из `docs/PROMPTS.md`. Codex прочитает набор и выдаст список противоречий и вопросов к тебе. Ответь на них. Codex запишет ответы в `docs/DECISIONS.md`.

Здесь же реши, согласен ли ты с решениями по умолчанию. Название, маскот, модели ИИ и другие — краткая таблица вверху `docs/DECISIONS.md`.

### Шаг 8. Проверка этапа 0
Новый чат: «Перескажи правила проекта в 5 пунктах. Код не меняй».

В ответе должны быть: русский и казахский; семантика цветов (зелёный — верно, красный — неверно, фиолетовый — ИИ); «правильный ответ считает код»; «ключ OpenAI только на сервере». Всё на месте — этап 0 готов (`docs/ROADMAP.md`).

### Шаг 9. Этап 1, часть 1.1 — каркас приложения
Новый чат → **П-1.1**. Когда Codex закончит, попроси: «Запусти сайт у меня и скажи адрес». Обычно это http://localhost:3000. Открой его в браузере.

Когда заглушка на localhost открылась и ты согласен — новый чат → **Т-6** («Ревью и выкладка»), скажи «выкладываем»: Codex вольёт PR в `main` и попросит подключить Vercel (шаг 10).

### Шаг 10. Сайт в интернете (Vercel)
Делай этот шаг только после Т-6 для части 1.1: пока кода нет в `main`, Vercel собирать нечего (`docs/WORKFLOW.md`, 1.6).

1. vercel.com → войти через GitHub.
2. **Add New → Project → Import** → репозиторий `matematika` → **Deploy**. Next.js Vercel узнаёт сам.
3. Ветка продакшена — `main`. Где это в настройках (Settings → Git) — **проверить**.
4. Vercel даст **публичный адрес** вида `matematika.vercel.app`. Если имя занято, будет суффикс: у Informatica адрес `informatica-chi.vercel.app`. Не путай со служебными адресами сборок вида `matematika-<хэш>-….vercel.app` — они открываются только после входа в Vercel. Запиши публичный адрес в `docs/HANDOFF.md`.

### Шаг 11. Ключ OpenAI (когда дойдёшь до этапа 2)
1. Заведи ключ с лимитом (раздел 4).
2. Попроси Codex: «Создай `.env.local` из `.env.example`, значение ключа оставь пустым». **Сам** открой `.env.local` в текстовом редакторе и вставь ключ после `OPENAI_API_KEY=`. Не вставляй ключ в чат.
3. Vercel → проект → **Settings → Environment Variables** → `OPENAI_API_KEY` для **Production**. После изменения нажми **Redeploy**: новые значения действуют только для новых сборок.
4. Без ключа приложение тоже работает: ИИ-кнопки показывают запасные ответы.

### Шаг 12. Дальше — по этапам
Каждый этап и каждая его часть идут по одной схеме:

1. новый чат → промпт из `docs/PROMPTS.md`, на модели, которая указана над промптом;
2. большая задача → Codex сначала показывает план (`/plan`) → ты отвечаешь «ок» или поправляешь;
3. Codex делает, проверяет, обновляет документы, коммитит в **ветку** этапа и открывает PR;
4. ты смотришь **превью** на телефоне и проходишь пункты «Готово, когда» из ROADMAP;
5. замечания → промпт Т-5 (один баг) или Т-11 (список);
6. всё нравится → Т-6 «Ревью и выкладка»: PR вливается в `main`, и публичный сайт обновляется.

**Этап закрыт только тогда, когда ты его принял.**

**Что Codex проверяет сам** — команды:
```bash
npm run typecheck && npm run lint && npm test && npm run build
```
Перед выкладкой ещё `npm run e2e`. Если Codex говорит «готово», попроси: «Покажи вывод проверок». Должно быть всё зелёное.

**Как поставить приложение на телефон** (после этапа 1.3; эти две инструкции можно пересылать тестерам и ученикам вместе с публичным адресом):

- **iPhone:** открой адрес в **Safari** (не в другом браузере) → кнопка «Поделиться» (квадрат со стрелкой) → «На экран «Домой»» → «Добавить».

## 8. Ежедневный цикл

**Начало**
1. Приложение ChatGPT → Codex → папка `matematika`.
2. «Чисто ли в git?» Если нет — сначала разобраться или закоммитить.
3. **Новый чат.** Модель — по промпту: думать — Sol, механика — Luna.
4. Первое сообщение: «Прочитай `docs/HANDOFF.md` и текущий этап в `docs/ROADMAP.md`. Где мы и что дальше — 3–5 строк. Код не меняй».
5. Дай задачу: промпт из `docs/PROMPTS.md` или своя по шаблону (раздел 9, правило 4).

**Во время работы**
- Отвечай на вопросы плана. Не понял — «объясни проще, что мне нажать».
- Codex просит разрешение на команду — прочитай, что она делает. Непонятно — спроси «зачем и что будет».
- Тема сменилась → новый чат. Codex «поглупел» и повторяется → «обнови HANDOFF» и новый чат.
- Никогда не проси «прочитай весь документ»: документы в `docs/` большие (самые большие — около 200 КБ), и один такой запрос съест весь чат. Пиши «прочитай раздел N из `docs/…`». Не знаешь номер — «найди в `docs/…` раздел про …».

**Конец задачи**
- [ ] проверки зелёные (вывод показан);
- [ ] ревью `/review` в **новом** чате, найденное исправлено;
- [ ] CHANGELOG, ROADMAP, HANDOFF обновлены;
- [ ] коммит и push ветки, ссылка на превью;
- [ ] ты посмотрел на телефоне.

**Конец дня:** «Обнови `docs/HANDOFF.md`, закоммить и запушь ветку». Всё должно быть отправлено на GitHub.

**Раз в 1–2 недели:** остаток лимита Codex (https://chatgpt.com/codex/settings/usage) и расходы API (platform.openai.com → Usage).

Подробно — `docs/WORKFLOW.md`, разделы 2 и 15.

## 9. Десять главных правил

1. **Ты принимаешь, Codex делает.** Этап закрыт, только когда ты сам прошёл его на телефоне и сказал «принято».
2. **Одна задача — один чат.** Новый чат всегда начинай с `docs/HANDOFF.md`. Один чат на весь проект — дорого и хуже по качеству.
3. **Перед задачей в git должно быть чисто, после задачи — коммит.** Это твоя кнопка «отменить».
4. **Задачи — из `docs/PROMPTS.md`.** Свою задачу пиши из четырёх частей: **цель** · **контекст** (какие файлы) · **ограничения** (чего не трогать) · **готово, когда** (что можно увидеть или проверить).
5. **Модель — по сложности.** Думать и планировать — GPT-6.1 Sol. Механику — GPT-6 Luna, она примерно в 20 раз экономнее. Fast, Max и Ultra не включать.
6. **После работы — ревью в новом чате** (`/review`). В Informatica ревьюер каждый раз находил настоящие баги.
7. **Смотри глазами то, чего не поймает тест:** телефон, тёмная тема, казахский. Тестерам давай только публичный адрес.
8. **Ключ OpenAI — только в `.env.local` и в Vercel.** Никогда в чат и в код. В кабинете OpenAI — жёсткий лимит расходов. Утёк — сразу отзови и выпусти новый.
9. **Правильные ответы считает код, ИИ только объясняет.** Если Codex предлагает «пусть ИИ проверяет ответы» или «пусть ИИ придумывает задания на лету» — отвечай «нет»: это дорого и ненадёжно, модели ошибаются в арифметике.
10. **Всё — на двух языках.** Новые казахские тексты Codex прогоняет через `npm run review:kk`. Найди учителя математики — носителя казахского, чтобы он хотя бы выборочно проверял.

## 10. Если что-то пошло не так

| Что случилось | Что делать |
|---|---|
| Codex 2–3 раза чинит одно и то же | Стоп. «Код не меняй. Опиши, что пробовал, что видишь, и 2–3 гипотезы». Потом новый чат с этим описанием на Sol · High. Не помогло — откатиться и разрезать задачу на части |
| Всё сломалось, непонятно что менялось | «Покажи `git status` и `git diff --stat` и объясни простыми словами». Плохо — «Верни все файлы к последнему коммиту» (несохранённое пропадёт) |
| Сломался сайт для учеников | Vercel → Deployments → прошлая рабочая сборка → откат (кнопка Instant Rollback или Promote — **проверить**). Чинить потом, спокойно, в ветке |
| Сборка на Vercel упала | Vercel → Deployments → упавшая сборка → Build Logs. Дай Codex **только текст ошибки**, не весь лог |
| `git push` не проходит (просит логин, ошибка авторизации) | Отправь кнопкой **Push origin** в GitHub Desktop (раздел 6, шаг 6) или попроси Codex провести через `gh auth login`. Пароль и токен GitHub в чат не вставляй |
| Codex говорит «готово», а не работает | «Покажи вывод проверок». Для бага — «сначала воспроизведи его тестом» |
| Задаёт слишком много вопросов | «Действуй сам, спрашивай только перед необратимым» |
| Забывает правила, повторяется | Чат переполнен: `/status` → «обнови HANDOFF» → новый чат |
| Одна и та же ошибка второй раз | «Сделай ретроспективу: почему так вышло? Предложи одно правило для `AGENTS.md`» |
| Хочет удалить урок, навык или поменять ключ хранилища | Запретить. На них хранится прогресс учеников. Урок убирают с карты, но не удаляют |
| Просит Full access или команду вроде `rm -rf`, `git reset --hard`, `git push --force` | Отказать и спросить: «Зачем? Что будет? Можно ли безопаснее?» |
| Кончился лимит Codex посреди задачи | Текущий ход доделается сам. Обнови HANDOFF, продолжи после сброса лимита; механику — на Luna |
| Ключ OpenAI попал в чат, в git или на скриншот | Сразу отзови его на platform.openai.com, выпусти новый, замени в `.env.local` и в Vercel |
| Сайт «не открывается» у друзей | Ты дал служебную ссылку превью (`matematika-<хэш>-….vercel.app`). Дай публичный адрес. В Informatica это было замечание № 1 из 25 |
| ИИ в приложении молчит | Нет ключа, кончился лимит расходов (`429`) или лимит запросов. Vercel → Logs → фильтр `[ai]` |

Подробнее — `docs/WORKFLOW.md`, разделы 10–12.

## 11. Словарик

| Слово | Что значит |
|---|---|
| **репозиторий** | папка проекта со всей историей изменений; лежит на GitHub |
| **коммит** | сохранение. К нему всегда можно вернуться |
| **ветка** | отдельная линия работы. `main` — это сайт для учеников |
| **push** | отправить коммиты на GitHub. Vercel сразу собирает сайт |
| **PR (pull request)** | запрос «влить ветку в `main`». В нём видно, что изменилось, и туда пишут ревью |
| **merge** | влить ветку в `main` — то есть выложить для всех |
| **diff** | список изменений: убранное красным, добавленное зелёным |
| **CI** | автоматическая проверка на GitHub при каждом PR и push в `main`: typecheck, lint, test. Зелёная галочка — всё в порядке. Без build и e2e: сборку проверяет Vercel |
| **worktree** | вторая рабочая папка того же репозитория, чтобы два чата Codex работали параллельно и не мешали друг другу |
| **деплой / выкладка** | сборка сайта и публикация в интернете (это делает Vercel) |
| **превью / продакшен** | закрытая проверочная версия ветки (нужен вход в Vercel) / сайт для всех из `main` |
| **локально, localhost** | сайт запущен на твоём компьютере, виден только тебе |
| **токен** | кусочек текста, по ним считают расход ИИ. Русский и казахский текст «весит» больше английского |
| **контекст** | всё, что модель «держит в голове» в этом чате. Чем он больше, тем дороже каждый шаг и тем хуже качество |
| **лимит** | сколько работы даёт подписка Codex за 5 часов или за неделю; у API — твой денежный потолок |
| **модель / усилие (reasoning)** | какой «мозг» работает и сколько он думает: дольше — точнее, но дороже. Усилие: Light → Medium → High → Extra High |
| **GPT-6.1 Sol / GPT-6 Luna / GPT-6 Astra** | модели Codex. Sol — умная, основная: планы, сложное, ревью. Luna — самая экономичная (примерно в 20 раз экономнее Sol), для механики по готовому заданию. Astra — самая мощная и дорогая, на Plus лимит маленький: GPT-6 Astra · Light/Medium — только если Sol не справился дважды |
| **Fast / Max / Ultra** | режимы, которые тратят лимит гораздо быстрее (Fast — в 2,5 раза). Держи выключенными |
| **слэш-команда** | команда, которую пишешь в поле чата Codex, начинается с `/`: `/plan` — сначала план, без правок; `/review` — проверить изменения; `/status` — сколько контекста и лимита занято; `/model` — выбрать модель. Нет такой команды — скажи то же словами |
| **Local / Cloud** | где работает Codex: на твоём компьютере (основной режим) или в облаке OpenAI (для длинных фоновых задач) |
| **Ask for approval / Full access** | права Codex. Ask for approval — правит файлы в папке проекта, а на всё остальное (интернет, файлы вне папки) спрашивает тебя. Full access — без спроса, **не включать** |
| **прораб / исполнитель** | сильная модель планирует и проверяет, более дешёвая делает по готовому заданию |
| **ТЗ** | техническое задание: точно что сделать и как проверить. Codex кладёт их в `docs/tasks/` |
| **ревью** | независимая проверка чужой работы (`/review`) |
| **тест / e2e** | программа, которая проверяет программу. e2e проходит сайт как живой ученик |
| **typecheck / lint / build** | проверка типов, проверка правил кода, сборка сайта |
| **env-переменная** | настройка вне кода: ключ, имя модели. Хранится в `.env.local` и в Vercel |
| **`.env.local`** | файл с секретами на твоём компьютере. В git не попадает. Никому не показывать |
| **API-ключ** | секретный «пропуск» приложения к OpenAI; за его запросы платишь ты |
| **AGENTS.md** | файл правил, который Codex сам читает в начале каждого чата |
| **skill** | сохранённая инструкция Codex для повторяющейся работы (`.agents/skills/`) |
| **localStorage** | память браузера на телефоне ученика. Там пока хранится его прогресс (ключ `matematika-v1`) |
| **PWA** | сайт, который можно «установить» на телефон как приложение |
| **Unicode / LaTeX / KaTeX** | формулы. Простые пишем обычными символами (`2³`, `√2`, `½`). Сложные — на языке LaTeX, а библиотека KaTeX рисует их красиво |
| **ЕНТ / ҰБТ, НЦТ** | Единое национальное тестирование (по-казахски ҰБТ) и Национальный центр тестирования, который его проводит |

Образец развивается дальше: многое у нас помечено [план образца] (выбор карты курса, стиль видео, игры на банке, облако, мини-ЕНТ), а баги в файлах `reference/` могут исправить позже. **Раз в 2–4 недели** попроси у владельца Informatica свежие `docs/CHANGELOG.md`, `docs/DECISIONS.md` и `docs/HANDOFF.md`, положи их в `scripts/out/sample/` и запусти промпт **Т-14** («Сверка с образцом»). `reference/` руками не правь: если нужен новый снимок образца — он кладётся целиком, с датой в `reference/README.md`.
