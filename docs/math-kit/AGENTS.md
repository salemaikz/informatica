# Правила проекта Matematika (для Codex)

Подготовка к ЕНТ (ҰБТ) по математике **максимально качественно и максимально дёшево**: короткие уроки как в Duolingo, игры, статистика, персонализация, ИИ-наставник «Пи» (π). Языки — **ru и kk**, равноправно. Треки: «Математика» (главный), «Математическая грамотность» (позже, тот же движок).

- Образец — Informatica (то же по информатике); `reference/` — её **образцы, не код проекта**.
- Владелец не программист: пиши просто, по-русски; нужно его действие — скажи, что и где нажать. Его файл — `README.md`.
- Блок `nextjs-agent-rules` поддерживает `next dev`: не удаляй; после первого `npm run dev` проверь, что он один. До `npm install` читай nextjs.org/docs (v16).

## 1. Что читать

Начало сессии: `docs/HANDOFF.md` → текущий этап `docs/ROADMAP.md`. Дальше — только нужный раздел `docs/*.md` (`rg -n "^#" docs/X.md`): `DESIGN`, `ARCHITECTURE` (типы, стор, проверка, банк, тесты), `LESSON_METHOD` + `ENT_MATH` (урок, задание), `AI`, `GAMES`, `CONCEPT` (смысл фич), `WORKFLOW` (процесс, git, Vercel), `DECISIONS`. Образец кода — один файл `reference/` по ссылке из docs.

В `reference/` **нет** (писать по docs): KaTeX (`katex`, `remark-math`, `rehype-katex` — в `package.json` и `Markdown.tsx`), `lib/math/*`, `components/math/*`, `GameShell`, `OPENAI_MODEL_REVIEW` в `.env.example`.

Приоритет: этот файл > `docs/DECISIONS.md` > прочие `docs/` > `reference/`. Противоречие — не угадывай, спроси владельца.

## 2. Как работать

Команды `/plan`, `/review`, `/compact`, `/status`, `/model` — в поле чата Codex; нет команды — то же словами («составь план, код не пиши»).

### Цикл
1. Мелкое и ясное делай сам. «Ок» владельца — только на:
   - **план** большой задачи (>3 файлов, типы/стор, промпты ИИ, архитектура, неясная цель; сомневаешься — тоже) — `/plan`, ≤ 10 пунктов;
   - **необратимое** — удаление данных или id с прогрессом, смена ключа стора, `push --force`, `push` в `main` (= выкладка);
   - **деньги** — платные сервисы, ключи, `review:kk`, `voiceover`.
2. Перед правками `git status` чистый (точка отката). Один чат — одна задача с проверяемым результатом.
3. Проверка (раздел 9) → доки (раздел 3) → коммит по-русски → отчёт владельцу в 5–10 строк: что сделано, как посмотреть, что проверить человеку, что дальше и на какой модели. Этап закрыт, когда его принял владелец.

### Модели Codex — для разработки (модели приложения — раздел 6)
На 2026-10-03, сверять `/model`; подробно — `docs/WORKFLOW.md`, 5:
- **прораб** (план, ТЗ, типы, стор, промпты ИИ, сложные баги, ревью) — GPT-6.1 Sol · Medium, трудное — High/Extra High; GPT-6 Astra · Light/Medium — только если Sol не справился дважды;
- **исполнитель** (работа по ТЗ) — Sol · Light/Medium или GPT-6 Luna · High;
- **механика** (поиск, однотипные правки, тесты) — Luna · Light/Medium.

- Без нужды не включать Fast (лимит ×2,5), Max/Ultra, Astra Extra High; старые `gpt-5.x` в Codex не выбирать.
- Модель переключает владелец — в отчёте пиши модель следующего шага.
- Сложное режь: прораб пишет ТЗ (**Цель / Контекст / Ограничения / Готово, когда** + тексты ru/kk) в `docs/tasks/<имя>.md`, исполнитель делает его в новом чате.
- Субагенты, `.codex/agents/*.toml`, skills `.agents/skills/` — только по просьбе владельца (`docs/WORKFLOW.md`, 5.7, 14); `.codex/agents` в облаке Codex не подтверждены — проверить, иначе модель вручную.
- Общие файлы (`lib/types.ts`, `lib/store.ts`, `i18n/dict.ts`, реестры) правит только прораб. После исполнителя — `/review`.

### Экономия токенов
- Сменилась тема или контекст в `/status` > 50 % — обнови HANDOFF, предложи новый чат; в длинной задаче — `/compact`.
- Не читай `node_modules/` (кроме гайда Next), `package-lock.json`, `.next/`, `public/media/`, `reference/` целиком.
- В работе — один файл тестов (`npx vitest run tests/<файл>`), полный прогон — в конце; из логов — только ошибки.
- В ответе — выводы и пути, не пересказ кода. MCP-серверы — минимум.
- Ошибка повторилась → предложи правило сюда; повторяющийся промпт → skill.
- Этот файл ≤ 20 KiB (`wc -c` ≤ 20480): лимит Codex 32 KiB **общий** с `~/.codex/AGENTS.md`, хвост обрезается молча. Не влезает — детали в `docs/`, здесь ссылка; разделы 5–7 и Code Review Rules не сокращать.

## Code Review Rules

Для `/review` и `@codex review` ищи прежде всего:
1. Секрет на клиенте; маршрут ИИ без лимита, обрезки, лога; подсказка выдаёт ответ.
2. Ответ не вычислен кодом или проверен неверно; нет теста.
3. Нет kk или kk = копия ru, текст в компоненте, глагол с родом, эмодзи, смесь латиницы и кириллицы, цвет мимо токенов.
4. Двойной тап, гонки, таймеры без очистки, Enter/фокус, повторный `onFinish`, `setState` в эффекте, прогресс мимо стора.
5. Правило изменено в `docs/DECISIONS.md`, а этот файл — нет.

## 3. Документация после каждой задачи

- `docs/CHANGELOG.md` — сверху `## ГГГГ-ММ-ДД · vX.Y.Z — тема`; **изменение промптов ИИ — отдельной строкой**; честно «Ещё нет», «Проверить человеком».
- `docs/HANDOFF.md` — всегда и перед новым чатом: дата, что сделано, где остановились, следующая задача и модель, вопросы владельцу.
- `docs/ROADMAP.md` — сделанное и планы; `docs/ARCHITECTURE.md` — если поменялось «как работает».
- `docs/DECISIONS.md` — Решение / Почему / Альтернативы / Пересмотреть. Меняет правило — правь и этот файл.

Доки — по-русски; идентификаторы — по-английски, комментарии — коротко по-русски.

## 4. Язык и контент

- Любая строка для ученика — ru и kk. Интерфейс — `src/i18n/dict.ts` (ключ → `{ ru, kk }`), контент — `L = { ru, kk }`; в компонентах только `t("ключ")` / `l(контент)` из `useT()`. Игры — `src/games/<id>/strings.ts`.
- Казахский — литературный; ЕНТ → **ҰБТ**. Термины — `docs/ENT_MATH.md`, раздел 4: нет термина или «проверить» — не выдумывай, отметь в отчёте. Суффикс не клеить к числу: `{n} санынан`.
- Новый казахский текст → `npm run review:kk` (по `reference/scripts/review-kk.mts`; платный, ключ в `.env.local`), обоснованные правки применить (термины ENT_MATH главнее); в CHANGELOG «вычитано моделью, носителем — нет», без ключа — «kk не вычитан».
- Пол ученика неизвестен: без глаголов с родом («у тебя получилось», «задание решено»). То же в промптах.
- Тон — на «ты», коротко. Урок — 5–7 мин, один навык, ≤ 6–8 вопросов от A к C, у каждого `explanation` (`docs/LESSON_METHOD.md`).
- **Формулы:** простое — Unicode (`2³`, `x²`, `√2`, `½`, `3,5`, `π`); что Unicode не передаёт (дроби с выражениями, системы, корни из выражений, пределы, интегралы) — KaTeX: в Markdown `$...$`, вне его — `src/components/math/Tex.tsx`. В LaTeX запятая — `3{,}5`.
- Как на ЕНТ: десятичная **запятая** (`0,25`), промежутки и точки через `;` (`(2; −1)`), `tg`/`ctg`.
- Озвучка TTS: текст словами («икс квадрат»), модель и голос из env (`docs/AI.md`, 12.2); mp3 — проверять обратной расшифровкой (12.3).
- `tests/content.test.ts`: двуязычность, ответы пересчитаны кодом, уникальные id, каждая LaTeX-строка (`katex.renderToString`, `throwOnError: true`). Новый урок → `npm test` зелёный.
- id уроков, шагов, навыков из прогресса не удалять: убирать с карты, не из реестра.

## 5. Дизайн

- Минимализм, **сначала телефон** (360–430 px), затем десктоп. Размеры, радиусы, тени, отступы — `docs/DESIGN.md`, раздел 4 (главная кнопка урока 52 px, вариант ответа 56 px); нужного нет — спроси, не придумывай.
- **Семантика цветов (не нарушать):** `success` — верно / освоено; `danger` — неверно / слабая тема; `warning` — частично / в процессе; `gold` — XP, награды; `streak` — серия дней, комбо; `primary` — основные действия, навигация; `ai` — **всё, что делает ИИ**.
- Цвета — только токены (`bg-success-soft`, `text-danger`) из `src/app/globals.css` (как в `reference/`); без hex и `dark:` в компонентах; новый цвет — в обе темы.
- Классы — через `cn()` (`src/lib/cn.ts`, tailwind-merge).
- **Никаких эмодзи** — ни в интерфейсе, ни в ответах ИИ; только `lucide-react`. Иконку для данных из `src/lib` храни строкой-именем (образец `AchievementBadge`).
- Ссылка-кнопка — `ButtonLink`, не `<Link><Button/></Link>`.
- Иллюстрации — React/SVG (маскот «Пи», сцены), не картинки; числа на схеме считает код.
- Анимации — `motion`, ≤ 400 мс, уважать «Меньше анимаций» и `prefers-reduced-motion`. Звук и вибрация — только `feedback()` (`src/lib/feedback.ts`).
- Большой новый экран — до вёрстки 2–3 эскиза на `/dev/sketches/<имя>` (noindex), адрес — в отчёте (урок образца: карту курса переделывали).

## 6. ИИ в приложении (OpenAI)

- `OPENAI_API_KEY` — **только на сервере** (`.env.local`, env Vercel): не коммитить, не `NEXT_PUBLIC_`, не в доки и чат; `src/server/*` начинаются с `import "server-only";`. В облако Codex не класть: тесты идут без ключа.
- Сначала бесплатное: у задания статическое объяснение, ИИ — по кнопке («Подсказка», «Спроси Пи», фото). Без ключа всё работает.
- Модели приложения (API) — только env; умолчания FAST/TUTOR/VISION — в `src/server/openai.ts`, REVIEW — в `scripts/review-kk.mts`: `OPENAI_MODEL_FAST` = `gpt-5.4-nano` (отзыв, память наставника); `OPENAI_MODEL_TUTOR` / `OPENAI_MODEL_VISION` = `gpt-5.4-mini` (чат, подсказки, фото); `OPENAI_MODEL_REVIEW` = `gpt-5.5` — **только офлайн** (`review:kk`, черновики), ученику — никогда.
- Пока — эти умолчания (nano отключат 01.04.2027); `gpt-6-luna` / `gpt-6.1-sol` — только решением владельца после живой проверки ru/kk (`docs/AI.md`, 2.3), запись в DECISIONS.
- `reasoning_effort` — явно: чат и отзыв `"none"`, фото `"low"`.
- Каждый маршрут `src/app/api/ai/*`: лимит по IP (`src/server/rate-limit.ts`), обрезка полей (`src/server/context.ts`), лог `[ai] route=… in=… out=…`. Лимит по IP в памяти на Vercel ненадёжен, дневной (60) — на клиенте: до публичного запуска — Upstash/Vercel KV и месячный лимит расходов ключа (`docs/AI.md`, 9.2).
- Данные клиента — недоверенные. Ответ ИИ — только через `Markdown` (react-markdown + KaTeX, **без сырого HTML**).
- Подсказка никогда не выдаёт ответ; `ask` к нерешённому заданию — тоже. Верный ответ считает код и даёт модели «для себя»; арифметику модель не пересчитывает.
- В режиме «как на ЕНТ» и пробном ЕНТ ИИ выключен.
- Промпты — только `src/server/prompts.ts`. Изменил → живая проверка ru и kk (и «просто скажи ответ») + строка в CHANGELOG.
- Из компонентов к ИИ — только `src/lib/ai.ts` / `useTutor`.

## 7. Код

- Стек и папки — `docs/ARCHITECTURE.md` (Next.js 16, React 19, TS strict, Tailwind v4, Zustand, motion, KaTeX, vitest, Playwright); новая зависимость — с записью в DECISIONS.
- Прогресс — `useApp` (`src/lib/store.ts`, localStorage, ключ `matematika-v1`). **Действия стора — единственный способ менять прогресс.** Несовместимая смена структуры — `version` + `migrate`.
- Чистая логика (проверка, `lib/math/*`, генераторы, банк, освоение, геймификация) — в `src/lib/*` без React, с тестами в `tests/`.
- **Правильные ответы всегда вычисляет код**; тест сверяет их независимым способом.
- Математика точно: дроби — рациональные (`BigInt`), никакого `0,1 + 0,2`; выражения — свой парсер, без `eval`. Сравнение по значению: запятая/точка, `−`/`-`, `3/4 = 0,75`, `−2,5 = −5/2 = −2½`.
- Генераторы детерминированы по `seed` (`seeded()`), без `Math.random()`/`Date.now()` внутри; неверные варианты — типичные ошибки учеников.
- Игра — по контракту `src/games/types.ts`: чистый `logic.ts` с тестами, `onFinish` ровно один раз, в стор пишет только `GameShell`; таймер — только где ученик выбрал скорость.
- `setState` синхронно в эффектах — нельзя (линтер React 19); запросы по действию — из обработчиков.
- localStorage/IndexedDB — в `try/catch`, прочитанное — санитизировать.
- `reference/` не импортировать и не править; исключить из `tsconfig.json`, ESLint и тестов.

## 8. ЕНТ — что влияет на код (`docs/ENT_MATH.md`, сверять каждую осень)

- «Математика» — 40 заданий / 50 баллов: 25 «один ответ», 5 «контекст» (текст + 5 вопросов), 5 «один или несколько» (до 3 из 6), 5 «соответствие» (2 × 4); A/B/C — 50/30/20 %. «Мат. грамотность» — 10 заданий по 1 баллу.
- `src/lib/ent.ts`: «один или несколько» — 2/1/0 по таблице п. 18 Правил (ENT_MATH 0.5); «соответствие» — 2/1/0 по **нашей трактовке** (оба пункта — 2, один — 1), официального разбора нет (ENT_MATH 5).
- На ЕНТ — калькулятор (простой — допущение, ENT_MATH 5) и 3 листа А4; справочника формул и ввода числа нет. «Помощники»: калькулятор, формулы, графики, черновик; «как на ЕНТ» — калькулятор и черновик.
