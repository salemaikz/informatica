### #1 · 2026-10-03 · Веб-приложение (PWA), сторы — позже
**Откуда:** Informatica #1, без изменений.
**Решение:** адаптивное веб-приложение, которое открывается с сайта и устанавливается на телефон как PWA (`src/app/manifest.ts`, образец — `reference/src/app/manifest.ts`). В сторы — позже через Capacitor: тот же код в нативной оболочке.
**Почему:** один код для всех устройств, обновления сразу и без модерации сторов, дешевле.
**Альтернативы:** React Native / Flutter — две кодовые базы (сайт + приложение), дороже поддерживать.
**Пересмотреть:** если понадобятся тяжёлые нативные функции (офлайн-видео, сложные уведомления). Планы — `docs/ROADMAP.md`, раздел 6.

### #2 · 2026-10-03 · Стек образца + KaTeX; ИИ — через серверные маршруты Next.js
**Откуда:** Informatica #2 и стек из правил образца.
**Решение:**
- Стек — Next.js 16 (App Router, Turbopack), React 19, TypeScript strict, Tailwind v4, Zustand (persist), `motion`, `lucide-react`, `react-markdown` + `remark-gfm`, `@remotion/player` + `remotion`, `canvas-confetti`, `idb-keyval`, `openai` SDK, `clsx` + `tailwind-merge` (для `cn()`), `server-only`, `vitest`, Playwright, `tsx` (скрипты), шрифты `@fontsource-variable/nunito` и `@fontsource-variable/jetbrains-mono`.
- **Разрешены без отдельной записи:** все зависимости из `reference/package.json` (включая инструменты: `typescript`, `eslint`, `@tailwindcss/postcss`, `@types/*`) и KaTeX — `katex`, `remark-math`, `rehype-katex` (#24). Версии — как в `reference/package.json`, где они там есть.
- Ключ OpenAI живёт только в серверных маршрутах `src/app/api/ai/{tutor,check-solution,lesson-feedback}`. Файлы `src/server/*` начинаются с `import "server-only";`.
- Любая другая новая зависимость — только с записью в этом журнале.

**Почему:** ключ нельзя отдавать в браузер; фронт и бэкенд в одном проекте; бесплатный хостинг на Vercel. Стек проверен образцом, и эталоны в `reference/` написаны именно на нём.
**Альтернативы:** отдельный бэкенд — лишний сервис и затраты; другой фреймворк — теряем эталоны образца.
**Для сторов:** клиент собирается статически, `/api/ai/*` остаётся на сервере, клиент ходит к нему по абсолютному URL.
**Пересмотреть:** не раньше v1.0. Next.js 16 новее знаний моделей: перед работой с его API читать `node_modules/next/dist/docs/` (блок в начале `AGENTS.md`).

### #3 · 2026-10-03 · Прогресс хранится на устройстве (MVP)
**Откуда:** Informatica #3.
**Решение:**
- Весь прогресс — в localStorage через Zustand persist, ключ `matematika-v1` (#21).
- Листы черновика — в IndexedDB (`idb-keyval`).
- Сервер ничего не хранит.
- Действия стора (`src/lib/store.ts`) — единственный способ менять прогресс.

**Почему:** запуск без регистрации, без базы данных и без затрат; ученик сразу учится.
**Минусы:** прогресс не переносится между устройствами; учитель его не видит; лимит ИИ по IP в памяти процесса слабый на serverless.
**Пересмотреть:** на этапе 8 «Вход через Google и облако». В плане образца — Supabase (авторизация + Postgres, бесплатный тариф); сервис выбрать на этапе. Интерфейс действий стора не меняется, меняется только хранилище.

### #4 · 2026-10-03 · Видео = Remotion-композиции в браузере
**Откуда:** Informatica #4.
**Решение:**
- Ролики по 60–90 с — React-композиции Remotion. Их проигрывает `@remotion/player` прямо на странице. MP4 не рендерим.
- Формулы и числа в кадре — те же компоненты, что в приложении (KaTeX, SVG-сцены). Числа считает код.

**Почему:** ноль затрат на рендер, хранение и трафик; переключение ru/kk и субтитров одним пропсом; правка ролика = правка кода; дёшево по токенам.

**Лицензия Remotion:** у образца — бесплатно для частных лиц и компаний до 3 сотрудников. Условия **проверить** на remotion.dev перед коммерческим запуском.
**Пересмотреть:** при выборе стиля видео (#19).

### #6 · 2026-10-03 · Модели ИИ в приложении
**Откуда:** Informatica #6.
**Решение:** модели задаются только env-переменными, умолчания — в `src/server/openai.ts`. `reasoning_effort` всегда задаётся явно.

| Переменная | По умолчанию | Для чего | `reasoning_effort` |
|---|---|---|---|
| `OPENAI_MODEL_TUTOR` | `gpt-5.4-mini` | чат, «Подсказка», «Спроси Пи», «Объясни, ИИ» | `none` |
| `OPENAI_MODEL_VISION` | `gpt-5.4-mini` | проверка решения по фото | `low` |
| `OPENAI_MODEL_FAST` | `gpt-5.4-nano` | отзыв после урока, память наставника | `none` |
| `OPENAI_MODEL_REVIEW` | `gpt-5.5` | **только офлайн**: `review:kk`, черновики контента. На запрос ученика — никогда | — |

**Почему:** в образце проверено живыми запросами: качество на ru и kk хорошее, ответ за 2–3 с, сотни токенов на запрос. Для математики качество объяснений **перепроверить** (`docs/AI.md`).
**Цены API** (за 1 млн токенов, вход / выход; developers.openai.com/api/docs/pricing, 2026-10-03):
- `gpt-5.4-nano` — $0,20 / $1,25;
- `gpt-5.4-mini` — $0,75 / $4,50;
- `gpt-5.5` — $5 / $30;
- кандидаты: `gpt-6-luna` — $0,10 / $0,50; `gpt-6.1-sol` — $2 / $10.

**Пересмотреть:**
- `gpt-5.4-nano` объявлен устаревшим, отключение в API **01.04.2027**. Кандидат на замену — `gpt-6-luna`. Он же — кандидат вместо `gpt-5.4-mini` (усилие `low` или `medium`). У `gpt-6-luna` по умолчанию усилие `medium`, поэтому задавать его явно.
- Для офлайн-задач кандидат — `gpt-6.1-sol` (`none` не поддерживает, минимум `low`).
- Менять только после живой проверки на математике ru и kk (Т-10) и новой записью в этом журнале.

**Как менять:** сначала только env-переменные (проверка `check:prompts`, Т-10). Если новая модель не принимает текущий effort (`gpt-6.1-sol` не принимает `none`), дополнительно поправить `EFFORT` в `src/server/openai.ts` и effort в `scripts/review-kk.mts`. Умолчания в коде менять — только после проверки, новой записью в этом журнале и «ок» владельца (`docs/AI.md`, 2.3; Т-10).

### #7 · 2026-10-03 · Ответы, задания, игры, калькулятор, графики — код; ИИ только объясняет
**Откуда:** Informatica #7, расширено для математики.
**Решение:**
- **Делает код:**
  - проверку ответов (#26);
  - генераторы заданий на каждый навык (`src/lib/generators.ts`, банк `src/lib/bank/`);
  - мини-игры, калькулятор, построитель графиков, числа на схемах.
- Генераторы детерминированы по `seed`. Неверные варианты — типичные ошибки учеников: посторонний корень вне ОДЗ, ошибка знака, перепутанная формула.
- **ИИ делает только:** объяснения, подсказки, чат, проверку рукописного решения по фото, отзыв после урока. Верный ответ ИИ получает от кода и арифметику сам не пересчитывает.

**Почему:** бесконечная практика бесплатно, мгновенно и без ошибок в ответах; всё проверяется тестами. Модели ошибаются в арифметике.
**Альтернативы:** генерация заданий ИИ на лету — дорого, медленно, с ошибками в ответах.

### #8 · 2026-10-03 · Сначала объяснение автора, ИИ — по кнопке

### #9 · 2026-10-03 · Подсказка ИИ не выдаёт ответ
**Откуда:** Informatica #9.
**Решение:** в режиме `hint` модель получает верный ответ, вычисленный кодом, «для себя» — с запретом его сообщать. Она ведёт ученика к первому шагу. После ответа ученика — полный разбор.
**Почему:** педагогика — ученик должен прийти к ответу сам.
**Как проверяем:** при любом изменении промпта — живые запросы на ru и kk, включая настойчивое «просто скажи ответ».

### #10 · 2026-10-03 · Освоение навыка — экспоненциальное сглаживание
**Откуда:** Informatica #10. Числа без изменений, образец — `reference/src/lib/mastery.ts`.
**Решение:**
- `mastery` от 0 до 1 на каждый навык.
- Первый ответ: 0,2 + 0,5 · outcome. Дальше: mastery += 0,3 · (outcome − mastery). outcome — балл ответа от 0 до 1, частично верный — 0,5.
- Пороги: ниже 0,6 — «слабо» (красный), от 0,8 — «освоено» (зелёный), между ними — «в процессе» (янтарный).
- Вес навыка в тренировке — (1,1 − mastery)², по умолчанию mastery = 0,5.
- Уровень задания: ниже 0,5 → A, ниже 0,8 → B, иначе C.

**Почему:** просто, понятно, хорошо работает на малых данных.
**Пересмотреть:** при накоплении данных — BKT / IRT, интервальные повторения с учётом забывания. Основа для них (`lastSeen`) уже хранится.

### #12 · 2026-10-03 · Без глаголов с родом — ни в текстах, ни у ИИ
**Откуда:** Informatica #12.
**Решение:** в промптах и во всех текстах для ученика нет глаголов прошедшего времени с родом: «у тебя получилось», «задание решено», а не «ты сделал/сделала». Пол в онбординге не спрашиваем.

### #13 · 2026-10-03 · Дизайн
**Откуда:** Informatica #13 и правило «без эмодзи» (замечание № 2 тестеров образца).
**Решение:**
- Шрифты: Nunito (есть казахские буквы ә ғ қ ң ө ұ ү һ і) и JetBrains Mono для чисел.

### #14 · 2026-10-03 · Прораб и исполнители: распределение задач между моделями
**Откуда:** Informatica #14. В образце это Claude Code (opus — думать, sonnet — по ТЗ, haiku — механика). Здесь переведено на Codex по документации OpenAI на 2026-10-03.
**Решение:**

| Роль | Модель · усилие | Что делает |
|---|---|---|
| Прораб | GPT-6.1 Sol · Medium; трудное — High / Extra High; GPT-6 Astra · Light/Medium — только если Sol не справился дважды | план, ТЗ в `docs/tasks/`, типы, стор, промпты ИИ, сложные баги, ревью |
| Исполнитель | GPT-6.1 Sol · Light / Medium или GPT-6 Luna · High | код, тесты, переводы, документы по готовому ТЗ |

### #24 · 2026-10-03 · Формулы: простое — Unicode, сложное — KaTeX
**Решение:**
- Простое пишем в Unicode: `2³`, `x²`, `√2`, `½`, `3,5`, `π`.
- Всё, что Unicode не передаёт (дроби с выражениями, системы, корни из выражений, пределы, интегралы), — LaTeX в `$…$` или `$$…$$`, рендер — KaTeX (`katex`, `remark-math`, `rehype-katex`). Вне Markdown — `src/components/math/Tex.tsx`.
- ИИ пишет формулы в `$…$`. Ответ ИИ рендерит `Markdown` (react-markdown + remark-math + rehype-katex) без сырого HTML.
- Тест контента: каждая LaTeX-строка проходит `katex.renderToString(s, { throwOnError: true })`.
- В озвучке формулы читаются словами (#5).

**Почему:** правило образца «только Unicode» для математики не подходит. Двухэтажную дробь, систему или интеграл Unicode не покажет, а ученик должен видеть запись как в учебнике и в вариантах ЕНТ. KaTeX рисует быстро, шрифты идут из пакета, поэтому всё работает офлайн. Тест ловит сломанную формулу до того, как её увидит ученик.
**Альтернативы:**
- только Unicode (как в образце) — сложные формулы нечитаемы;
- MathJax — больше возможностей, но тяжелее (не измеряли);
- картинки формул — не редактируются, не переводятся, много весят.

**Пересмотреть:** уточнение «дроби в вычислениях — всегда `\frac`» — в разделе «Ждут решения».

### #26 · 2026-10-03 · Проверка ответа — по значению, точно, своим парсером
**Решение:**
- Код проверки — `src/lib/math/` (`rational`, `normalize`, `parse`, `value`, `interval`, `compare`, `format`).
- Ответ сравнивается по значению: `3,5` = `3.5` = `7/2` = `3½`; `−2,5` = `−5/2` = `−2½`; `√169` = `13`.
- Дроби — точные рациональные числа на `BigInt`, без ошибок вида `0.1 + 0.2 = 0.30000000000000004`.
- Свой парсер выражений, без `eval` и `new Function`.
- Ввод ученика и эталон нормализуются одинаково.
- Неразборчивый ввод — подсказка формата, а не «неверно».
- Тот же код используют калькулятор, графики и сцены.

**Почему:**
- В вариантах ЕНТ одно число бывает записано по-разному: в демо № 37 верны −2,5, −2½ и −5/2. Сравнение строк засчитало бы верный ответ как ошибку.
- `float` даёт неточности — в образце ревью нашло неточное округление больших чисел.
- `eval` небезопасен.

**Альтернативы:** сравнение строк (как в образце для информатики) — недостаточно для математики; сторонняя библиотека компьютерной алгебры — тяжелее и сложнее проверить.
**Пересмотреть:** когда понадобится эквивалентность выражений с переменной (`algebra.ts`, в плане).

### #29 · 2026-10-03 · Ветки → превью → PR → `main`
**Решение:**

- Ветки-эксперименты в `main` не сливать.

**Почему:**

- Тестерам — только публичный адрес: служебные адреса превью требуют входа в Vercel. В образце это было замечание № 1: «сайт не открывается с других устройств».

**Отличие от образца:** в Informatica рабочая ветка и была продакшеном — каждый push сразу выкладывался.
**Пересмотреть:** если CI начнёт мешать или в него понадобятся e2e.

### #30 · 2026-10-03 · Ключ OpenAI, лимиты и деньги
**Решение:**
- `OPENAI_API_KEY` хранится только в `.env.local` и в переменных Vercel.
  - Не `NEXT_PUBLIC_`, не в чат, не в документы, не в облако Codex.
  - Тесты идут без ключа: ИИ в них подменяется.
  - Если живая проверка ИИ в облаке всё же нужна — Network secret для `api.openai.com` и отдельный ключ с жёстким лимитом.
- Отдельный проект OpenAI «matematika» с **жёстким** месячным лимитом (совет: $10–20 на старте) и оповещением на 50 %.
- Каждый маршрут ИИ: лимит по IP, обрезка входа, лог `[ai] route=… in=… out=…`. Лимиты образца за 10 минут: tutor — 40 запросов, check-solution — 15, lesson-feedback — 20.
- У ученика — 60 обращений к ИИ в день. Если запрос не удался, обращение возвращается. Это счётчик в localStorage (`AI_DAILY_LIMIT` в сторе): он для удобства, бюджет **не защищает** — его обходят очисткой данных браузера. Бюджет защищают жёсткий лимит в кабинете OpenAI и лимиты маршрутов.

**Почему:** в образце тестовый ключ однажды передали в чате, и для продакшена пришлось выпускать новый. Жёсткий лимит не даёт счёту вырасти. При ответе `429` приложение продолжает работать без ИИ.
**Пересмотреть:** на этапе 8 (часть 8.3) — лимиты на аккаунт вместо IP (лимит в памяти процесса слабый на serverless).

### #34 · 2026-10-03 · Картинки-«крючки» для ситуаций — по умолчанию нет
**Откуда:** план образца (PLAN 2.6): картинки-«крючки» к ситуациям генерировать один раз через OpenAI Images и хранить лёгкими `webp`. На 2026-10-03 в образце их нет.
**Решение:**
- По умолчанию иллюстрации — только React/SVG (`AGENTS.md`, раздел 5; `docs/DESIGN.md`, 11). Codex сам картинки не генерирует и не предлагает в каждом уроке.
- Если владелец сам захочет картинку-«крючок» к ситуации (`story`), это можно — только с его «ок» на конкретный урок и на таких условиях:
  - генерирует офлайн-скрипт с ключом владельца (как `review:kk`), не приложение и не на запрос ученика;
  - файл `webp` ≤ 50 КБ в `public/media/`, коммитится;
  - внутри картинки нет текста и чисел: подписи и числа — SVG поверх или текст рядом, чтобы были ru и kk и числа считал код;
  - `alt` на ru и kk;
  - картинка читается в обеих темах (без белого фона-«пятна» в тёмной теме — проверить на скриншоте);
  - стоимость генерации и модель — строка в CHANGELOG.

**Почему:** SVG дешевле, весит мало, работает в тёмной теме, переводится и масштабируется; числа на нём считает код. Но «живая» картинка может сделать ситуацию теплее — решать владельцу по одному-двум пробам.
**Альтернативы:** картинки всюду — дорого и тяжело, нарушает тёмную тему; полный запрет — владелец не сможет попробовать.
**Пересмотреть:** после урока-образца (этап 3), если владелец захочет попробовать «крючок» на одной ситуации.
