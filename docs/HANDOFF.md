## Как работаем (пользователь это просил)
- **Распределение моделей** (`CLAUDE.md`):
  - главная модель — ТЗ, архитектура, промпты, интеграция, финальная проверка;
  - `sonnet` — работа по ТЗ, параллельно, у каждого исполнителя свои файлы;
  - `haiku` — механика;
  - после исполнителей — независимый ревьюер, ревьюеры каждый раз находили реальные баги.
- **Каждый этап:** ТЗ → исполнители → тесты и скриншоты → выкладка → пользователь смотрит → правки. Этап закрыт, только когда пользователь его принял.
- **Документация обязательна:** `CHANGELOG`, `ROADMAP`, `DECISIONS`, `ARCHITECTURE`, `PLAN`. Изменения промптов ИИ — отдельной строкой и с проверкой живыми запросами на ru и kk.
- **Казахский:** носителя нет, после новых текстов запускается `npm run review:kk`. Обоснованные правки применяем, а термины НЦТ (`docs/ENT.md`, раздел 4) важнее советов модели.
- **Перед выкладкой:** `npm run typecheck && npm run lint && npm test && npm run build` и `npm run e2e`. Пока работают исполнители, сохранённую версию можно проверить в отдельной рабочей копии, чтобы не выложить незаконченное:
  ```bash
  git worktree add <scratch>/wt HEAD
  cp -al node_modules <scratch>/wt/node_modules
  ```
  Ссылка на `node_modules` (symlink) не подходит — Turbopack её не принимает.
- **Облако Claude Code:**
  - сервер с ИИ запускать с `NODE_USE_ENV_PROXY=1`;
  - Chromium — `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`;
  - останавливать серверы по PID, не через `pkill -f next`: PID — `ps -eo pid,cmd | grep next-server` (утилиты `ss` в среде нет). Перед e2e убедись, что на 3100 не висит старый `next-server` от прошлой сборки: Playwright переиспользует его (`reuseExistingServer`), и все тесты «зависают на загрузке» — страница просит чанки новой сборки у старого сервера.
  - не запускать `pkill -f "<строка>"`, если эта строка есть в самой команде: убивает собственную оболочку (код 144).
- Пользователь пишет по-русски коротко и неформально. Отвечать по-русски, без жаргона, по делу.

## Известные ограничения
- Прогресс хранится только на устройстве (аккаунты — этап 17). Серверные лимиты ИИ — по устройству, IP и сайту; без Upstash — в памяти каждой копии сервера.
- Звуки и вибрация не проверены на реальном телефоне.
- Казахские тексты вычитаны только моделью.
- Видео к новым урокам пока нет: старое видео не понравилось, ждём выбора стиля.
- Напоминания работают без сервера: уведомление приходит, пока открыто приложение (на Android с установленным приложением — и в фоне). Настоящие push — этап 5.
- Практикум: Pyodide и sql.js скачиваются с CDN при первом запуске (несколько МБ); без сети Python и SQL не работают. HTML/CSS, JavaScript и Excel — локально.
- Голосовой вопрос в Safari (iPhone) записывает `audio/mp4` — проверено только тестами, не на телефоне. Озвучка на казахском — только если в системе есть казахский голос.
- Изменённые промпты ИИ (в том числе строка про кризис из этапа 10) и новые потолки токенов не проверены живыми запросами — в облачной среде нет ключа.
- После выкладки v0.9 вкладки со старой версией сайта покажут «OK» в конце ответа ИИ, пока страницу не обновят.
- Тестовый ключ OpenAI передавался в чате. Для продакшена нужен новый ключ и лимит расходов в кабинете OpenAI.
