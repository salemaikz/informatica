# Журнал решений

> Формат: что решили · почему · альтернативы · когда пересмотреть. Новые решения — в конец.

### #1 · 2026-10-02 · Веб-приложение (PWA), сторы — позже
**Решение:** делаем адаптивное веб-приложение, которое открывается с сайта и устанавливается на телефон как PWA. В сторы — позже через Capacitor (тот же код в нативной оболочке).
**Почему:** один код для всех устройств, мгновенные обновления без модерации сторов, дешевле.
**Альтернативы:** React Native / Flutter — дороже поддерживать две кодовые базы (сайт + приложение).
**Пересмотреть:** если понадобятся тяжёлые нативные функции (офлайн-видео, сложные уведомления).

### #2 · 2026-10-02 · Next.js 16 + серверные маршруты для ИИ
**Решение:** Next.js (App Router). Ключ OpenAI живёт только в серверных маршрутах `/api/ai/*`.
**Почему:** ключ нельзя отдавать в браузер; Next даёт фронт и бэкенд в одном проекте, бесплатный хостинг на Vercel.
**Для сторов:** клиент собирается статически, а `/api/ai/*` остаётся на сервере — клиент ходит к нему по абсолютному URL.

### #3 · 2026-10-02 · Прогресс хранится на устройстве (MVP)
**Решение:** весь прогресс — в localStorage через Zustand. Сервер ничего не хранит.
**Почему:** запуск без регистрации, без базы данных и без затрат; ученик сразу учится.
**Минусы:** прогресс не переносится между устройствами, учитель его не видит.
**Пересмотреть:** при запуске пилота — бэкенд (предложение: Supabase — авторизация + Postgres, бесплатный тариф). Интерфейс действий стора менять не нужно — только хранилище.

### #4 · 2026-10-02 · Видео = Remotion-компоненты, проигрываемые в браузере
**Решение:** ролики — React-композиции Remotion, их проигрывает `@remotion/player` прямо на странице. MP4 не рендерим.
**Почему:** ноль затрат на рендер, хранение и трафик видео; переключение ru/kk и субтитров одним пропсом; правка ролика = правка кода; генерировать такие ролики дёшево по токенам.
**Альтернативы:** рендер MP4 (Remotion CLI / Lambda) — можно включить позже для соцсетей; ИИ-видео (Sora и т.п.) — дорого и плохо для точных формул.
**Лицензия Remotion:** бесплатно для частных лиц и компаний до 3 сотрудников; для компании больше — нужна платная лицензия (проверить условия на remotion.dev перед коммерческим запуском).

### #5 · 2026-10-02 · Озвучка — OpenAI TTS
**Решение:** `gpt-4o-mini-tts`, голос `coral`, mp3 генерируется один раз скриптом и коммитится.
**Почему:** копейки за минуту, оба языка. Казахскую озвучку проверили обратной расшифровкой (`gpt-4o-transcribe`): распознаётся практически дословно.
**Пересмотреть:** если носитель казахского сочтёт произношение неестественным — переозвучить живым голосом (файлы просто заменяются, длительности пересчитает скрипт).

### #6 · 2026-10-02 · Модели ИИ
**Решение:** `gpt-5.4-mini` — чат, подсказки, разбор ошибок, проверка фото; `gpt-5.4-nano` — отзыв после урока и память наставника. Для чата `reasoning_effort: none` (быстро и дёшево), для фото — `low`.
**Почему:** проверили на реальных запросах — качество на русском и казахском хорошее, ответ за 2–3 с, расход сотни токенов на запрос.
**Как менять:** env-переменные `OPENAI_MODEL_*`, код трогать не нужно.

### #7 · 2026-10-02 · Тренировочные задания генерирует код, а не ИИ
**Решение:** процедурные генераторы на каждый навык (`lib/generators.ts`).
**Почему:** бесконечная практика бесплатно, мгновенно, без ошибок в ответах (ответ вычисляется), детерминированно (тестируется).
**ИИ остаётся** для того, что код не умеет: объяснить ошибку, ответить на вопрос, проверить рукописное решение.

### #8 · 2026-10-02 · Сначала статическое объяснение, ИИ — по кнопке
**Решение:** у каждого задания есть объяснение от автора; ИИ вызывается только по запросу («Подсказка», «Объясни, ИИ»).
**Почему:** экономия и надёжность: большинству учеников хватает статического объяснения.

### #9 · 2026-10-02 · Подсказка ИИ не выдаёт ответ
**Решение:** в режиме подсказки модель получает верный ответ «для себя» с запретом его сообщать.
**Почему:** педагогика — ученик должен прийти к ответу сам. После ответа — полный разбор.

### #10 · 2026-10-02 · Модель освоения — экспоненциальное сглаживание
**Решение:** `mastery` 0..1 на навык, обновление после каждого ответа (`lib/mastery.ts`).
**Почему:** просто, понятно, хорошо работает на малых данных.
**Пересмотреть:** при накоплении данных — BKT / IRT, интервальные повторения с учётом забывания.

### #11 · 2026-10-02 · Двуязычие на уровне типов
**Решение:** строки интерфейса — словарь `{ ключ: { ru, kk } }`, контент — тип `L = { ru, kk }`. TypeScript и тесты не дают пропустить перевод.
**Почему:** казахский — не «второй сорт», и перевод нельзя забыть.

### #12 · 2026-10-02 · ИИ не угадывает пол ученика
**Решение:** в промптах запрещены глаголы прошедшего времени с родом при обращении к ученику («ты сделал/сделала»).
**Почему:** модель угадывала пол по имени (и даже без имени) — ошибка неприятна подростку.

### #13 · 2026-10-02 · Дизайн
**Решение:** шрифт Nunito (поддерживает казахские буквы ә ғ қ ң ө ұ ү һ і), JetBrains Mono для чисел, маскот «Бит» в SVG, строгая семантика цветов (см. CLAUDE.md), «объёмные» кнопки как в Duolingo, светлая и тёмная темы.

### #14 · 2026-10-02 · Распределение задач между моделями по сложности
**Решение:** главная (мощная) модель планирует, пишет ТЗ, принимает решения и проверяет; механику (поиск, прогон тестов, скриншоты) делает `haiku`, работу по чёткому ТЗ (компоненты, тесты, переводы) — `sonnet`. В приложении — та же лестница: код → `gpt-5.4-nano` → `gpt-5.4-mini` → `gpt-5.5` только для офлайн-задач разработчика.
**Почему:** экономия токенов без потери качества — дорогая модель тратится только там, где без неё нельзя.
**Как применяем:** мини-игры спроектированы панелью (3 «дизайнера» + 2 «судьи» на sonnet, синтез — главная модель) и реализованы параллельно исполнителями на sonnet с независимым ревью каждой игры.

### #15 · 2026-10-02 · Мини-игры: 4 разных механики, без ИИ, как «движки»
**Решение:** первые игры — «Бит-спринт» (поток вопросов на время), «Битовый тумблер» (собрать число переключателями), «Сортировщик» (карточки по корзинам по правилу), «Найди ошибку» (найти и исправить строку в готовом решении).
**Почему:** разные типы нагрузки (беглость, понимание разрядов, классификация, разбор ловушек ЕНТ) и разный ввод; три из четырёх — универсальные движки: новые темы подключаются генераторами, без новых игр. Ноль затрат на ИИ.
**Как устроено:** игра — один компонент по контракту `src/games/types.ts`; оболочка `GameShell` показывает правила и итоги; результат игры обновляет XP (с потолком), рекорд и освоение навыков (один раз за игру по доле верных действий).
**Бэклог идей** — в ROADMAP.

### #16 · 2026-10-02 · Курс строится по спецификации ЕНТ-2026
**Решение:**
- Курс перестраивается в 9 разделов по 13 темам спецификации НЦТ (`docs/ENT.md`).

**Пересмотреть:** при выходе новой спецификации (осенью) и если с 2027 года сменится формат.

### #17 · 2026-10-02 · Калькулятор и черновик — как на экзамене
**Решение:**
- На платформе всегда есть калькулятор и тетрадь-черновик.
- В режиме «как на ЕНТ» доступен только обычный калькулятор, как встроенный в интерфейс экзамена.
- При обучении есть «умный» калькулятор систем счисления, который показывает шаги решения.
**Почему:** на ЕНТ есть встроенный калькулятор и лист А4 (Правила, п. 80). Тренировать длинную арифметику бессмысленно, тренировать нужно процедуры решения.

### #18 · 2026-10-02 · Порядок работ v0.3–v1.0 и выбор игр
**Решение:**
- Пользователь выбрал **все 10** новых мини-игр.
- Порядок этапов пользователь поручил выстроить «по важности и правильности»:
  1. Фундамент: банк заданий, анимации, калькулятор и черновик, темп игр.
  2. Новая методика на уроке 1, затем контент-поток.
  3. Навигация: карта, режимы, «Теория», повторение, мини-ЕНТ.
  4. Игры на банке заданий.
  5. Вход через Google и облако.
  6. Конспекты 2.0.
  7. ИИ-помощник 2.0.
  8. Python и IDE.
  9. Весь курс и пробный ЕНТ.
**Почему:**
- Сначала то, на чём строится остальное.
- Методику проверяем на одном уроке, прежде чем тиражировать.
- Игры делаем, когда в курсе несколько тем.
- Облако — до чатов и конспектов, чтобы фото и переписки не пришлось переносить.
**Пересмотреть:** если пользователь решит поменять приоритеты.

**Решение:**

### #20 · 2026-10-02 · ИИ на любом шаге урока, кроме режима «как на ЕНТ»
**Решение:**
- Режим ИИ `ask`: вопрос по текущему шагу (теория или задание).
- К нерешённому заданию ответ не называется — ИИ даёт метод на другом примере.
- В пробном ЕНТ и режиме «как на ЕНТ» ИИ выключен.
**Почему:** пользователь просил «возможность спросить у нейронки в уроках и тестах». Ответ на нерешённое задание убил бы обучение, а на экзамене подсказок нет.

### #21 · 2026-10-02 · Весь курс ЕНТ сразу, конвейер «автор + ревьюер, который пересчитывает ответы кодом»
**Решение:** написать 38 уроков (все 13 тем спецификации) за один этап, а не «по уроку в неделю». На каждый урок — автор (`sonnet`) и ревьюер (`opus`), который заново считает каждый ответ кодом (`python3`, `sqlite3`) и правит методику и казахский. У каждого урока — банк заданий и задания ЕНТ. Самопроверка — `scripts/check-content.ts`, общие тесты — `tests/content*.test.ts`.
**Почему:** пользователь не мог пройти дальние разделы («первые я знаю»), исследование называет объём главной дырой продукта. Ошибка в ответе на подготовке к экзамену — самая дорогая, поэтому проверка кодом обязательна.
**Пересмотреть:** когда появится носитель-редактор казахского и пользователь пройдёт уроки — правки по отзывам.

### #22 · 2026-10-02 · Свободный режим: все готовые уроки открыты
**Решение:** замков по порядку нет; рекомендуемый урок — первый непройденный, но можно начать любой. «Сдать экстерном» — тест по разделу (≥ 80%, минимум 6 заданий) засчитывает уроки.
**Почему:** просьба пользователя; минимум заданий — чтобы раздел нельзя было засчитать 1–2 угаданными ответами.

### #23 · 2026-10-02 · Честные XP и интервальное повторение
**Решение:** повтор урока: ×0,5 во второй раз, ×0,3 дальше; плановое повторение по расписанию 1-3-7-14-30-60 дней — ×0,75; бонус «без ошибок» — только за первый раз; «Проверить себя» — половина бонуса.
**Почему:** просьба пользователя («повтор даёт меньше опыта»), исследование («XP за понимание, а не за фарм»). Повторять «остывшее» выгодно, фармить один урок — нет.

### #24 · 2026-10-02 · Заморозка серии вместо наказания за пропуск
**Решение:** каждые 7 дней подряд — заморозка (максимум 2), она закрывает пропущенный день. Не продаётся.
**Почему:** исследование: отток резко падает после 7–10 дней серии, а серия, которая сгорает от одного пропуска, отталкивает. Продажа заморозок — запрещённый приём (`RESEARCH.md`, раздел 10).

### #25 · 2026-10-02 · Экономия ИИ: сначала бесплатное, общий кэш неперсональных ответов
**Решение:**
- у каждого задания — подсказка автора и «почему неверно» для вариантов; ИИ — только следующей ступенькой по кнопке;
- подсказки, разборы ошибок и быстрые вопросы к шагу строятся **без персональных данных** (только язык, стиль, задание) и кэшируются: на сервере — память + `unstable_cache` (Next 16 рекомендует `use cache`, но он требует включить `cacheComponents` для всего приложения — не делаем ради одной функции), на устройстве — 150 ответов в localStorage; попадание в кэш не тратит дневной лимит;
- подсказка проверяется кодом на утечку ответа; запросы с чужих сайтов отклоняются по `Origin`.
**Почему:** просьба пользователя: «многие задачи одни и те же — не создавать новые подсказки». Персонализация в подсказке почти ничего не даёт, а общий ответ на одно задание переиспользуется сотнями учеников.
**Пересмотреть:** на этапе 5 (аккаунты) — общий кэш в базе (переживает деплои), квоты на аккаунт.

### #26 · 2026-10-02 · Пробный ЕНТ — отдельная спокойная оболочка, разбор бесплатный
**Решение:** мини (15), полный (40/50) и тест по теме (10); без маскота, XP и ИИ во время теста, только обычный калькулятор и черновик; вариант детерминирован seed (вариант по ссылке); попытка сохраняется в IndexedDB (бумага + ответы), итог — в сторе. Разбор каждого задания — из контента (бесплатно), «Разбор от Бита» — один запрос дешёвой модели через существующий маршрут отзыва (новых промптов нет). Пробник не даёт XP, но обновляет освоение навыков и засчитывает день серии (только если есть ответы).
**Почему:** просьба пользователя (тест ЕНТ с фидбеком и статистикой, экономно); исследование: «пробник → слабые темы → практика» — главный цикл подготовки.

### #27 · 2026-10-02 · Конспекты 2.0 без бэкенда
**Решение:** папки и записи (markdown) — в сторе (localStorage), картинки и рисунки — в IndexedDB (ссылка `note-img:`); маркер `==текст==` / `=={g}текст==` своим remark-плагином; Markdown сам грузит только `note-img:`, внешние картинки показываются ссылкой (защита от трекинга через ответы ИИ).
**Почему:** просьба пользователя (папки, поиск, маркер, сохранение из черновика); облако — этап 5.

### #28 · 2026-10-02 · Напоминания о серии без сервера
**Решение:** баннер в приложении, уведомления через сервис-воркер (пока приложение открыто; `periodicSync` на Android с установленным приложением) и файл календаря `.ics` с ежедневным напоминанием. Настройки зеркалятся в IndexedDB для сервис-воркера. Web-push с сервера — на этапе 5.
**Почему:** настоящий push требует хранить подписки на сервере (а сервера с базой пока нет); календарь надёжно работает на любом телефоне, включая iPhone.

### #29 · 2026-10-02 · Карта курса: «Путь» + «Карта ЕНТ» вместо трёх эскизов
**Решение:** не делать три эскиза на выбор, а сразу сделать два вида: иллюстрированный путь (местности разделов, извилистая дорога, маскот) и плиточную карту тем ЕНТ (размер — вес темы, цвет — освоение).
**Почему:** пользователь попросил сразу удобную навигацию; это сочетание вариантов «а» и «в» из плана. Исследование предостерегало рисовать «путешествие», пока узлы пустые, — теперь курс заполнен. «Метро» не делали.

### #30 · 2026-10-02 · Универсальные игры и «урок игрой»
**Решение:** первые три игры на банке заданий — «Башня» (question), «Верю — не верю» (statement), «Мемо-пары» (pair). Без «жизней» и сердечек, таймер не по умолчанию, новые ученики начинают в темпе «Спокойно». Урок засчитывается игрой при ≥ 70% и не меньше 5 ответов.
**Почему:** просьба пользователя «пройти урок чисто игрой»; запреты из исследования (раздел 10).

### #31 · 2026-10-02 · Экономика: сердечки в уроках, чипы за опыт, ИИ сверх бесплатного — за чипы
**Решение:**
- **Сердечки** (5 у бесплатного тарифа, 10 у «Лайта», безлимит у «Безлимита») тратятся только в уроках — ошибка с первой попытки. Каждый день — полный запас; потерянное сердечко возвращается само через 4 ч (у «Лайта» — 2 ч). ### #54 · 2026-10-04 · Потолок расходов ИИ на сервере: устройство, IP, сайт
**Решение (этап 10, реализует #48):** каждый маршрут `app/api/ai/*` проходит страж `server/ai-guard.ts`:
- **«Запрос с нашего сайта»:** в production без заголовка `Origin` — отказ 403; `Sec-Fetch-Site`, если есть, — только `same-origin`. В разработке запрос без `Origin` проходит (curl, тесты).
- **Устройство** — cookie `inf_ai` = случайный id + подпись HMAC-SHA256 (`HttpOnly`, `SameSite=Lax`, `Path=/api`, 400 дней, `Secure` в production). Секрет — `AI_DEVICE_SECRET`, иначе производный от ключа OpenAI. IP учитывается по первому адресу `x-forwarded-for` (на Vercel его ставит платформа), IPv6 — по сети /64, в хранилище — только хеш.

- Списание — до вызова модели. Возврат — только если модель запрос точно не получила: ошибка до вызова, ответ из кэша, кризисный ответ, отказ OpenAI с HTTP-статусом. Обрыв соединения клиентом, таймаут и сетевой сбой обращение не возвращают — иначе скрипт вызывал бы модель бесплатно. Таймаут вызова OpenAI — на 5 с короче лимита функции.

### #55 · 2026-10-04 · Оборванный ответ ИИ не считается готовым
**Решение:** поток ответа наставника — простой текст со служебным маркером в конце (`lib/ai-stream.ts`): `\u0000OK` — ответ полный, `\u0000CUT` — обрезан по длине, `\u0000ERR` — сбой во время потока; ответ без `OK` (тихий обрыв, прокси) — тоже оборванный. - **Цены входа:** урок 1 (большой урок, `hearts: 2`, — 2; таких уроков пока нет), «Проверить себя» 1, пробный ЕНТ любого вида 1, контрольная 2, **экстерн 2** (зачитывает весь раздел — как контрольная).
- **Продолжение урока** (#41): вернулся не позже 20 минут после последнего действия — вход уже оплачен; позже — снова цена входа. «Начать заново» стоит всегда (иначе бесплатный перезапуск в пределах 20 минут).
- **Цены сердечек за чипы:** 1 — 60, 3 — 150 (по 50), полный запас — по 45 за каждое недостающее, продаётся, когда не хватает хотя бы 4 (полный запас бесплатного — 225). Урок приносит ~45–65 чипов (7–8 заданий, бонусы), поэтому урок окупает чуть меньше одного следующего входа — чипы не превращаются в бесконечный запас, а повод для «Безлимита» остаётся. Сердечко за чипы (≈150 ₸ по цене набора чипов) дороже суточного безлимита сердечек (149 ₸).
- **Возврат за тренировку строже:** от 6 ответов (было 3) с точностью от 70% (было 60%), до 3 раз в день (было 5). Бесплатный запас в день у бесплатного тарифа: ~4 сердечка восстановлением (раз в 6 ч) + до 3 тренировками.
**Почему:** при старых ценах (20 чипов за сердечко) урок окупал три следующих входа — сердечки теряли смысл. Списание при первом ответе защищает от случайного входа и не мешает читать теорию (#40: теория бесплатна).
**Альтернативы:** списание при открытии урока (теряется сердечко при случайном входе, двойное списание при перезагрузке), фиксированная цена полного запаса (у «Лайта» с запасом 10 — слишком дёшево, а при 1–2 недостающих — переплата).

### #80 · 2026-10-05 · Освоение тает без практики: база 0,5, полураспад 30 дней (этап 14, #45)
**Решение:** часть оценки навыка выше 0,5 тает вдвое за 30 дней с последнего ответа: `0,5 + (m − 0,5) · 2^(−дни/30)`; ниже 0,5 оценка не тает. В хранилище лежит оценка «на момент последнего ответа»; карта, прогресс, прогноз, тренировка, игры, отчёт родителю и ИИ-наставник читают затухшую (`decaySkills`); новый ответ сдвигает уже затухшую оценку, поэтому после перерыва навык быстро «вспоминается». Счётчики самостоятельных ответов и дней (#67) не тают. Игры в темпе «Спокойно» сдвигают освоение с весом 0,5.
**Как это выглядит:** освоенный навык (1,0) без практики через неделю — 0,9 («освоено»), через 30 дней — 0,75 («в процессе»), через 60 — 0,63; один верный самостоятельный ответ возвращает «освоено». Прогноз балла после месяца перерыва снижается умеренно, а не вдвое.
**Почему не «чистые» 30 дней полураспада всей оценки:** 0,95 падало бы ниже порога «освоено» уже через 7 дней — значок мигал бы, а прогноз обваливался вдвое за месяц. Владелец поручил решить (#45).
**Альтернативы:** период полураспада, растущий с числом повторений (как в карточных системах, — сложнее объяснять); затухание только значка без влияния на прогноз.

### #81 · 2026-10-05 · Курс 3.0: «Практика» после группы, «Повторение» в конце раздела, мини-тест (этап 14, #46)

### #82 · 2026-10-05 · Микроуроки: сложный навык — цепочкой коротких уроков (этап 14, #46)
**Решение:** четыре цепочки по три микроурока: ветвления (if → if–else → elif, перед `py-2-if`), range (после `py-3-loops`), срезы строк (после `py-4-strings`), ссылки в таблицах (относительная → абсолютная → смешанная, перед `data-2-refs`). Микроурок (`micro: true`) — 9–12 шагов, 4–6 заданий (≥ 1 в формате ЕНТ), 3–5 минут; навык — общий с родительским уроком, поэтому свой банк и задания ЕНТ не нужны, а освоение, тренировка и прогноз не дробятся. Родительский урок остаётся на карте как «собираем вместе» (ловушки ЕНТ и задания уровня C); у `py-2-if` — новое название и вступление.

### #87 · 2026-10-05 · Практика ЕНТ — это «чтение кода»: вид задания, квота в пробнике, «босс» в уроках (этап 15)
**Решение:** у задания ЕНТ — вид «чтения» (`read`): `output` (что выведет / вернёт / покажет), `bug` (где ошибка), `fix` (что поменять), `fill` (что вставить вместо пропуска), `purpose` (зачем строка, что изменится без неё), `schema` (ключи и связи таблиц БД). Пробный ЕНТ (полный, мини, по теме) в практических темах берёт долю заданий только «на чтение»: Python (t06) — все, алгоритмы (t07), SQL (t10) и веб (t13) — 2/3, БД (t09) и таблицы (t12) — половина; среди равных по уровню — вид, который встречался реже. В банке было ≈ 690 «что выведет» и лишь ≈ 30 «ошибка / правка / пропуск». Практикум (писать код) остаётся — для понимания, но экзамен проверяет чтение.
**Альтернативы:** только новые задания без квоты (в пробник они попадали бы случайно и редко); отдельный раздел «код-ревью» вне пробника (не тренирует формат экзамена); разметить вручную все 2 600 заданий (дорого — вывод по тексту плюс явное поле у новых).
