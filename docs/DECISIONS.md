# Журнал решений

> Формат: что решили · почему · альтернативы · когда пересмотреть. Новые решения — в конец.

### Видео-лаборатория · 2026-10-02
**Решение:** четыре разные короткие истории одного математического примера, действия синхронизированы с отдельными фразами.
**Почему:** владелец счёл смену фоновых стилей сухой и слишком похожей. Сравниваем способы объяснения: квест, диалог, бытовое взвешивание и игру.
**Реализация:** SVG/React-сцены Remotion, локальная озвучка macOS Milena, обратная расшифровка Whisper base; платные API не используются. Пять тактов на сюжет, длительности из аудио.
**Пересмотреть:** после выбора подачи — полный сценарий, финальный голос и казахская версия.

### #1 · 2026-10-02 · Веб-приложение (PWA), сторы — позже
**Решение:** делаем адаптивное веб-приложение, которое открывается с сайта и устанавливается на телефон как PWA. В сторы — позже через Capacitor (тот же код в нативной оболочке).
**Почему:** один код для всех устройств, мгновенные обновления без модерации сторов, дешевле.
**Альтернативы:** React Native / Flutter — дороже поддерживать две кодовые базы (сайт + приложение).
**Пересмотреть:** если понадобятся тяжёлые нативные функции (офлайн-видео, сложные уведомления).

### #2 · 2026-10-02 · Next.js 16 + серверные маршруты для ИИ
**Решение:** Next.js (App Router). Ключ OpenAI живёт только в серверных маршрутах `/api/ai/*`.
**Почему:** ключ нельзя отдавать в браузер; Next даёт фронт и бэкенд в одном проекте, бесплатный хостинг на Vercel.
**Для сторов:** клиент собирается статически, а `/api/ai/*` остаётся на сервере — клиент ходит к нему по абсолютному URL.

### #3 · 2026-10-02 · Прогресс хранится на устройстве (MVP)
**Решение:** весь прогресс — в localStorage через Zustand. Сервер ничего не хранит.
**Почему:** запуск без регистрации, без базы данных и без затрат; ученик сразу учится.
**Минусы:** прогресс не переносится между устройствами, учитель его не видит.
**Пересмотреть:** при запуске пилота — бэкенд (предложение: Supabase — авторизация + Postgres, бесплатный тариф). Интерфейс действий стора менять не нужно — только хранилище.

### #4 · 2026-10-02 · Видео = Remotion-компоненты, проигрываемые в браузере
**Решение:** ролики — React-композиции Remotion, их проигрывает `@remotion/player` прямо на странице. MP4 не рендерим.
**Почему:** ноль затрат на рендер, хранение и трафик видео; переключение ru/kk и субтитров одним пропсом; правка ролика = правка кода; генерировать такие ролики дёшево по токенам.
**Альтернативы:** рендер MP4 (Remotion CLI / Lambda) — можно включить позже для соцсетей; ИИ-видео (Sora и т.п.) — дорого и плохо для точных формул.
**Лицензия Remotion:** бесплатно для частных лиц и компаний до 3 сотрудников; для компании больше — нужна платная лицензия (проверить условия на remotion.dev перед коммерческим запуском).

### #5 · 2026-10-02 · Озвучка — OpenAI TTS
**Решение:** `gpt-4o-mini-tts`, голос `coral`, mp3 генерируется один раз скриптом и коммитится.
**Почему:** копейки за минуту, оба языка. Казахскую озвучку проверили обратной расшифровкой (`gpt-4o-transcribe`): распознаётся практически дословно.
**Пересмотреть:** если носитель казахского сочтёт произношение неестественным — переозвучить живым голосом (файлы просто заменяются, длительности пересчитает скрипт).

### #6 · 2026-10-02 · Модели ИИ
**Решение:** `gpt-5.4-mini` — чат, подсказки, разбор ошибок, проверка фото; `gpt-5.4-nano` — отзыв после урока и память наставника. Для чата `reasoning_effort: none` (быстро и дёшево), для фото — `low`.
**Почему:** проверили на реальных запросах — качество на русском и казахском хорошее, ответ за 2–3 с, расход сотни токенов на запрос.
**Как менять:** env-переменные `OPENAI_MODEL_*`, код трогать не нужно.

### #7 · 2026-10-02 · Тренировочные задания генерирует код, а не ИИ
**Решение:** процедурные генераторы на каждый навык (`lib/generators.ts`).
**Почему:** бесконечная практика бесплатно, мгновенно, без ошибок в ответах (ответ вычисляется), детерминированно (тестируется).
**ИИ остаётся** для того, что код не умеет: объяснить ошибку, ответить на вопрос, проверить рукописное решение.

### #8 · 2026-10-02 · Сначала статическое объяснение, ИИ — по кнопке
**Решение:** у каждого задания есть объяснение от автора; ИИ вызывается только по запросу («Подсказка», «Объясни, ИИ»).
**Почему:** экономия и надёжность: большинству учеников хватает статического объяснения.

### #9 · 2026-10-02 · Подсказка ИИ не выдаёт ответ
**Решение:** в режиме подсказки модель получает верный ответ «для себя» с запретом его сообщать.
**Почему:** педагогика — ученик должен прийти к ответу сам. После ответа — полный разбор.

### #10 · 2026-10-02 · Модель освоения — экспоненциальное сглаживание
**Решение:** `mastery` 0..1 на навык, обновление после каждого ответа (`lib/mastery.ts`).
**Почему:** просто, понятно, хорошо работает на малых данных.
**Пересмотреть:** при накоплении данных — BKT / IRT, интервальные повторения с учётом забывания.

### #11 · 2026-10-02 · Двуязычие на уровне типов
**Решение:** строки интерфейса — словарь `{ ключ: { ru, kk } }`, контент — тип `L = { ru, kk }`. TypeScript и тесты не дают пропустить перевод.
**Почему:** казахский — не «второй сорт», и перевод нельзя забыть.

### #12 · 2026-10-02 · ИИ не угадывает пол ученика
**Решение:** в промптах запрещены глаголы прошедшего времени с родом при обращении к ученику («ты сделал/сделала»).
**Почему:** модель угадывала пол по имени (и даже без имени) — ошибка неприятна подростку.

### #13 · 2026-10-02 · Дизайн
**Решение:** шрифт Nunito (поддерживает казахские буквы ә ғ қ ң ө ұ ү һ і), JetBrains Mono для чисел, маскот «Бит» в SVG, строгая семантика цветов (см. CLAUDE.md), «объёмные» кнопки как в Duolingo, светлая и тёмная темы.
**Почему:** дружелюбно, но не по-детски; цвет сразу говорит, что произошло.

### #14 · 2026-10-02 · Распределение задач между моделями по сложности
**Решение:** главная (мощная) модель планирует, пишет ТЗ, принимает решения и проверяет; механику (поиск, прогон тестов, скриншоты) делает `haiku`, работу по чёткому ТЗ (компоненты, тесты, переводы) — `sonnet`. В приложении — та же лестница: код → `gpt-5.4-nano` → `gpt-5.4-mini` → `gpt-5.5` только для офлайн-задач разработчика.
**Почему:** экономия токенов без потери качества — дорогая модель тратится только там, где без неё нельзя.
**Как применяем:** мини-игры спроектированы панелью (3 «дизайнера» + 2 «судьи» на sonnet, синтез — главная модель) и реализованы параллельно исполнителями на sonnet с независимым ревью каждой игры.

### #15 · 2026-10-02 · Мини-игры: 4 разных механики, без ИИ, как «движки»
**Решение:** первые игры — «Бит-спринт» (поток вопросов на время), «Битовый тумблер» (собрать число переключателями), «Сортировщик» (карточки по корзинам по правилу), «Найди ошибку» (найти и исправить строку в готовом решении).
**Почему:** разные типы нагрузки (беглость, понимание разрядов, классификация, разбор ловушек ЕНТ) и разный ввод; три из четырёх — универсальные движки: новые темы подключаются генераторами, без новых игр. Ноль затрат на ИИ.
**Как устроено:** игра — один компонент по контракту `src/games/types.ts`; оболочка `GameShell` показывает правила и итоги; результат игры обновляет XP (с потолком), рекорд и освоение навыков (один раз за игру по доле верных действий).
**Бэклог идей** — в ROADMAP.

### #20 · 2026-10-02 · ИИ на любом шаге урока, кроме режима «как на ЕНТ»
**Решение:**
- Режим ИИ `ask`: вопрос по текущему шагу (теория или задание).
- К нерешённому заданию ответ не называется — ИИ даёт метод на другом примере.
- В пробном ЕНТ и режиме «как на ЕНТ» ИИ выключен.
**Почему:** пользователь просил «возможность спросить у нейронки в уроках и тестах». Ответ на нерешённое задание убил бы обучение, а на экзамене подсказок нет.

### #21 · 2026-10-02 · Предметы превращаются в двоичную запись
**Решение:** новые пробы показывают `101₂ → 5₁₀` на трёх фиксированных позициях 4/2/1. Сначала два состояния предмета, затем размеры вдвое больше справа налево, затем каждое действие по очереди. Позиция 0 остаётся видимой. В конце та же модель превращается в цифры и сумму.
**Почему:** владелец выбрал кухню, но объяснение с шестью позициями и числом 45 оставалось непонятным. Малый пример раскрывает разницу между цифрой 1 и весом её места. Фирменный Бит и цвета связывают видео с приложением. Из референсов Droider взят переход «знакомый предмет → модель → обозначения», без копирования оформления.
**Альтернатива:** менять только визуальную тему; это не решает проблему понимания.
**Пересмотреть:** после просмотра владельцем, прежде чем готовить полный урок и оба языка.

### #22 · 2026-10-02 · Мастерская: бит, перенос, разряды
**Решение:** по выбору владельца развиваем мастерскую Бита. До следующего ролика подготовлен методический разбор `docs/content/bit-workshop-research.md`: два состояния → независимые сочетания → двоичный счёт с переносом → веса → примеры 101₂ и 110₂ → вопрос зрителю. Число сочетаний и вес разряда объясняются отдельно. Формулы подписывают наблюдаемое действие.
**Голос:** владелец предпочитает голос исходного урока; для следующей пробы используем его TTS-пайплайн вместо macOS Milena.
**Почему:** текущая мастерская понравилась визуально, но роботизированный голос, необъяснённое удвоение и одна демонстрация мешают пониманию. Бит не должен выглядеть как физическая ёмкость для четырёх единиц.
**Пересмотреть:** после новой короткой пробы и проверки понимания примеров, перед полным уроком.

### #23 · 2026-10-02 · Две подачи на одной последовательности объяснения
**Решение:** сравниваем телефонный мини-сюжет и тактильный счётчик на одной последовательности из 11 тактов. Показываем реальные переносы количеств, отдельно — состояния бита и вес позиции. Пояснения внутри такта меняются по действию; итог задерживается. Без голоса по прямому разрешению владельца, с постоянными пояснениями в кадре.
**Почему:** нужно сравнить интерес и ясность двух способов подачи, сохранив одинаковые математические понятия и примеры. Новая озвучка исходным голосом требует ключа, которого в локальной копии нет; владелец выбрал продолжить без неё.
**Пересмотреть:** после просмотра двух проб; перед полноценным уроком вернуть предпочитаемый голос и проверить темп с аудио.

## 24. Следующие пробы объясняют через сюжет
Обратная связь: телефон и счётчик всё ещё напоминают схемы. Поэтому следующая пара — минидетектив с тремя вопросами и скетч в пекарне. Первая история раскрывает двоичный адрес через последовательное деление вариантов, вторая — веса через объединение и выбор коробок. Разные действия ведут к одним примерам 5 и 6. Голос пока не добавляется по явному выбору владельца.

## 25. Прямое объяснение на одном сквозном примере
Обратная связь: сюжеты добавляют нагрузку и мешают пониманию самого формата. Следующая пара сравнивает направление объяснения: 5₁₀ → 101₂ и 101₂ → 5₁₀. Каждый шаг связывает цифру, вес и количество; ноль сохраняет свою позицию. Основной пример один, второй коротко проверяет перенос правила. Семь тактов по 48,8 секунды, без персонажей и голоса. Полный урок и озвучка остаются после выбора подачи.


## 26. Готовая библиотека учебных ответов
Стандартные вопросы генерируются при авторстве контента и сохраняются в исходном двуязычном банке. Сервер получает идентификатор вопроса и возвращает подготовленный метод, пример или объяснение; имя, ответ и история чужого ученика в библиотеку не попадают. Для своего вопроса сохраняется личный диалог. Это устраняет повторный расход токенов и позволяет проверить правильность заранее. До попытки эталон скрыт; совпавший с ответом пример не показывается. Изменение контента версионирует библиотеку вместе с приложением.

## 27. Сердце за начало занятия и ограниченные чипы
Урок, тренировка, повторение, код, тест, ЕНТ и новый игровой раунд используют единый допуск за одно сердце. Повторный вызов того же допуска не списывает сердце дважды. Награды соответствуют запросу владельца; ускоритель влияет только на XP. Недельная история отделена от постоянных ключей выданных наград. Одинаковый набор теста получает одинаковый ключ награды независимо от порядка вопросов и названия варианта. Пустое или преимущественно пропущенное занятие не завершает урок; полностью пропущенный тест не приносит награду.

## 28. Кейс за уровень и косметический инвентарь
Каждый уровень после первого выдаёт один кейс. Внутри оформление аватара; купить кейс за чипы или деньги нельзя. До полной коллекции дубликатов нет; после её заполнения новые кейсы сохраняются. Оформление не влияет на ответы и учебные ограничения. Переход старого прогресса выдаёт исторические кейсы однократно.

## 29. Экономика MVP и платежи
В этой ветке нет платёжного сервера. Модель тарифа Lite имеет 6 сердец, пополнение всех сердец стоит 490 ₸, но покупка выключена и подписки нельзя бесплатно активировать в интерфейсе. До коммерческого запуска балансы и допуски должны проверяться сервером. Не создаём видимость реального платежа в localStorage.

## 30. Авторский пробник и покрытие программы
Структура вариантов следует спецификации НЦТ-2026: 40 заданий, один общий контекст, отдельные соответствия, распределение A/B/C и максимум 50 баллов. ## 31. Итог без модели и медиа до публикации
После урока бесплатный итог строится по фактической точности и ошибкам первой попытки. Автоматический модельный отзыв и обновление памяти удалены из этого сценария. Музыка включается по желанию и останавливается при выходе. Две новые видео-пробы и материалы Instagram подготовлены для просмотра владельцем; публикация и окончательная озвучка требуют отдельного выбора.

### 2026-10-07 · Сравнение новых визуалов и видеоподач
**Решение:** сравниваем три визуально разных объяснения одного Python-примера и три отдельных Reels с разными задачами: обучение, юмор, знакомство. Пробы изолированы в новой галерее с RU/KK и выключенной по умолчанию музыкой.
**Почему:** одинаковое содержание урока позволяет выбирать именно ясность подачи; разные цели Reels позволяют оценить контент для аудитории сервиса. Три направления оформления показаны сразу на уроке, кейсе и обложке.
**Альтернативы:** перекрасить предыдущие карточки или сразу заменить визуал курса. Отложены до выбора владельца; пока сохраняются все прежние материалы и действующая косметика.
**Пересмотреть:** после выбора — финальная озвучка с обратной расшифровкой, MP4, редактура и отдельное решение о публикации. Remotion-пакеты фиксируем одной версией 4.0.532 для совместимости Studio/Player/media.

**Дополнение:** просмотр `/video-lab` не ждёт гидратацию учебного профиля. Причина — галерея не изменяет прогресс и должна открываться даже при отказе хранилища. Учебные режимы сохраняют прежнее ожидание; данные не удаляем.
