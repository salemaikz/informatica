## W1-1. Новые сцены (`scenes`)

**Файлы:** `src/components/scenes/{TableScene,CodeScene,CircuitScene,FlowScene,CardsScene,PixelsScene,WebScene}.tsx`, `src/components/scenes/icons.ts`, `src/components/scenes/circuit.ts` и `src/components/scenes/highlight.ts` (чистая логика), `src/components/scenes/SceneView.tsx` (добавить ветки), `tests/scenes-new.test.ts`, `src/i18n/parts/scenes.ts`.

Типы сцен — `src/lib/types.ts` (`Scene`: `table`, `code`, `circuit`, `flow`, `cards`, `pixels`, `web`; комментарии к полям — там же). Валидация уже есть — `tests/validate.ts` (`validateScene`), её не меняй. Посмотри, как сделаны существующие сцены (`BinaryScene`, `LadderScene`, `primitives.tsx`): стабильные ключи элементов и анимация изменений через `motion` (`m` из `motion/react`), уважение «меньше анимаций» (`useReduceMotion`).

Требования ко всем сценам:
- Телефон 360 px — главное: ничего не вылезает за экран, мелкий текст ≥ 13 px. Если таблица/код шире — горизонтальная прокрутка внутри сцены, а не страницы.
- Светлая и тёмная тема — только токены (`bg-surface`, `text-muted`, `border-border`, `bg-primary-soft`, `text-success` …). Цвета по смыслу (CLAUDE.md): подсветка «текущее» — `primary`, «верно/1» — `success`, «ошибка/0» — нейтрально или `danger` только для ошибки.
- Подпись `caption` — под сценой, `text-sm text-muted`.
- Сцены одного вида подряд (подшаги разбора) не пересоздаются: SceneView уже рендерит по `scene.kind`; внутри — стабильные `key`, подсветка меняется плавно (≈200 мс).
- Тексты `Text` (`string | L`) переводи через `l()` из `useT()`.

По сценам:
1. **table** — таблица с закруглёнными углами; `columns` — шапка (жирная, `bg-surface-2`); `mono` — JetBrains Mono (`font-mono`); подсветка строк/столбцов/ячеек — `bg-primary-soft` + рамка `primary` у ячеек. `sheet: true` — как электронная таблица: слева столбец номеров строк 1…n, сверху буквы A, B, C… (серые, `text-muted`, `bg-surface-2`), ячейки с тонкой сеткой; `columns` в режиме sheet не используется (если заданы — первая строка данных). Значения «1»/«0» в mono-таблицах можно чуть окрашивать (`1` — `text-success`, `0` — `text-muted`) — только если все ячейки столбца из 0/1.
2. **code** — блок кода (`font-mono`, фон `bg-surface-2`, номера строк серым). Простая подсветка синтаксиса без библиотек (`lang`): python — ключевые слова (`def if elif else for while in range return print input and or not True False None break continue import from as with open`) `text-primary`, строки `text-success`, числа `text-warning-strong`, комментарии `text-muted`; sql — ключевые слова (SELECT FROM WHERE AND OR NOT BETWEEN IN LIKE ORDER BY ASC DESC INSERT INTO VALUES UPDATE SET DELETE CREATE TABLE PRIMARY KEY COUNT SUM AVG MIN MAX GROUP DISTINCT AS) — регистр не важен; html/css — теги/свойства `text-primary`, значения атрибутов `text-success`. `active` — строка с фоном `bg-primary-soft`, полоской слева `primary` и маленькой стрелкой ▶ (иконка lucide `ChevronRight`). `marks` — строки с `bg-warning-soft`. Пробелы отступов сохраняй (`white-space: pre`). Под кодом, если есть: панель **«Переменные»** (`vars` — чипы `имя = значение`, значение — `font-mono`; изменившееся с прошлого подшага значение коротко подсвечивается) и панель **«Вывод»** (`output` — как консоль: `bg-surface` с рамкой, `font-mono`). Заголовки панелей — из словаря: ключи `scene.vars`, `scene.output` и т. п. клади в свой файл `src/i18n/parts/scenes.ts` (префикс `scene.`).
3. **circuit** — логическая схема: входы слева (кружки с буквами и значением 0/1, если `values`), вентили — прямоугольники с подписью операции (И / ИЛИ / НЕ / И-НЕ / ИЛИ-НЕ / XOR — через словарь, на казахском: ЖӘНЕ, НЕМЕСЕ, ЕМЕС; для И-НЕ/ИЛИ-НЕ/XOR — «ЖӘНЕ-ЕМЕС», «НЕМЕСЕ-ЕМЕС», «XOR») и значком (символы `&`, `1`, `¬`/кружок инверсии по ГОСТ-стилю, как в школьных учебниках: прямоугольник с «&» для И, «1» для ИЛИ, «1» с кружком для НЕ), провода — SVG-линии с изломами; выход справа (F). Раскладка автоматическая: столбец вентиля = 1 + максимальный столбец его входов; внутри столбца — по порядку. Если есть `values` — значения на всех проводах (провод «1» — `success`, «0» — `muted`), значение считает `circuit.ts` (`evalCircuit(scene, values) → Record<id, 0|1>`). SVG масштабируется по ширине (viewBox), на 360 px читается.
4. **flow** — блоки на сетке 5×10 (x 0..4, y 0..9; высота сетки — по максимальному y): `start`/`end` — овал, `action` — прямоугольник, `if` — ромб, `io` — параллелограмм, `box` — скруглённый прямоугольник, `device` — карточка с иконкой (`icon`) и подписью. Стрелки — SVG от края блока к краю (вертикальные/горизонтальные с одним изломом), подписи стрелок (`label`, напр. «да»/«нет») — маленькие. `active` — блок с подсветкой `primary`. Стрелки «назад» (цикл) обходят слева/справа. Если x используются только 0..2 — схема компактнее (ширина по факту).
5. **cards** — сетка карточек 2 или 3 колонки (на 360 px — всегда 2; при `columns: 3` на ≥ 480 px — 3): иконка в цветном круге (tone → `bg-<tone>-soft text-<tone>`; по умолчанию primary), заголовок жирный, текст `text-sm text-muted`. Появление карточек — лёгкий каскад.
6. **pixels** — сетка квадратов (размер ячейки по ширине, макс. 28 px), цвета из `palette`; `codes: true` — справа или под картинкой строки кодов (`rows` как есть, `font-mono`), при наведении/нажатии на строку — подсветка строки в картинке.
7. **web** — две панели: «Код» (как `code` с lang html; css — отдельным блоком, если есть) и «В браузере» — рамка-окно браузера (три кружка, строка адреса), внутри `<iframe sandbox="" srcDoc=…>` (без `allow-scripts`!), высота по содержимому (≈ 140–260 px; можно фиксированную 200 с прокруткой). В srcDoc добавь базовый стиль: `body{font-family: system-ui, sans-serif; margin:12px; color:#1b2333; background:#fff}` и затем `scene.css`. Заголовки панелей — словарь (`scene.code`, `scene.browser`).

`icons.ts`: `ICONS: Record<IconName, LucideIcon>` — сопоставь все имена из `IconName` (types.ts) с иконками `lucide-react` (`cpu → Cpu`, `memory → MemoryStick`, `hard-drive → HardDrive`, `virus → Bug`/`ShieldAlert`, `cube → Box`… подбери близкие; проверь, что импорт существует в установленной версии lucide-react).

Тесты: `evalCircuit` (И/ИЛИ/НЕ/XOR/И-НЕ/ИЛИ-НЕ, вложенность), раскладка circuit/flow (чистые функции), токенайзер подсветки (python/sql) — в `tests/scenes-new.test.ts`.

Проверка глазами: **не создавай маршрутов** в приложении. Скриншоты всех сцен сделает главная модель после интеграции, поэтому особенно тщательно продумай вёрстку на 360 px и тёмную тему. Обязательно `npx tsc` и `npx eslint` своих файлов и тесты логики.

Цель (пользователь): «многие задачи одни и те же — не создавать новые подсказки для каждого вопроса, экономить токены без сильного вреда качеству». Исследование (`docs/RESEARCH.md` в ветке `claude/gifted-keller-dfnn5u`, раздел 6.5) — кэш готовых разборов, статические разборы неверных вариантов, лестница подсказок до ИИ.

1. **Лестница подсказок (бесплатно → ИИ).** У заданий появились поля `hint?: L` и `whyWrong?: (L|null)[]` (`types.ts`). `TaskContext` (`ai-types.ts`) дополни: `hint?: string`, `whyWrong?: string` (разбор выбранного неверного варианта), `stepKey?: string` (стабильный ключ задания для кэша — см. п. 3).
   - `AiPanel` в режиме `hint`: если `task.hint` есть — **сразу показывает его без запроса** (карточка «Подсказка», цвет `primary`, не `ai` — это не ИИ) и кнопку **«Ещё подсказка от Бита»** (`ai`) — только она делает запрос. Нет статической — как сейчас (сразу ИИ).
   - `AiPanel` в режиме `explain`: если есть `task.whyWrong` — сначала показывает его (и `explanation`, если есть) без запроса, кнопка «Подробнее от Бита» — запрос.
   - Кнопка «Сохранить в конспект» у ответов ИИ — как сейчас.
2. **Панель «Неверно» в плеере** (`LessonPlayer`, нижняя карточка обратной связи): если у `choice`/`multi` есть `whyWrong` для выбранного варианта — показывать его строкой над `explanation` (жирным, коротко). Номер выбранного варианта — из `answer` (`choice` → `index`; `multi` — первый выбранный неверный).
3. **Кэш ответов ИИ на сервере** (`src/server/ai-cache.ts`): кэшируются только **неперсональные** ответы — `hint` и `explain` на **первый** запрос (без истории), и `ask` с **быстрым вопросом-кнопкой** («Объясни проще», «Дай пример», «С чего начать?») как первым сообщением. Для таких запросов:
   - промпт строится **без персональных данных** (без имени, памяти, ошибок, заметок): только язык, стиль объяснений (`short | examples | steps`) и задание → `tutorSystemPrompt` получает флаг `neutral` (в `prompts.ts` — отдельная ветка; формулировки правил не меняй, только не подставляй блок «ДАННЫЕ УЧЕНИКА»);
   - ключ = sha256 от `{v: PROMPT_VERSION, mode, lang, style, task: {prompt, options, correct, given (только для explain), theory}, question (для ask)}` — нормализованные строки (trim, схлопнуть пробелы);
   - хранение — `unstable_cache` из `next/cache` (в Next 16 он помечен как заменённый на `use cache`, но `use cache` требует включить `cacheComponents` для всего приложения — мы этого не делаем; `unstable_cache` хранит результат между запросами и деплоями, на Vercel — в общем Data Cache) **плюс** in-memory LRU на 500 записей перед ним. `revalidate`: 30 дней, `tags: ["ai-cache"]`. Ошибки и пустые ответы **не кэшируются** (бросай исключение).
   - такие ответы отдаются **не потоком**, а целиком (короткие: ≤ 300 токенов для hint, ≤ 600 для explain/ask), тем же `text/plain` — клиент `streamTutor` и так читает поток, ему всё равно. Заголовок ответа `X-AI-Cache: hit | miss`. Лог: `[ai] route=tutor:hint cache=hit` (без токенов при hit) / `… cache=miss in=… out=…`.
   - **Защита подсказки**: в режиме `hint` после генерации проверь кодом, не содержит ли текст верный ответ (`leaksAnswer(text, correct)`: для ответов из ≥ 2 символов — вхождение нормализованного ответа как отдельного токена; для чисел — то же число отдельно; для вариантов choice — полный текст верного варианта, если он ≥ 3 символов). Если утёк — один повтор генерации с припиской «Не называй ответ»; если опять — вернуть `task.hint` или общий текст «Начни с первого шага решения…» из словаря и **не кэшировать**.
4. **Кэш на клиенте** (`src/lib/ai-cache.ts`): `localStorage` (`informatica:ai-cache:v1`), LRU на 150 записей, ключ — тот же принцип (без sha на клиенте можно простой `hashString` из `lib/text.ts` + длина). `useTutor.ask` для кэшируемых запросов сначала смотрит в клиентский кэш — **при попадании не тратит дневной лимит** и не делает запрос. При ответе сервера с `X-AI-Cache: hit` — вернуть потраченное обращение (`refundAi()`), ответ положить в клиентский кэш. Всё в try/catch (приватный режим).
5. **`LessonPlayer`** (только `taskCtx` и панель обратной связи): передавай в `TaskContext` `hint` (текст на языке ученика, `plain`), `whyWrong` выбранного варианта (после ответа) и `stepKey` (`question.id` для заданий урока; для сгенерированных — id без хвоста `#…`/seed не нужен: используй `prompt + options` — ключ строит сервер).
6. **Проверка Origin** во всех трёх маршрутах ИИ (`src/server/context.ts`: `sameOrigin(req)`): если заголовок `Origin` есть и его хост не совпадает с `Host` запроса (или `x-forwarded-host`) — 403 `forbidden_origin`. Нет Origin — пропускаем (старые клиенты, curl в dev). Это закрывает использование нашего ИИ чужими сайтами (исследование, раздел 7.7).
7. **Промпты**: изменения минимальные (флаг neutral, приписка против утечки). Запиши в отчёте точный дифф промптов — главная модель занесёт в CHANGELOG. Живую проверку на ru/kk сделать нельзя (нет ключа в среде) — отметь это.

Тесты (`tests/ai-cache.test.ts`): построение ключа (одинаковые задания → один ключ; разный язык/стиль/вариант ответа → разные), `leaksAnswer` (числа, двоичные, текстовые варианты, ложные срабатывания на подстроках), клиентский LRU (вытеснение, повреждённые данные). Производительность: 50 уроков × 15 шагов — поиск < 10 мс на телефоне (без регулярных выражений на каждый документ в цикле — заранее нормализованный текст).
Тесты: регистр, ё, казахские буквы и их «мягкие» пары, AND, ранжирование заголовка, сниппет и диапазоны.
