# ТЗ для авторов уроков (контент-поток, этап 3)

> Читает каждый исполнитель, который пишет урок. Образец урока — `src/content/lessons/ns-2-read.ts` и `ns-3-write.ts` (прочитай оба целиком перед работой). Методика — `docs/CONTENT_GUIDE.md`, спецификация ЕНТ — `docs/ENT.md`.

## 1. Что ты делаешь

Один урок = **три файла**, которые принадлежат только тебе:

| Файл | Экспорт | Что внутри |
|---|---|---|
| `src/content/lessons/<id>.ts` | `export const lesson: Lesson` | сам урок: шаги, конспект |
| `src/lib/bank/<id>.ts` | `export const BANKS: SkillBank[]` | банк заданий для тренировки, игр и тестов — по одному `SkillBank` на каждый навык урока |
| `src/content/ent/<id>.ts` | `export const ITEMS: EntItem[]` | задания в формате ЕНТ для пробного ЕНТ и тестов по теме |

**Не трогай** общие файлы: `course.ts`, `skills.ts`, `bank/index.ts`, `types.ts`, `i18n/*`, `tests/*`, чужие уроки. Регистрирует урок главная модель. Если в типах чего-то не хватает — опиши это в итоговом отчёте, не меняй типы сам.

**Готово, когда** `npx tsx scripts/check-content.ts <id>` выдаёт **0 ошибок** (предупреждения — разбери и поправь, что разумно), и ты сам перепроверил каждый ответ (раздел 7).

## 2. Урок (методика v2)

Урок на 5–8 минут, **12–15 шагов**, один-два близких навыка. Ученик — **полный новичок**: объясняем через знакомое из жизни, каждый новый термин — только после примера.

Ход урока:
1. **Ситуация** (`story`, `speaker: "bit"`) — зачем это нужно, где встречается в жизни. Можно продолжать сюжет «Побег из компьютера» (Бит и ученик проходят комнаты, открывая замки задачами), но главное — понятность, а не сюжет.
2. **Объяснение с иллюстрацией** (`theory` со `scene`) — одна карточка = одна мысль. 1–3 карточки.
3. **Разбор примеров по шагам** (`worked`) — 2–3 примера от простого к сложному (A → B → C). У каждого подшага своя `scene`, которая меняется вместе с шагом (подсветка строки кода, новая строка таблицы и т. п.).
4. **Ловушка** — частая ошибка ЕНТ, показанная разбором или заданием с `reveal`.
5. **Решаем вместе** (`cloze`) — пример с пропусками.
6. **Сам** — 3–5 заданий от лёгкого к сложному (уровни 1 → 2 → 3).
7. **Задание ЕНТ** (`ent: true`) — «босс урока» в настоящем формате: 4 варианта, или `multi` из **6** вариантов с 2–3 верными, или `match`.
8. **Финал** — короткая `story` или `theory`-шпаргалка.

Правила:
- **Заданий** (вопросов) — от 4 до 8. Не больше двух одинаковых типов подряд. Чередуй `choice`, `input`, `match`, `order`, `multi`, `cloze`.
- **Минимум 2 задания `ent: true`.** `solution` (развёрнутое решение по фото) — по желанию, для расчётных тем.
- У **каждого** задания: `skill`, `level` (1 — A, 2 — B, 3 — C), `explanation` (полное объяснение решения, бесплатно показывается при ошибке) и **`hint`** — подсказка, которая подталкивает к первому шагу и **не выдаёт ответ** (1–2 предложения).
- У `choice` и `multi` — **`whyWrong`**: для каждого неверного варианта одно предложение, почему он неверен и какую ошибку выдаёт («Ты прочитал остатки сверху вниз» — нет, без рода: «Остатки прочитаны сверху вниз»). У верных — `null`. Это экономит ИИ: при ошибке ученик сразу видит разбор своей ошибки.
- **Уровни A/B/C — это тип рассуждения, а не размер чисел:** A — применить правило по образцу; B — распознать модель в таблице/коде, сравнить, проанализировать; C — несколько шагов, объединение тем, обратная задача (найти основание, найти условие).
- `reveal` — «предскажи → проверь»: сцена, которая показывается после ответа (например, трассировка программы после вопроса «что выведет»).
- Задание может иметь **`scene`** — схема-условие под текстом (код программы, таблица БД, логическая схема). Код в задании показывай **только через `scene: { kind: "code", … }`**, а не внутри `prompt`.
- `conspect` — шпаргалка темы (markdown, 400–1200 символов): правила, формулы, лайфхаки ЕНТ, частые ошибки. Её ученик видит в разделе «Теория» и в конспектах.
- `durationMin` — честная оценка (5–8).
- `entTopics` — темы ЕНТ урока (`t01`…`t13`, см. `src/content/ent-topics.ts`).
- id шагов — `<короткий префикс>-<что>`: `oct-story-intro`, `oct-q-triads-1`. Уникальны в уроке.

Типы шагов и их поля — `src/lib/types.ts` (там же комментарии). Кратко:
- информационные: `story` (scene обязательна), `theory`, `worked`, `video` (не используй — видео делаем отдельно), `explore` (только инструменты двоичной системы `lamps | weights | coins` — для других тем не используй);
- задания: `choice`, `multi`, `input` (`answers` — все допустимые формы, `mode: number | binary | text`), `match` (3–6 пар, справа без повторов), `order` (items в правильном порядке), `cloze` (строки с пропусками `{ blank: [...], mode }`), `solution`, а также `bits`/`ladder` (только двоичная система).

Нормализация ответов `input`/`cloze` (`src/lib/check.ts`): регистр и все пробелы игнорируются; в режиме `number` остаются только символы `0-9a-f-` (значит «12.5» превратится в «125» — **дробные ответы давай в режиме `text` с вариантами `["12.5", "12,5"]`**); в режиме `text` срезается финальная пунктуация. Для текстовых ответов перечисляй разумные варианты написания.

## 3. Сцены (иллюстрации)

Сцена — это данные, рисует их `SceneView`. В новых темах используй:

| kind | Для чего | Пример |
|---|---|---|
| `table` | таблица истинности, таблица БД, электронная таблица (`sheet: true` — буквы столбцов и номера строк), трассировочная таблица, таблица единиц | `{ kind: "table", columns: ["A", "B", "A ∧ B"], rows: [["0","0","0"], …], highlightRows: [3], mono: true }` |
| `code` | программа на Python, SQL-запрос, HTML/CSS; `active` — текущая строка, `vars` — значения переменных, `output` — что уже напечатано | `{ kind: "code", lang: "python", lines: ["s = 0", "for i in range(3):", "    s += i", "print(s)"], active: 2, vars: [{ name: "i", value: "1" }, { name: "s", value: "1" }] }` |
| `circuit` | логическая схема: входы, вентили по порядку от входов к выходу, `values` — значения входов (значения вентилей посчитает код) | `{ kind: "circuit", inputs: ["A","B"], gates: [{ id: "g1", op: "and", in: ["A","B"] }, { id: "g2", op: "not", in: ["g1"] }], output: "g2", values: { A: 1, B: 0 } }` |
| `flow` | блок-схема, топология сети, устройство компьютера: блоки на сетке x 0..4, y 0..9 + стрелки | `{ kind: "flow", nodes: [{ id: "s", shape: "start", label: { ru: "Начало", kk: "Басы" }, x: 2, y: 0 }, …], edges: [{ from: "s", to: "a" }] }` |
| `cards` | понятия с иконками для тем «на знание» (устройства, виды ПО, угрозы) | `{ kind: "cards", items: [{ icon: "cpu", title: { ru: "Процессор", kk: "Процессор" }, text: {…} }] }` |
| `pixels` | растровое изображение и его коды | `{ kind: "pixels", rows: ["0110","1001"], palette: { "0": "#ffffff", "1": "#1b2333" }, codes: true }` |
| `venn` | круги Эйлера на 2–3 множества: `sets`, `values` (число в области), `highlight` (какие области залить), `universe` (рамка «U»). Области: `a`, `b`, `ab`, `out` (для трёх ещё `c`, `ac`, `bc`, `abc`; «ab» — A ∩ B без C) | `{ kind: "venn", sets: ["A", "B"], universe: "U", values: { a: "8", ab: "4", b: "5" }, highlight: ["ab"] }` |
| `web` | HTML-код и вид страницы в браузере (без скриптов) | `{ kind: "web", html: "<h1>Привет</h1><p>Текст</p>" }` |
| `binary`, `ladder` (`base` — любое основание!), `lamps`, `coins`, `decimal` | системы счисления | см. уроки ns-* |
| `quest` | иллюстрации сюжета (дверь, шкафчик, комната, окно с лампами) | см. уроки ns-* |

Ограничения (проверяет скрипт): таблица — до 8 столбцов и 16 строк; код — до 24 строк по 60 символов, отступ 4 пробела; схема — до 4 входов и 6 вентилей; `flow` — блоки в разных клетках; иконки — только из списка `IconName` в `types.ts`. Подписи (`caption`, тексты карточек, подписи блоков) — `{ ru, kk }` или строка без перевода (числа, код).

**Иллюстрация к каждой новой идее**: минимум 3–4 шага урока со сценой. В разборах (`worked`) сцена меняется по шагам — это главное «вау» урока: ученик видит, как исполняется программа строка за строкой, как заполняется таблица истинности, как сигнал проходит по схеме.

## 4. Банк заданий (`src/lib/bank/<id>.ts`)

Банк даёт бесконечную тренировку, игры и тесты. Для каждого навыка урока — `SkillBank` (`src/lib/bank/types.ts`):
- `question(level, seed)` — **обязательно**: задание урока (`QuestionStep`) нужного уровня, детерминированное по `seed` (используй `seeded(seed)` из `src/lib/text.ts`). У задания: `id` (уникальный по содержанию, например `g:info.units:kb2bit:3:<seed>`), `skill`, `level`, `hint`, `explanation`, у choice — по возможности `whyWrong`.
- `statement(level, seed)` — утверждение «верно/неверно» с объяснением (для игры «Верю — не верю»). Желательно.
- `pair(level, seed)` — пара «термин ↔ определение/значение» (для «Мемо-пар» и соответствий). Желательно.
- `short(level, seed)` — вопрос с коротким однозначным ответом. По возможности.

Два способа:
1. **Расчётные темы** (системы счисления, единицы, формулы, кодирование, логика, Python-трассировка, SQL, таблицы, IP, скорость, шифр Цезаря) — **генератор кодом**: случайные числа/программы/таблицы по `seed`, правильный ответ **вычисляет код**, неверные варианты — из типичных ошибок (не просто n±1). Образец — `src/lib/generators.ts`, `src/lib/bank/ns.ts`. Для Python-трассировки — шаблоны маленьких программ с параметрами, результат считай функцией на TypeScript, которая повторяет логику программы. Для SQL — маленькая таблица-массив и фильтр кодом.
2. **Темы «на знание»** (устройства, ПО, сети, безопасность, современные IT, теория БД) — **статичный пул**: используй `poolBank({ skill, questions, statements, pairs, shorts })` из `src/lib/bank/pool.ts`. Пул — **не меньше 15 заданий** на навык (5+ на каждом уровне), 10+ утверждений, 8+ пар. Варианты перемешаются сами по `seed` (вместе с `whyWrong`).

Можно смешивать: генератор + пул.

Объём: на каждом уровне из 60 разных `seed` должно получаться **не меньше 6 разных заданий** (скрипт предупредит).

## 5. Задания ЕНТ (`src/content/ent/<id>.ts`)

`export const ITEMS: EntItem[]` — статичные задания **в точном формате ЕНТ** (`docs/ENT.md`, раздел 1), типы — `EntSingle | EntMulti | EntMatch | EntContext` в `types.ts`:
- **не меньше 10 `single`** (ровно 4 варианта, 1 верный; по возможности `whyWrong`);
- **не меньше 3 `multi`** (ровно **6** вариантов, **2–3 верных**; оценка 2/1/0 по правилам ЕНТ);
- **не меньше 3 `match`** (ровно 2 пункта и 4 описания; `answer` — индекс описания для каждого пункта, разные);
- уроки по Python (`py-*`, особенно `py-3-loops` и `py-8-trace`) — ещё **1–3 `context`**: общий текст и программа (`scene: { kind: "code" }`) и **ровно 5** вопросов по 4 варианта: что выведет при таких-то входных данных, сколько раз выполнится цикл, что изменится, если поменять условие, зачем нужна строка `continue` и т. п. — как в демоверсии НЦТ («касса супермаркета»).
- Уровни A/B/C примерно 50/30/20; все три уровня обязательны.
- `id` — `<id урока>:<короткое-имя>` (латиница, цифры, дефис): `ns-5-oct-hex:hex-to-bin-1`.
- `topic` — из `entTopics` урока; `skill` — навык урока.
- Стиль условий — как в официальных демоверсиях НЦТ: коротко, однозначно, без подвохов в формулировке; дистракторы — реальные типичные ошибки.
- `explanation` — полное решение (его ученик увидит в разборе пробного ЕНТ без ИИ).
- **Не копируй** задания из чужих сборников дословно — составляй свои по образцу.

## 6. Язык

- Все строки для ученика — `{ ru, kk }`. Строка без перевода (`"1011₂"`, код) — просто строка.
- **Казахский — литературный, термины по глоссарию НЦТ** (`docs/ENT.md`, раздел 4) и школьным учебникам Казахстана: санау жүйесі, екілік/ондық/сегіздік/он алтылық жүйе (не «бинарлы»), негіз, разряд, қалдық, бөлінді, айнымалы, шартты оператор, цикл, блок-сызба, программа/программалау (как в спецификации НЦТ), деректер қоры, жазба, өріс, сұраныс, ДҚБЖ, электрондық кесте, абсолютті/салыстырмалы/аралас сілтеме, IP мекенжай, хаттама, желінің өткізу қабілеті, кэш жады, жедел жад, тұрақты жад, бұлтты технология, ЭЦҚ, ақиқат кестесі, пікір (высказывание), ақиқат/жалған. ЕНТ по-казахски — **ҰБТ**.
- После чисел в казахском падежное окончание зависит от числа — **избегай окончаний после переменных чисел** в генераторах: пиши «x = 25» или «25 саны», «нәтижесі: 25», а не «25-ті».
- **Пол ученика неизвестен**: никаких глаголов прошедшего времени с родом («ты сделал/сделала», «прочитал»). Пиши безлично: «у тебя получилось», «остатки прочитаны снизу вверх».
- На «ты», коротко, дружелюбно, без канцелярита. Без эмодзи.
- Формулы — Unicode, не LaTeX: `1011₂`, `2³`, `N = 2ⁱ`, `I = K · i`, `¬A`, `A ∧ B`, `A ∨ B`, `A → B`, `A ↔ B`, `≤`, `≠`.
- Markdown в `body`/`explanation`: **жирный**, списки, `код`; без HTML и таблиц markdown (таблицы — сценой `table`).
- Python — версия 3, как в ЕНТ.

## 7. Проверка правильности — обязательно

Ответы ЕНТ-заданий и уроков должны быть верными на 100%. Ошибка в ответе — самое дорогое, что может быть на платформе подготовки к экзамену.
- **Каждую программу на Python** из урока и ЕНТ-заданий запусти: `python3 -c '…'` или временный файл в `scripts/out/` (папка в .gitignore). Ответ «что выведет» бери из реального вывода.
- **Каждый SQL-запрос** проверь в `python3` + `sqlite3` на той же таблице.
- Логические выражения, таблицы истинности, формулы электронных таблиц, переводы чисел, единицы — посчитай кодом (`python3`), а не в уме.
- Генераторы банка: ответ всегда считает код; прогони `check-content`.
- В отчёте перечисли, что и чем проверено.
