### А1. Виды заданий «на чтение» — как писать

Все новые задания — с **явным** `read`. id — `<урок>:rv-<имя>` (контекстные — `<урок>:ctx-<имя>`). Тема и навык — как у остальных заданий файла.

| `read` | Вопрос | Шаблоны условия (ru / kk) | Как проверить |
|---|---|---|---|
| `bug` | Где ошибка / какая ошибка возникнет / почему не работает | «В какой строке допущена ошибка?» — «Қай жолда қате жіберілген?»; «Программа должна …, но выводит … . В какой строке ошибка?»; «Какая ошибка возникнет при запуске программы?» | Запусти: ошибка реально возникает (тип ошибки — настоящий), логическая ошибка реально даёт неверный результат. Варианты — номера строк («Строка 3» — «3-жол») или короткие описания. **`marks` не ставить.** |
| `fix` | Что поменять, чтобы стало правильно | «Программа должна вывести …, а выводит … . Что нужно изменить?»; «Как исправить строку 4, чтобы …?» | Каждый из 4 вариантов — конкретная правка («В строке 3 заменить `<` на `<=`»). Примени **каждую** правку и запусти: ровно одна даёт нужный результат. |
| `fill` | Что вставить вместо пропуска | «Что нужно вставить вместо ___, чтобы программа вывела …?» — «… шығаруы үшін ___ орнына не қою керек?» | Пропуск в коде — `___` (три подчёркивания). Подставь **каждый** вариант и запусти: ровно один даёт нужный результат. |
| `purpose` | Зачем строка / что делает фрагмент / что изменится, если убрать | «Для чего в программе строка 5?»; «Что изменится, если удалить строку 4?»; «Зачем здесь `break`?» | Удали или измени строку и запусти — описанный эффект настоящий. |
| `output` | Что выведет / вернёт / покажет | (их уже много — новых почти не нужно) | Реальный вывод `python3` / `sqlite3`. |
| `schema` | Чтение структуры БД | «Какое поле таблицы — первичный ключ?»; «Какое поле таблицы «Оценки» — внешний ключ и на какую таблицу оно ссылается?»; «Какой вид связи между таблицами?»; «Какая новая запись нарушит целостность?» | По данным: у первичного ключа нет повторов и пустых значений; значения внешнего ключа есть в родительской таблице. |

**Ошибки — настоящие и типичные для школьника**, а не опечатки ради опечаток:
- **Python:** `=` вместо `==`; нет двоеточия; отступ; `input()` без `int()` (сложение строк); граница `range` (не включает конец); `len(a)` как индекс; бесконечный `while` (счётчик не меняется); `return` внутри цикла; `print` вместо `return`; деление `/` вместо `//`; изменение списка при обходе; `a.sort()` вместо `sorted(a)` в присваивании (`b = a.sort()` → `None`); строка неизменяема (`s[0] = "A"`); локальная переменная вместо глобальной; рекурсия без базового случая; `and`/`or` перепутаны; сравнение строки и числа.
- **SQL:** нет запятой между полями; `WHERE` после `ORDER BY`; `= NULL` вместо `IS NULL`; текст без кавычек; агрегат в `WHERE` вместо `HAVING`; поле в `SELECT` не из `GROUP BY`; `DELETE`/`UPDATE` без `WHERE` (меняет все строки); `BETWEEN` с перепутанными границами; `LIKE` с неверным шаблоном; `JOIN` без `ON`. Пояснять по **стандарту SQL**, а не по поблажкам SQLite (SQLite, например, принимает текст в двойных кавычках как имя поля — так не пишем).
- **Электронные таблицы:** `#ДЕЛ/0!`, `#ИМЯ?` (опечатка в функции, текст без кавычек), циклическая ссылка, нет `$` перед копированием (ссылка «уехала»), `$` не там (A$1 вместо $A1), диапазон не тот (`A1:A4` вместо `A1:A5`), `СУММ` вместо `СРЗНАЧ`. Функции — русские имена, как в ЕНТ и в остальных заданиях файла (СУММ, СРЗНАЧ, ЕСЛИ, СЧЁТЕСЛИ, МАКС, МИН). Значения — считать `python3`.
- **HTML/CSS:** не закрыт тег; неверная вложенность (`<b><i>…</b></i>`); `<li>` вне списка; `scr` вместо `src`; `href` без кавычек; нет `;` в CSS — следующее свойство не применится; `.title` вместо `#title`; размер без `px`; `color` вместо `background-color`.

### А2. Формы

- ≈ 60% `single` (4 варианта, `whyWrong` у каждого неверного), ≈ 20% `multi` («Отметьте все строки с ошибкой», «Какие правки исправят программу? Отметьте все верные» — ровно 6 вариантов, 2–3 верных), ≈ 20% `match` (2 пункта × 4 описания: «строка ↔ ошибка в ней», «фрагмент ↔ что изменится», «поле ↔ его роль: первичный ключ / внешний ключ / обычное поле»).
- Уровни: ≈ 40% A, 35% B, 25% C. A — одна очевидная ошибка в 3–5 строках; B — логическая ошибка, нужно проследить выполнение; C — две правки на выбор, ошибка проявляется только на части входных данных, связь нескольких тем.
- Код — сценой `code` (`lang`: `python`, `sql`, `html`, `css`, `text`), 3–14 строк, не длиннее 60 символов. Схема БД из 2–3 таблиц — сценой `code` с `lang: "text"` (`Ученики(id_ученика, ФИО, id_класса)`) или `table` с данными; таблица Excel — сценой `table` с `sheet: true`.
- Подсказка (`hint`) — с чего начать, без ответа («Пройди цикл для i = 1 и i = 2 и сравни с тем, что нужно»). Разбор (`explanation`) — какая строка, почему это ошибка, что будет после исправления.
- Не повторять по смыслу задания, которые уже есть в файле.

### А3. Контекстные задания (+10)

Как демо НЦТ «касса супермаркета»: программа на Python 8–20 строк (бытовой сюжет: касса, оценки, шагомер, тариф, скидки, проездной) + ровно 5 вопросов по 4 варианта, у каждого вопроса `read` и `hint`. В каждом задании: не больше двух `output` (с разными входными данными), не меньше одного `fix` («Что нужно изменить, чтобы …»), не меньше одного `purpose` («Для чего строка …», «Что изменится, если удалить `continue`»), один `bug` или `fill`. Все ответы — реальный вывод `python3`.
