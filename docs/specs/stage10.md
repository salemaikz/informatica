## B. Потолок расходов ИИ, обрыв ответа, тексты лимитов, кризисный ответ

### B1. Серверный страж `src/server/ai-guard.ts` (#48)
Одна функция для всех маршрутов `app/api/ai/*`:

```ts
const g = await guardAi(req, { route: "tutor", units: 1 });
if (!g.ok) return g.response;          // 403 / 429 / 503 с jsonError
// ... вызов модели ...
g.release();                            // модель не вызывалась (ошибка до запроса, ответ из кэша)
return withGuardHeaders(response, g);   // Set-Cookie нового устройства
```

- **Проверка «запрос с нашего сайта»:** `sameOrigin` строже — в production запрос без `Origin` отклоняется (403 `forbidden_origin`); если есть `Sec-Fetch-Site`, он должен быть `same-origin`. В dev (`NODE_ENV !== "production"`) без `Origin` пропускаем (curl, тесты).
- **Устройство:** cookie `inf_ai` = `<id>.<sig>`: id — 16 случайных байт base64url, sig — HMAC-SHA256(secret, id) base64url (первые 22 символа). Secret — env `AI_DEVICE_SECRET`; нет — производный от `OPENAI_API_KEY` (sha256 с солью, сам ключ нигде не логировать); нет и его — постоянная строка только вне production. Cookie: `HttpOnly; SameSite=Lax; Path=/api; Max-Age=34560000`, `Secure` в production. Нет cookie или подпись неверна — выдаём новое устройство.
- **Новые устройства с одного IP:** не больше `AI_NEW_DEVICES_PER_IP` (30) в сутки; сверх — 429 `daily_limit`. Это закрывает обход через удаление cookie.
- **Лимиты в «обращениях»** (сутки по `kzDay()`):
  - устройство — `AI_DEVICE_DAILY_UNITS` (100 — потолок «Безлимита», тариф сервер пока не знает);
  - IP — `AI_IP_DAILY_UNITS` (1000 — класс за одним адресом);
  - весь сайт — `AI_SITE_DAILY_UNITS` (3000) → сверх 503 `ai_busy`;
  - всплеск — как сейчас, окно 10 минут по IP (`rateLimit` переложить на `getKv()` с ключом окна) → 429 `rate_limited`.
  - Числа — env с этими значениями по умолчанию; разбор env — строго числа > 0, иначе значение по умолчанию.
- **Цена маршрутов в обращениях:** чат, подсказка, разбор, вопрос по шагу — 1; фото (чат с фото, проверка решения) — 2; голос (расшифровка) — 4; отзыв после урока — 0 для устройства (у него свой потолок 30 в сутки на устройство), 1 для сайта.
- Списываем **до** вызова модели (`incrBy`), `release()` возвращает (`incrBy(-units)`), если модель не вызывалась: ошибка до запроса, ответ из серверного кэша, кризисный ответ. Сбой Upstash не роняет маршрут (kv.ts уже падает на память).
- Лог: `[ai] route=… units=… dev=<первые 6 символов id> site=<сколько за сутки>` при каждом списании; без IP и полного id.
- **Меньше токенов на ответ:** `max_completion_tokens` — чат/вопрос/разбор потоком 1200 → 800, подсказка 300 → 250, кэшируемые ответы 600 → 500; проверка фото и отзыв — посмотри текущие и сократи, если запас больше двойного типичного ответа (обоснуй в отчёте). История чата: не больше 8000 символов всего (старые сообщения отбрасываются), каждое — до 2000.
- Тест `tests/ai-guard.test.ts` (kv — память): подпись cookie, новое устройство, лимиты устройства/IP/сайта, release, строгий origin в production, разбор env.

### B3. Обрыв ответа (T9)
- Общий модуль `src/lib/ai-stream.ts` (без React, без `server-only`): маркеры конца потока `\u0000ERR` (сбой во время потока) и `\u0000CUT` (`finish_reason === "length"`), функция `splitStreamTail(text) → { text, end: "ok" | "error" | "cut" }`.
- Сервер (`tutor` потоком): ловит `finish_reason` из чанков; при сбое потока или обрезке по длине дописывает маркер последним куском; лог `[ai] route=tutor:<mode> cut=1` / `stream_error=1`.
- Клиент (`streamTutor`): маркер никогда не показывается ученику (в `onText` — текст до `\u0000`); `end !== "ok"` → `AiError("stream_cut")`. Сеть оборвалась посреди чтения → тоже `AiError("stream_cut")`.
- `useTutor`: при `stream_cut` возвращает обращение (`refundAi`), ответ не сохраняется как готовый; ошибка `ai.err.cut`.
- **«Повторить»:** в `ChatScreen` и `AiPanel` под ошибкой кнопка «Повторить» — повторяет последний вопрос, **не дублируя** сообщение ученика в ленте. Остановленный учеником ответ («Стоп») — как сейчас, сохраняется показанная часть.
