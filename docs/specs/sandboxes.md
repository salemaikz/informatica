# ТЗ-черновик: песочницы (Python, HTML/CSS, SQL, Таблица, JS)

> 2026-10-02, черновик для нового чата. Основание — `docs/CURRICULUM_REVIEW.md`, п. 5.
> Правила `CLAUDE.md` действуют всегда:
> - ru/kk везде, без эмодзи;
> - цвета только токенами и с их семантикой, `cn()`, `ButtonLink`;
> - мобильная вёрстка 360–430 px, светлая и тёмная тема;
> - правильные ответы считает код.
>
> **Без ИИ.** Песочницы и автопроверка работают бесплатно. ИИ включается только кнопкой «Объясни ошибку» (фиолетовая, через `useTutor`, модель среднего уровня, лимит по IP).

## 1. Решение: один раздел `/sandbox` с вкладками

| Вариант | Плюсы | Минусы |
|---|---|---|
| Отдельные страницы в меню (`/python`, `/web`, `/sql`, `/sheet`) | просто | 4–5 пунктов меню (на телефоне тесно); общий код (редактор, задания, «В конспект», ссылка `?code=`) дублируется |
| **Хаб `/sandbox` + `/sandbox/[tool]`** | один пункт меню «Песочница»; общий каркас; тяжёлые библиотеки грузятся только на своей вкладке (code splitting по маршруту); прямые ссылки из уроков `/sandbox/sql?task=…` | нужно перенести `/python` |

**Выбор — хаб.**
- `/sandbox` — карточки инструментов и «Задания дня» по слабым темам ученика.
- `/sandbox/python`, `/sandbox/web`, `/sandbox/sql`, `/sandbox/sheet`, `/sandbox/js` — сами песочницы.
- `/python` остаётся рабочим: после интеграции F1 — `redirects()` в `next.config.ts` на `/sandbox/python` с сохранением `?code=`.
- Пункт меню «Python» заменяется на «Песочница» (иконка `SquareTerminal`).
- Название на казахском — через `review:kk` (варианты: «Құмжәшік», «Зертхана»).

## 2. Общий каркас (S0) — делает главная модель

**Файлы:**
- `src/lib/sandbox/*` — чистая логика: типы заданий, кодек ссылки (обобщить `src/lib/python/codec.ts`: `?code=` в base64url, лимит длины), нормализация вывода;
- `src/components/sandbox/*` — общий UI: `SandboxShell`, `TaskPanel`, `ResultCard`, `CodeArea`;
- `src/app/(main)/sandbox/*`.

**Формат задания** (`src/lib/sandbox/types.ts`):

```ts
type Tool = "python" | "web" | "sql" | "sheet" | "js";
interface SandboxTask {
  id: string;                 // "sql-join-03"
  tool: Tool;
  skill: string;              // навык курса (db-4-join) — для мастерства и «слабых тем»
  level: 1 | 2 | 3;           // A/B/C
  prompt: L;                  // условие (ru/kk)
  starter?: string;           // начальный код / формулы
  check: CheckSpec;           // своя форма для каждого инструмента, см. ниже
  hint: L;                    // бесплатная подсказка (без ответа)
  solution: string;           // эталон: по нему код считает правильный ответ
  explanation: L;             // показывается после решения
}
```

**Общий UI:**
- **Режим «Свободно»** — редактор и результат.
- **Режим «Задание»** — условие сверху, редактор, кнопка «Проверить».
  - Итог проверки: зелёный `success` — верно, красный `danger` — что не так (понятным текстом, без ответа), янтарный `warning` — частично (например, верные строки, но не тот порядок).
  - Кнопки: «Подсказка» (бесплатная `hint`), «Показать решение» (после 2 попыток), «Объясни ошибку» (ИИ, фиолетовая).
- Редактор на телефоне: `autoCapitalize="off" autoCorrect="off" spellCheck={false}`. Типографские кавычки `“ ” « »` заменяются на `"` с предупреждением.
- Черновик каждой вкладки хранится в `localStorage` (как в F1). «В конспект» — через `useSaveToNotes.getState().open(…)` из `src/components/notes/saveToNotesBus.ts` (как в `AiPanel`).

**Прогресс:**
- Действие стора `completeSandboxTask(id, firstTry)` — решённые задания, XP (`gold`), вклад в мастерство навыка.
- Стор правит только главная модель.

**Шаг урока `practice`** (P3, после S1–S3):
- поля `{ type: "practice", tool, taskId }` — встроенная мини-песочница внутри урока, результат засчитывается как ответ на вопрос;
- правки в `src/lib/types.ts`, `evaluate.ts`, `tests/validate.ts` — главная модель.

**Кнопка «Попробовать»** (на всех этапах, ссылкой `ButtonLink`, вид сцены не ломать):

| Где | Условие | Куда ведёт |
|---|---|---|
| `CodeScene` | `lang === "python"` | `/sandbox/python?code=…` (сейчас F1: `/python?code=…`) |
| `CodeScene` | `lang === "sql"` | `/sandbox/sql?code=…&db=<база сцены>` |
| `CodeScene` | `lang` = `html` / `css` | `/sandbox/web?html=…&css=…` |

| Разбор ЕНТ-задания с кодом | задание про Python / SQL / HTML / формулу | «Проверить в песочнице» с кодом задания |

## 3. HTML/CSS (S1) — `/sandbox/web`

**Что умеет:**
- две вкладки редактора, HTML и CSS (или один HTML с `<style>`);
- живой просмотр с задержкой 300 мс;
- подсветка через `highlight.ts`;
- 6 примеров: визитка, список, таблица, ссылка и картинка, три способа подключения CSS, выравнивание;
- кнопка «Показать код страницы целиком».

**Изоляция:**
- просмотр — `<iframe sandbox="" srcDoc={buildWebDoc(html, css)}>`, переиспользуется `src/components/scenes/web.ts`: там уже CSP `default-src 'none'; style-src 'unsafe-inline'; img-src data:` и экранирование `</style`;
- скрипты не выполняются, сеть закрыта, формы не отправляются;
- `<script>` в HTML игнорируется, ученик видит подсказку «JavaScript — на вкладке JS»;
- картинки: учебные SVG/PNG вшиты как `data:` (3–5 штук, «кот», «логотип»). Ученик пишет `src="cat.png"`, перед вставкой в iframe имя заменяется на `data:`. Так пути к файлам учатся «по-настоящему»;
- `<link rel="stylesheet" href="style.css">` так же подменяется содержимым вкладки CSS (внешних файлов в iframe нет, а без этого третий способ подключения из демо не показать). Другие имена файлов — понятное сообщение «файл не найден».

**Автопроверка** (`src/lib/sandbox/web-check.ts` + тесты), `CheckSpec` — список утверждений:
- `exists(selector)`, `count(selector, n)`, `text(selector, value)`, `attr(selector, name, value)`, `tagPaired(tag)` — по `DOMParser` (разбор без выполнения);
- `declares(selector, prop, value)` — по CSSOM (`new CSSStyleSheet().replaceSync(css)` или разбор `<style>`), с нормализацией цвета (`red` = `#ff0000` = `rgb(255,0,0)`);
- `computed(selector, prop, value)` — для каскада и способов подключения. Проверка идёт в **отдельном скрытом** `<iframe sandbox="allow-same-origin">` **без** `allow-scripts`: скрипты не выполняются, а родитель может прочитать `getComputedStyle`. Видимый просмотр остаётся с `sandbox=""`;
- ошибки CSS: правило без `{`, `;` или `:` — понятное сообщение со строкой. Чистый парсер ловит то, что браузер молча проглатывает (как задание демо «найди неверную запись»).

**Задания (≈25):**
- выровнять абзац по центру через `align`, потом через CSS;
- одиночные теги;
- список из 3 пунктов;
- таблица 2×3 с `colspan`;
- ссылка в новой вкладке;
- картинка с `alt`;
- подключить стиль тремя способами;
- найти ошибку в правиле;
- `.класс` и `#id`;
- рамка `1px solid black`;
- цвет фона, `padding` и `margin`.

**Затраты:** без библиотек и сети. Размер — M (≈1 исполнитель sonnet). Риски малые.

## 4. SQL (S2) — `/sandbox/sql`

**Движок:**
- SQLite в браузере, **sql.js** (WASM), закреплённая версия;
- источник — CDN, как Pyodide в F1: `cdn.jsdelivr.net/npm/sql.js@<версия>/dist/` или cdnjs. Файл проверить `curl -sI` при реализации;
- альтернатива — положить `sql-wasm.js` и `sql-wasm.wasm` (≈1 МБ) в `public/vendor/sqljs/`: работает офлайн (F6) и не зависит от CDN. **Решение — за главной моделью**, рекомендую self-host;
- запуск в **Web Worker** (`public/sql-worker.js`): зацикленный `WITH RECURSIVE` обрывается `terminate()` через 3 с;
- **проверить версию SQLite в сборке ≥ 3.39** (`SELECT sqlite_version()`), иначе нет `RIGHT JOIN`. `ALTER TABLE … DROP COLUMN` есть с 3.35.

**Учебные базы** — `src/lib/sandbox/sql-dbs.ts`, SQL-скрипт создания, пересоздаётся при «Сбросить»:
- имена таблиц и полей — английские, как в демо НЦТ;
- строковые значения подбираем одинаковые в ru и kk: имена и города (Айгерім, Алматы, Астана);
- три базы:

| База | Таблицы | Для чего |
|---|---|---|
| `school` | `students(id, name, class, grade, city)`, `subjects`, `marks(student_id, subject_id, mark)` | SELECT/WHERE, агрегаты, JOIN, составной ключ в `marks` |
| `film` | `film(id, title, rating, length, year)` | как в KK-демо: `rating = 'PG-13' AND length < 60`, LIKE, ORDER BY |
| `geo` | `country(code, name, continent, region)`, `city(id, name, country_code, district, population)` (+ страна без городов, город без страны) | как в EN-демо № 6 и 39 (там учебная база MySQL `world`): INNER / LEFT / RIGHT JOIN — видно, кто получает NULL; «какое поле может быть первичным ключом» |

**Интерфейс:**
- редактор;
- кнопка «Выполнить»;
- результат — таблица (на телефоне прокручивается внутри блока, не вся страница);
- «Схема базы»: список таблиц и полей, ключи отмечены значком `KeyRound`;
- «Сбросить базу»;
- выполняется только первый оператор, если не включено «Несколько команд».

**Автопроверка** (`src/lib/sandbox/sql-check.ts` + тесты на Node с тем же sql.js из npm-пакета в devDependencies):
- **SELECT:** на свежей копии базы выполняются запрос ученика и `solution`, результаты сравниваются:
  - число столбцов и значения;
  - порядок строк учитывается, только если в эталоне есть `ORDER BY`, иначе сравниваются мультимножества;
  - имена столбцов проверяются, только если в задании `requireAliases`;
- **INSERT/UPDATE/DELETE/ALTER/DROP/CREATE:** после запроса ученика выполняется `checkQuery` (например, `PRAGMA table_info(students)` или `SELECT * FROM students ORDER BY id`), результат сравнивается с тем же после эталона;
- **сообщения:** «лишние строки: 2», «не хватает столбца», «порядок не тот», «таблица изменилась не так»; ошибки SQLite — переведены на ru/kk (`no such column` → «нет такого поля»).

**Расхождения SQLite и MySQL** (в демо упомянут MySQL) — отметить в карточке «Особенности песочницы»:
- типы гибкие: `VARCHAR(20)` принимается, но длина не проверяется;
- `LIKE` без учёта регистра только для латиницы;
- нет `AUTO_INCREMENT` (есть `INTEGER PRIMARY KEY`);
- нет пользователей и прав: `GRANT`/`REVOKE` (EN-демо № 13) учим только теорией в db-1, в песочнице — сообщение «в учебной базе нет пользователей».

Задания строим так, чтобы эти отличия не влияли на ответ.

**Задания (≈35):**
- по 6–8 на урок db-2, db-3, db-4;
- плюс 5 «что вернёт запрос?» (ввести число строк);
- плюс 5 «исправь запрос».

**Затраты:** ≈1 МБ трафика при первом открытии вкладки. Размер — M+.

**Риски:**
- недоступность CDN — снимается self-host;
- ложные «неверно» при эквивалентных запросах — снимается сравнением результата, а не текста.

## 5. Таблица / Excel (S3) — `/sandbox/sheet`

**Движок формул** — `src/lib/sheet/*`, чистая логика без React, **тесты обязательны** (`tests/sheet-*.test.ts`, ≥ 150 случаев):
- `parse(formula)` — токенизатор и парсер (Pratt):
  - числа (точка и запятая как десятичный знак), строки `"…"`, логические значения;
  - ссылки `A1`, `$A$1`, `A$1`, `$A1`; диапазоны `A1:C3`;
  - операторы `+ - * / ^ &`, `= <> < > <= >=`, унарный минус, постфиксный `%`;
  - разделитель аргументов — `;` и `,`.
- `evaluate(sheet)`:
  - граф зависимостей и пересчёт в топологическом порядке;
  - **циклическая ссылка** — ошибка ячейки;
  - ошибки `#ДЕЛ/0!`, `#ИМЯ?`, `#ЗНАЧ!`, `#ССЫЛКА!` (и английские при английских именах).
- **Функции** (русское / английское имя):
  - базовые: СУММ/SUM, СРЗНАЧ/AVERAGE, МИН/MIN, МАКС/MAX, СЧЁТ/COUNT, СЧЁТЗ/COUNTA;
  - логика: ЕСЛИ/IF (вложенное), И/AND, ИЛИ/OR, НЕ/NOT;
  - с условием: СЧЁТЕСЛИ/COUNTIF, СУММЕСЛИ/SUMIF, СРЗНАЧЕСЛИ/AVERAGEIF (критерии `">5"`, `"<>0"`, `"текст"`, `*` и `?`);
  - округление: ОКРУГЛ/ROUND;
  - текст: СТРОЧН/LOWER, ПРОПИСН/UPPER, ДЛСТР/LEN, СЦЕПИТЬ/CONCATENATE, ЛЕВСИМВ/LEFT, ПРАВСИМВ/RIGHT, ПСТР/MID, ЗАМЕНИТЬ/REPLACE, ПОДСТАВИТЬ/SUBSTITUTE.
  - Расширяемая таблица функций. Казахские имена добавим, если владелец подтвердит, что они встречаются.
- `shiftFormula(formula, dRow, dCol)` — копирование формулы с учётом `$`. Выход за край — `#ССЫЛКА!`.
  - **Та же функция генерирует задания** на ссылки для data-2-refs (генератор в `src/lib/generators.ts`, тренировка и игры), так что ответы всегда считает код.

**Интерфейс:**
- сетка 6 × 12 (A–F), прокрутка только внутри сетки;
- строка формул сверху, адрес активной ячейки;
- выбор ячейки нажатием;
- кнопки «Копировать вниз / вправо на N» вместо перетаскивания маркера (на телефоне); на компьютере — ещё и маркер;

## 6. JavaScript (S5, P3) — `/sandbox/js`

**Объём:** только то, что нужно для темы 13 — переменные, типы, `+` для строк и чисел, `typeof`, `if`, `for`, `console.log`. **DOM не делаем.**

**Исполнение:**
- **Web Worker внутри изолированного iframe:** скрытый `<iframe sandbox="allow-scripts">` (без `allow-same-origin`, origin — opaque) с CSP `default-src 'none'; script-src 'unsafe-inline' blob:; worker-src blob:` создаёт Worker из `Blob` и общается с приложением через `postMessage`;
  - почему не Worker прямо на странице: он живёт в origin приложения — видит IndexedDB и может `fetch` к нашим `/api/*` (ИИ-маршруты) от имени ученика. Подмена `fetch = undefined` не защищает: `delete self.fetch` или прототип её обходят. А код приходит и по ссылке `?code=` от другого человека;
  - в Worker нет DOM, `localStorage` и `document`;
  - при реализации проверить, что Blob-Worker из opaque-origin iframe запускается в Chrome (Android), Safari (iOS) и Firefox; если где-то нет — запасной вариант: интерпретатор без `eval` не делаем, просто показываем «что выведет» без запуска;
- перед кодом ученика подставляются `console.log`/`alert`/`document.write`, которые копят вывод;
- `prompt()` берёт строки из поля ввода;
- `terminate()` через 3 с (или удаление iframe) — бесконечный цикл не вешает вкладку;
- сеть закрыта CSP iframe; `fetch`, `importScripts`, `XMLHttpRequest`, `WebSocket` дополнительно заменяются на `undefined` — это подсказка ученику («сети нет»), а не защита.

**Почему код не выполняется в самом iframe:** изолированный iframe часто работает в том же потоке, что и страница (особенно на телефонах). `while(true)` повесит вкладку, и снять его нельзя. В Worker — можно, поэтому iframe только создаёт Worker.

**Автопроверка:** сравнение вывода (как у Python). Задания «что выведет» в уроке web-3-js проверяются без песочницы; песочница — «проверь себя запуском».

**Задания (≈10):** `"Hello"+10+5`, `10+5+"Hello"`, `"5"*2`, `typeof`, `==` и `===`, цикл с суммой.

**Затраты:** без библиотек. Размер — S.

**Риски:** ученик может спутать синтаксис JS и Python. На вкладке плашка «Это JavaScript, не Python» и сравнение `print` ↔ `console.log`.

## 7. Python (S4) — встроить F1

F1 (`/python`, Pyodide в Worker, пошаговый режим, `ErrorCard`) делается в волне 3. После приёмки:
1. Перенести страницу в `/sandbox/python`. `PythonSandbox` и `PythonEditor` переиспользуются как есть; `/python` → redirect.
2. **Режим заданий** (`src/lib/sandbox/py-check.ts`):
   - `CheckSpec = { tests: { stdin: string; stdout: string }[] }`;
   - программа ученика запускается на каждом тесте через `runPython`, вывод нормализуется (пробелы в конце строк, последний перевод строки);
   - при ошибке показывается номер теста и вход, но не скрытый ответ (у последнего теста вход скрыт).
3. **Задания (≈40):**
   - по 3–5 на py-1…py-6 и py-11;
   - «напиши программу» для практикума py-review;
   - «узнай сортировку — допиши» для py-9.
4. Контекстные ЕНТ-группы: кнопка «Запустить эту программу» в разборе.
5. **Риск (проверить при приёмке F1):** Pyodide-Worker живёт в origin приложения, а в Pyodide есть модуль `js` — код из чужой ссылки `?code=` может обратиться к IndexedDB и `/api/*`. Если так — перенести Worker в изолированный iframe, как у JS (п. 6).

**Затраты:** Pyodide ≈10 МБ при первом запуске, дальше из кэша браузера. Размер — M.
