# Битва (Шайқас): дуэль с персонажами — этап 16Е

> ТЗ главной модели. Строится поверх дуэлей «Жекпе-жек» (`docs/specs/duels.md`, решения #126–#129): тот же движок,
> друзья, вызовы, живые матчи, бот. Меняется зрелище и правило победы: вместо очков — здоровье, удары и нокаут.

## 0. Решения владельца (2026-10-11)

- **Битва — мини-игра.** На экране видно персонажа соперника. Каждый верный ответ — удар, у соперника убывает здоровье.
- **На урон влияют:**
  - верные ответы — это основной урон;
  - скорость ответа;
  - серия верных ответов подряд в бою (комбо);
  - серия дней занятий — маленький бонус: +1% за каждые 5 дней подряд, максимум +5% (с 25-го дня).
- **Ошибка** не наносит урона по себе. Она сбрасывает комбо и «оглушает» персонажа на 1,5 с (пауза режима, как в блице).
- **Скины только меняют внешний вид.** Урон у всех считается одинаково. Скины продаются в магазине.
  Это отменяет прежнее «украшения не за деньги» (#108): чипы за ₸ появятся с Kaspi на этапе 17.
- **Выкладка** — одним разом вместе с v0.19–v0.20, когда владелец примет битву.

## 1. Как играется

- **Экран** (ширина телефона, сверху вниз):
  - полоска времени;
  - соперник: имя, уровень, полоска здоровья и его персонаж;
  - поле боя: цифры урона, искры удара, надпись «Крит!»;
  - ваш персонаж, полоска здоровья, огонёк комбо «×3»;
  - карточка вопроса с вариантами.
- **Верный ответ.** Ваш персонаж делает выпад, у соперника вспышка, всплывает число урона, полоска здоровья убывает.
  Удар соперника по вам выглядит так же: его события приходят по таймлайну — бот, запись друга или живой матч (`opponentAt`).
- **Неверный ответ.** Комбо гаснет, персонаж на 1,5 с «оглушён», и ответ не принимается.
- **Нокаут.** Здоровье дошло до 0 — персонаж падает, матч сразу кончается.
  Если часы вышли без нокаута, побеждает тот, у кого больше здоровья.
- **Цвета по семантике (CLAUDE.md):**
  - полоска здоровья: > 50% — `success`, 25–50% — `warning`, < 25% — `danger`;
  - комбо — `streak`;
  - число урона — `danger`, крит — `streak` и крупнее;
  - награды на итогах — `gold`.

## 2. Формула урона (считает код, сервер перепроверяет)

Все числа — константы в `src/lib/duel/battle.ts`, их можно подкручивать без смены логики.

| Что | Значение |
|---|---|
| Здоровье | `BATTLE_HP = 100` |
| Базовый удар по уровню задания | A — 10, B — 12, C — 15 |
| «Норма» времени на задание | A — 6 с, B — 9 с, C — 13 с |
| Скорость | время ≤ ½ нормы — «молния» ×1,3; ≤ нормы — «быстро» ×1,15; дольше — ×1 |
| Комбо (k-й верный подряд) | +10% × (k − 1), не больше +50% |
| Крит (только зрелище) | k ≥ 5 |
| Серия дней | +1% за каждые полные 5 дней подряд, не больше +5% (25 дней) |

- **Удар:** `урон = round(база × скорость × (1 + комбо + серия))`. Неверный ответ — урон 0, комбо 0.
- **Пределы удара:** от 10 (A, медленно, без бонусов) до 30 (C, «молния», комбо +50%, серия +5%).
  Обычный удар — 13–15, нокаут — за 7–8 верных ответов, это примерно минута.
- **Время на задание.** Его считаем по событиям, как сервер (`itemMs` в `live.ts`): `t[k] − t[k−1]`.
  Если предыдущий ответ неверный, вычитаем ещё паузу ошибки. Отрицательное время → 0.
- **Норма зависит от уровня**, поэтому за трудные задания (C) скорость не наказывает.
- **Нечестные ответы урона не дают.** Слишком быстрый ответ и неверная сумма времени у сервера уже становятся «неверно» (`plausible.ts`).

## 3. Победа

1. **Нокаут.** Побеждает тот, кто первым набрал урон ≥ 100, то есть с меньшим `t` нокаутирующего удара.
   - Нокаут в одно и то же `t` — ничья.
   - Удары стороны после момента первого нокаута в матче не считаются: персонаж уже упал.
2. **Нет нокаута.** Больше нанесённого урона — побеждает (`reason: "hp"`).
   Дальше правила как в `score.ts → winner`: больше верных, больше отвечено, меньше время (разница < 1 с — ничья).
3. **Техническая победа** (ушёл, молчит) — без изменений (`technicalResult`).

## 4. Режим `battle` в движке дуэлей (пакет Б2)

```ts
battle: {
  id: "battle", icon: "swords", shape: "choice",
  n: 24, clockMs: 90_000, perItemMs: null, ladder: null,  // уровни растут по полосе (bandLevels)
  pts: { ok: 1, bad: 0 },                                   // для battle очки = нанесённый урон (см. ниже)
  errorPauseMs: 1_500, random: true, needsTopic: false,
}
```

- **Очки стороны** в битве — это нанесённый урон (`dealt`), а не `pts`.
  - `totals()` получает контекст `{ levels, streakDays }` (уровни из набора, у обеих сторон он один — общий seed).
  - `winner()` сначала смотрит нокаут (`koAt`).
  - Места вызова: `server/duel/match.ts`, `server/duel/challenge.ts`, `DuelPlay`, `DuelRun`, `ChallengePlay`, `record.ts → duelOutcome`.
- **Серия дней стороны** (`streakDays`):
  - живой матч — приходит с клиентом (`PlayerInput`), сервер обрезает до 0…25;
  - вызов — хранится в записи;
  - бот — 0.
  - Пока прогресс хранится на устройстве, это значение не проверить. Обрезка 0…25 ограничивает выгоду подмены пятью процентами. Проверка появится с аккаунтами (этап 17).
- **Случайные соперники.** Очередь случайных соперников — только «Битва»: одна очередь, чтобы быстрее находилась пара. Блиц остаётся для друзей и бота.
- **`MatchView.result.reason`** получает значение `"ko"`. Итоги показывают «Нокаут!» или «Больше здоровья».
- **Опыт и очки недели** — как у дуэлей (#129): опыт за верные ответы (2 за ответ, не больше 30), бонус за победу, сердечко за вход. Битва — один из режимов.

## 5. Персонажи и скины (пакеты Б3, Б4)

- **Стиль** выбирает владелец по эскизам: страница `/dev/battle` в превью, в продакшене 404.
- **Персонаж** — SVG-компонент с позами `idle | attack | hit | ko | win`.
  - Анимация на `motion/react` (`m.*`, общий `MotionProvider`). Настройка «Меньше анимаций» её выключает.
  - Персонаж лёгкий: без картинок и внешних файлов.
- **Скины — новый слот украшений `fighter`** (`lib/cosmetics.ts`), рядом с рамкой, фоном и титулом.
  - Базовый персонаж есть у всех бесплатно.
  - Обычные, редкие и эпические скины — за чипы, легендарные — только из кейса за уровень.
  - Цены пока по таблице украшений (80 / 160 / 320). Финальные — вместе с экономикой.
- **Скин виден сопернику:** `PublicCard.skin`. Сервер принимает только известный id слота `fighter`.
  Владение не проверить до аккаунтов, но вреда нет: скин ничего не даёт в бою.
- **Бот** носит случайный скин из каталога, в том числе редкие. Это витрина: ученик видит, что можно купить.
- **Примерка** — в шторке `TryOnSheet`, как у рамок.

## 7. Интерфейс `src/lib/duel/battle.ts` (пакет Б1)

Чистый модуль без React и сервера: один код у клиента, сервера и бота.

```ts
import type { Level } from "../types";
import type { DuelEvent } from "./types";

export const BATTLE_HP = 100;
export const BASE_DAMAGE: Readonly<Record<Level, number>> = { 1: 10, 2: 12, 3: 15 };
export const SPEED_NORM_MS: Readonly<Record<Level, number>> = { 1: 6_000, 2: 9_000, 3: 13_000 };
export const SPEED_MULT = { lightning: 1.3, fast: 1.15, normal: 1 } as const;
export type SpeedTier = keyof typeof SPEED_MULT;
export const COMBO_STEP = 0.1;
export const COMBO_MAX = 0.5;
export const CRIT_COMBO = 5;
export const STREAK_DAYS_PER_STEP = 5;
export const STREAK_STEP_BONUS = 0.01;
export const STREAK_BONUS_MAX = 0.05;

/** ms ≤ норма/2 → "lightning"; ms ≤ норма → "fast"; иначе "normal". Негодный ms (NaN, < 0) → "normal". */
export function speedTier(level: Level, ms: number): SpeedTier;
/** Бонус серии дней: floor(days / 5) × 1%, в пределах 0…5%. NaN, Infinity, отрицательное → 0. */
export function streakBonus(days: number): number;
/** Бонус комбо для k-го верного подряд (k ≥ 1): min(0,1 × (k − 1), 0,5); k < 1 → 0. */
export function comboBonus(k: number): number;

export interface Hit {
  i: number;
  /** Мс от старта матча (как у события). */
  t: number;
  ok: boolean;
  /** Урон удара; 0 у неверного. */
  dmg: number;
  /** Сколько верных подряд, включая этот; 0 у неверного. */
  combo: number;
  /** Скорость; null у неверного. */
  speed: SpeedTier | null;
  crit: boolean;
}

export interface BattleOpts {
  /** Пауза после ошибки режима, мс (вычитается из времени следующего задания). */
  errorPauseMs: number;
  /** Серия дней атакующей стороны. */
  streakDays: number;
}

/**
 * Удары по событиям стороны. levels[i] — уровень задания i набора; нет такого → уровень 1.
 * Время задания k: t[k] − t[k−1] (для k = 0 — t[0]) минус errorPauseMs, если предыдущий ответ неверный; не меньше 0.
 */
export function battleHits(events: readonly DuelEvent[], levels: readonly Level[], opts: BattleOpts): Hit[];

export interface BattleSide {
  /** Удары, которые засчитаны (до конца боя). */
  hits: Hit[];
  /** Нанесённый урон: сумма dmg засчитанных ударов, не больше BATTLE_HP. */
  dealt: number;
  /** t удара, после которого dealt ≥ BATTLE_HP; null — нокаута нет. */
  koAt: number | null;
  correct: number;
  answered: number;
  /** t последнего засчитанного события; 0 — событий нет. */
  timeMs: number;
}

/** Сторона без учёта соперника: удары до своего нокаута (после него — не считаются). */
export function battleSide(events: readonly DuelEvent[], levels: readonly Level[], opts: BattleOpts): BattleSide;

export interface BattleResult {
  a: BattleSide;
  b: BattleSide;
  /** Момент первого нокаута в матче; null — нокаута не было. События обеих сторон после него отброшены. */
  endAt: number | null;
  winner: "a" | "b" | "draw";
  reason: "ko" | "hp" | "correct" | "time";
}

/**
 * Матч целиком. endAt — min(a.koAt, b.koAt). Если endAt есть, у обеих сторон отбрасываются события с t > endAt.
 * Победитель по §3: нокаут → раньше; одновременно → ничья. Иначе: dealt → correct → answered → время (|Δt| < 1 с — ничья).
 */
export function battleMatch(
  aEvents: readonly DuelEvent[],
  bEvents: readonly DuelEvent[],
  levels: readonly Level[],
  opts: { errorPauseMs: number; aStreakDays: number; bStreakDays: number },
): BattleResult;

/** Здоровье защитника в момент nowMs: BATTLE_HP − Σ dmg ударов атакующего с t ≤ nowMs, не меньше 0. */
export function hpAt(attacker: Pick<BattleSide, "hits">, nowMs: number): number;
```

- **Константа ничьей по времени** — `DRAW_TIME_MS` из `score.ts`. Импортировать её, а не копировать.
- **Тесты** — `tests/duel-battle.test.ts`. Что проверяют:
  - пороги скорости на границах: ровно ½ нормы и ровно норма;
  - предел комбо +50% и сброс комбо после ошибки;
  - серия дней: 0 и 4 → 0; 5 → 1%; 12 → 2%; 24 → 4%; 25 и 100 → 5%; −1, NaN → 0; 9,9 → 1%;
  - вычитание паузы после ошибки;
  - нокаут и отбрасывание событий после него;
  - одновременный нокаут — ничья;
  - победа без нокаута по урону, затем по верным и по времени;
  - пустые события;
  - событие с номером за пределами levels — уровень 1;
  - проверка здравого смысла: 8 верных «быстрых» B подряд нокаутируют, 6 медленных A — нет;
  - пределы удара: минимум 10, максимум 30.
