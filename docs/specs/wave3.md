## Общие правила для всех модулей

1. **Свои файлы.** Правишь только файлы своего раздела (список «Владеешь»). Новые файлы — внутри своих папок. Общие файлы правит только главная модель:
   `src/i18n/dict.ts`, `src/lib/store.ts`, `src/components/app/AppShell.tsx`, `src/components/app/Providers.tsx`, `src/games/components.ts`, `docs/*`, `package.json` (кроме модуля, которому явно разрешено поставить зависимость).
   Если нужна правка общего файла (пункт меню, монтирование компонента, поле стора) — **не делай**, а опиши в итоговом отчёте: «главной модели: …».
2. **Строки** — только в своём файле `src/i18n/parts/<модуль>.ts` (он уже создан и подключён к словарю), ключи с префиксом модуля. У мини-игр строки — в `src/games/<id>/strings.ts`.
3. **Чистая логика** — в `src/lib/...` (или `src/games/<id>/logic.ts`) без React, с тестами в `tests/`. Правильные ответы всегда считает код.
4. **Разметка заданий банка** (`код`, **жирный**, ==маркер==) — рендерить через `InlineMarkdown` (`src/components/Markdown.tsx`); для `aria-label`, замеров длины, объявлений — `plainText` (`src/lib/text.ts`).
5. **Проверка своей работы:**
   - `npx tsc --noEmit -p .` — параллельно работают другие исполнители, ошибки **в чужих** файлах игнорируй, в своих — ноль;
   - `npx eslint <свои файлы>` — ноль ошибок и предупреждений;
   - `npx vitest run <свои тесты>` (и затронутые старые тесты);
   - **`npm run build` не запускать** (его запускает только главная модель — общий `.next`).
6. **Браузер.** Свой dev-сервер: `npx next dev -p <твой порт>` (порт указан в разделе), после проверки остановить **по PID** (никогда `pkill -f next`). Chromium: `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`. Смотреть: ширина 390 px, светлая и тёмная тема, ru и kk, нет горизонтальной прокрутки, нет ошибок в консоли (`pageerror`). Онбординг пропускается так: перед открытием страницы записать в `localStorage` ключ `informatica-v1` со `state.onboarded = true` (пример — `e2e/games.spec.ts`; **не** через `addInitScript` во все фреймы — он ломает изолированные iframe). Скриншоты и скрипты — в `scripts/out/wave3/<модуль>/` (в git не попадают).
   - Если странице нужен внешний CDN (Pyodide), запускай контекст Playwright с `proxy: { server: process.env.HTTPS_PROXY }` и `ignoreHTTPSErrors: true` (облачная среда ходит в интернет через прокси).
7. **Не коммитить.** Коммиты делает главная модель.
8. **Итоговый отчёт** (≤ 25 строк, по-русски): какие файлы созданы/изменены; что сделано; отступления от ТЗ и почему; строки для `docs/CHANGELOG.md`; что нужно от главной модели (подключение в меню, монтирование, поля стора); известные ограничения.

### G1. «Бинго» (`bingo`) — порты 3311 / 3312
- Карточка 4 × 4 из 16 **разных коротких** ответов: верные варианты choice-заданий банка (после `plainText` ≤ 16 символов; повторяющиеся и длинные — пропускать). Если пригодных меньше 16 — карточка 3 × 3 (9), меньше 9 — понятное сообщение «мало заданий для бинго по этим темам» и выход через `onFinish` с нулём.
- Показывается вопрос, ученик нажимает ответ на карточке. Верно — клетка отмечена; неверно — ошибка, в `calm` разбор. Линии (строки, столбцы, 2 диагонали) — бонус, считает `logic.ts`.
- `calm`: все вопросы карточки по очереди без таймера; `normal`: время на вопрос по уровню; `blitz`: 120 с.
- Ответ, которого нет среди вопросов, на карточке не бывает: каждая клетка — ответ ровно одного вопроса.

### G2. «Шифровка» (`cipher`) — порты 3321 / 3322
- Набор из ~12 фраз об информатике (ru/kk пары, в `strings.ts`, 15–35 букв, литературный казахский, термины по глоссарию НЦТ). Буквы скрыты, пробелы и знаки видны.
- Каждый верный ответ открывает несколько букв (распределение так, чтобы к последнему вопросу открылось всё). Ошибка ничего не открывает (в `calm` — разбор).
- «Знаю фразу» — выбор из 4 фраз (без ввода с клавиатуры на телефоне); верно — бонус за оставшиеся скрытые буквы, неверно — небольшой штраф к очкам, игра продолжается.
- `calm`: 10 вопросов; `normal`: 12 с временем на вопрос; `blitz`: 180 с.

### G3. «Ставка» (`bet`) — порты 3331 / 3332
- Вопрос → выбор ответа → ставка 1 / 2 / 3 → проверка. Верно: +ставка, неверно: −ставка (итоговые очки для рекорда не ниже 0).
- Перед `onFinish` игра показывает свой экран **«Карта уверенности»**: точность по каждой ставке («ставка 3: верно 4 из 5») и вывод (уверенность оправдана / ставишь много там, где ошибаешься / недооцениваешь себя), кнопка «Дальше» вызывает `onFinish`.
- Цвета: очки/ставки — `gold`; верно/неверно — `success`/`danger`.
- `calm`: 10 вопросов; `normal`: 12; `blitz`: 150 с.

### G4. «Босс-битва» (`boss`) — порты 3341 / 3342
- Босс собирается из **слабых навыков** ученика: среди навыков игры берём 3 с наименьшим освоением (`useApp((s) => s.skills)`, только чтение; если данных нет — случайные из списка). Имя босса — по теме ЕНТ самого слабого навыка (13 тем, `src/content/ent-topics.ts`; имена ru/kk в `strings.ts`, например «Страж счисления» / «Санау жүйесінің сақшысы»).
- Здоровье 100. Верный ответ — урон по уровню (A 20, B 30, C 40); ошибка — босс восстанавливает 10 и в `calm` показывается разбор. Победа — здоровье 0. Ходов: `calm` 12, `normal` 12 с временем на ход, `blitz` 180 с. Не победил — не «проигрыш», а «босс отступил, до встречи» + сколько урона нанесено.
- «Большой босс недели»: выбор в начале игры; задания по всем переданным навыкам, уровень B–C, здоровье 150, seed — номер недели (у всех один босс на неделе).
- Рисунок босса — SVG/lucide-иконки темы и полоса здоровья (`danger`), маскот Бит атакует (motion). Без эмодзи.

### G5. «Собери решение» (`build`) — порты 3351 / 3352
- Источник — шаги `worked` (пошаговые разборы) из уроков `LESSONS` (`src/content/course.ts`): берём разборы уроков, чьи навыки пересекаются с `props.skills` (если пусто — навыки из метаданных); годятся разборы с 3–7 шагами.
- Раунд: заголовок разбора, шаги перемешаны — ученик расставляет порядок (переиспользовать `OrderView` из `src/components/lesson/steps/OrderView` через шаг `order`, проверка — `evaluate`). После проверки — верный порядок и итог разбора (`result`).
- Навык попытки — навык шага `worked` (`step.skill`) или первый навык урока.
- `calm`: 5 решений; `normal`: 6, время 20 с на шаг; `blitz`: 180 с.
- Если по навыкам нет разборов — сообщение и выход с нулём.
